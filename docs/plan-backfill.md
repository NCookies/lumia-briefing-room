# 과거 녹화 전체 분석 (로그에 없는 경기 복구)

> 목적: 게임 로그(`Player.log`)에 남지 않은 과거 경기도 스팀 녹화 영상만으로 찾아 클립을 만든다.
> 계기: 친구 PC 에서 어제·엊그제 녹화가 분석되지 않았다. 앱이 경기 목록을 `Player.log`/`Player-prev.log`(최근 게임 실행 2번 분량)에서만
> 얻기 때문이다. 앱을 늦게 설치한 사용자는 스팀에 녹화가 남아 있어도 그 경기가 있었다는 사실을 알 수 없다.
> 진행 상태를 이 문서 §0 에 적는다([CLAUDE.md](../CLAUDE.md)).

## 1. 설계

**핵심 아이디어**: 로그 기반 경로는 "경기 시작·종료 시각"만 넘겨받으면 나머지(검출·컷·썸네일·결과 화면 OCR)를 다 한다
(`process_match(session, start, end, …)`). 그래서 새로 만들 것은 **경계를 화면에서 찾는 부분**뿐이다.
다시보기(VOD) 분석이 이미 프레임 판독(`analyze_frame`)과 게임 분할(`split_games`)을 갖고 있다.

```
세션 폴더(bg_1049590_…) ─▶ 세그먼트 키프레임(3초 간격) ─▶ FrameState 판독(캐시) ─▶ split_games ─▶ 게임 구간
   ─▶ 로그·기존 클립과 겹치는 것 제외 ─▶ 오래된 것부터 process_match(스테이징) ─▶ 클립 폴더로 이동
```

- **이터널 리턴 세션만** 본다(폴더 이름의 앱 ID 1049590). 다른 게임 세션은 건너뛴다.
- **경계 보정**: 화면 기준 시작은 로딩이 끝나 HUD 가 뜬 시점이라 로그 시작보다 늦고, 끝은 마지막 인게임 프레임이라 로그 종료(로비 복귀)보다 이르다.
  결과 화면은 경기 끝 뒤에 나오므로 끝에 여유(`POST_GAME_SEC`)를 주되 다음 경기 시작을 넘지 않게 한다.
- **취소 시 "복원"** = 롤백이 아니라 **이어하기 + 경기 단위 스테이징**이다. 이 분석은 원본을 읽기만 하고 완성된 클립은 취소해도 유효하다.
  경기 하나는 임시 폴더에 다 만든 뒤 mp4 → 썸네일 → json 순서로 옮기므로, 중간에 멈추거나 컴퓨터가 꺼져도 깨진 클립이 목록에 뜨지 않는다.
  프레임 판독은 캐시에 이어 쓰므로 다시 누르면 저장된 지점부터 계속한다.
- **링버퍼**: 스팀이 새 녹화를 쌓으면 옛 세그먼트를 지운다. 오래된 것부터 처리하고, 처리 중 사라진 구간은 건너뛰며 알린다.
  (실측: 분석 도중 세그먼트가 801 → 616 개로 줄었다.)
- **게임 중 부하**: CPU 를 많이 쓴다. 확인 창에서 게임을 끄고 실행하라고 안내한다(앱은 이미 낮은 우선순위로 돈다).

## 3. 시작 전 확인하려던 것 → 결과

1. 스팀 녹화에서 게임 분할 정확도 → 확인(이 PC 6판, 개수·시간·순위가 로그 기반과 일치, §4)
2. 화면 기준 경계에서 결과 화면(순위)이 읽히는지 → 처음엔 안 읽혔고 탐색 방식을 고쳐 해결(§5)
3. 다른 해상도 → 아직(§6)
4. 앞부분이 잘린 경기 → 건너뛰기로 정했다(§6-3)

## 5. 알아 둘 함정

- **결과 화면 탐색은 구간 끝이 로비 복귀라는 전제였다.** 화면 기반 경계는 끝이 마지막 인게임 프레임이라 처음엔 순위가 전부 비었다. `find_result_after`(끝 뒤에서 앞으로) 로 바꿔 해결.
- **프레임 추출이 구간 전체를 임시 파일로 이어붙여 통째로 메모리에 올렸다**(40분 = 9GB). 파이프 스트리밍으로 바꿔 메모리가 일정해졌다. 이 함수는 평소 매치 분석도 쓴다.
- **아는 경기 판별에 로그도 써야 한다.** 클립 폴더만 보면 "로그엔 있지만 아직 처리 전"인 경기를 여기서 또 만들어 감시와 중복된다.
- **링버퍼가 분석 중에도 앞을 지운다**(실측: 세그먼트 801→616). 지워진 구간의 캐시된 판독은 버리고, 앞부분이 잘린 경기는 클립을 부분적으로만 만들 수 있어 건너뛴다. 잘린 경기는 시작 시각이 계속 밀려 같은 경기가 다른 키로 중복 처리될 위험도 있다.
- **소요 시간 예측은 이 PC 기준**이다(25배속). 친구 PC 는 디스크·CPU 에 따라 다르다.

## 6. 남은 확인 필요

1. **친구 PC** — 로그에 없는 어제·엊그제 녹화가 실제로 복구되는지. 진단 zip 으로 결과를 받는다.
2. **4시간 규모** — 약 40GB 세션의 소요 시간과 메모리(스캔은 프레임 한 장 분량이라 문제없을 것으로 보지만 실측 아님).
3. **앞부분이 잘린 경기** — 지금은 건너뛴다. 부분이라도 클립으로 만들지는 사용자 의견을 듣고 정한다.
4. **다른 해상도·다른 UI 크기**에서 게임 분할 정확도.
5. **게임 중 실행** — CPU 를 많이 쓴다. 확인 창이 게임을 끄라고 안내하지만, 실제 프레임 저하는 재 보지 않았다.
