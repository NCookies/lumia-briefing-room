## 2. 기능

### 2-1. 분석 요청 대기열 — 두 탭 공통 (2026-09-29 접수, 2026-10-01 todo 로 범위 확장)

지금 분석 작업은 한 번에 하나라 실행 중이면 거부한다: 스팀 게임 `다시 분석`·`풀영상 만들기`(`POST /api/games/{key}/reanalyze`·풀영상 만들기 공유, `409`), 옛 `start_reprocess`(`api/app.py`, `409`), 영상 파일 분석·다시 분석(`409`, [spec/vod.md](spec/vod.md)). **분석 버튼을 여러 개 연달아 눌러도 거부하지 말고 대기열에 넣었다가 앞 작업이 끝나면 차례로 실행한다.**
- 대상: 스팀 녹화 탭의 게임 `다시 분석`·`풀영상 만들기`, 영상 파일 탭의 영상 `분석 시작`·`다시 분석`·`풀영상 만들기 (N)`. 큐 + 순차 워커 하나(동시 실행은 하지 않는다 — spec/vod.md "여러 영상 동시 분석"은 계속 안 함). 같은 대상 중복 요청은 무시하거나 최신 요청으로 대체. 실시간 감시의 게임 분석·과거 녹화 분석과 순서를 어떻게 맞출지(감시는 링버퍼 때문에 앞세워야 한다)는 구현 때 정한다.
- 화면: 행·영상 묶음에 "대기 중(N번째)"/"진행 중" 구분(게임 행 배지·`ActivityBar` 재사용), 대기 취소.
- **확인 창 경고**: 이미 분석한 것을 다시 분석할 때 **보관한 클립을 뺀 클립이 모두 지워진다**는 것을 확인 창에 적는다(스팀 `다시 분석` 확인 창은 지금 유지·초기화 항목을 적고 있으니 문구를 맞추고, 영상 파일 `다시 분석`에도 같은 경고를 넣는다). 구현 전에 실제 동작을 대조한다 — `자동 보관` 카테고리 클립(보관됨이 아님)이 스팀 다시 분석·영상 파일 다시 분석(`auto` 는 클립을 다시 자름 — spec/vod.md 분석 단계 "클립 컷")에서 지워지는지 남는지에 따라 문구를 정한다.
- 스팀 게임의 원본 녹화가 없으면 저장한 풀영상으로, 둘 다 없으면 불가 표시 — **이미 구현됨**(`GET /api/games/{key}/reanalyze` 의 `full`/`candidates`/`null`, [spec/pipeline.md §11](spec/pipeline.md)). 대기열에 넣을 때도 이 판정을 먼저 해서 `null` 이면 넣지 않고 "다시 분석할 수 없습니다"를 보인다.

### 2-6. 게임 정보·제목 직접 고치기 (2026-10-01 todo)

판독이 틀린 순위·TK/K/A 를 새 게임 목록에서 고칠 수단이 없다. 순위 수동 보정(`✎`, `matchResultSource="manual"`)은 옛 카드 뷰에만 있다([spec/ui.md](spec/ui.md) "게임 단위 동작").
- 게임 행·풀영상 화면 머리줄의 `⋯` 메뉴에 **`게임 정보 고치기`**: 순위(코발트는 승리/패배)·일반/랭크·TK·K·A 를 고친다. 저장 위치는 클립이 아니라 게임(`game.json`)이고, 고친 값은 잠가서(`matchResultSource="manual"` 처럼) 다시 분석·`backfill_game_result.py` 가 덮어쓰지 않게 한다 — 다시 분석은 이미 수동 결과를 잇는다([spec/pipeline.md §11](spec/pipeline.md)). 그 게임 클립의 결과 표시(클립 탭 카드)도 같은 값을 쓰게 맞춘다.
- **게임 제목**: 지금 게임에는 제목이 없다(`녹화 없음` 같은 자동 제목만). 사용자 제목 필드를 두고 게임 행의 초상화 옆에 보이며 그 자리에서 고친다(연필·더블클릭, 빈 값 = 제목 없음). 영상 파일 게임의 `스트리머 · 게임 N` 제목과의 관계는 구현 때 정한다.

### 2-8. 화면마다 주소 — 뒤로 가기로 이동 (2026-10-01 todo)

지금은 탭·열린 풀영상이 화면 상태(탭은 localStorage)라 브라우저 뒤로 가기를 누르면 앱 밖으로 나간다. 화면마다 내부 주소를 두고 history 에 쌓는다.
- 대상: 상단 탭(`스팀 녹화`/`영상 파일`/`클립`), 풀영상 화면(게임 키), 클립 탭의 카테고리. 예: `#/steam`, `#/steam/game/<경기키>`, `#/vod/game/<게임 키>`, `#/clips/<카테고리>`(형식은 구현 때 정한다 — 서버 정적 라우팅을 안 바꿔도 되는 해시 주소가 쉽다).
- 풀영상 화면의 `← 게임 목록` 과 뒤로 가기가 같은 동작이어야 하고, 돌아왔을 때 목록 스크롤 위치·접힘을 유지한다. 주소로 바로 열었는데 게임이 없으면(지워짐) 목록으로 보낸다.
- 탭 기억(localStorage)과의 관계: 주소가 있으면 주소가 우선, 없으면(첫 접속) 기억한 탭.
- 범위를 고치고 저장 안 한 후보가 있을 때 뒤로 가기로 나가는 경우는 지금 `← 게임 목록` 과 같게 처리한다.

### 2-5. 결과 화면 판독 — 남은 것 (2026-09-30)

모드 칩 3배 확대·다수결·순위 없이 저장·게임 끝 2fps 읽기·순위 숫자 본보기·숫자만 자른 OCR(1080p 실측)·소급 도구는 끝났다([spec/detection.md §8](spec/detection.md)). 남은 것:
- **순위 숫자 본보기 추가**(우선순위 낮아짐 - 본보기가 없는 숫자도 숫자만 따로 자른 OCR 로 읽힌다, [spec/detection.md §8](spec/detection.md)): 지금 **1·3 만** 있다. 2·4~8 은 그 순위가 나온 판의 결과 화면 프레임이 생길 때 `tools/build_rank_templates.py` 에 `숫자=프레임.png` 를 더 줘서 다시 만든다(기존 숫자도 같이 넣어야 한다). 본보기가 없는 순위는 OCR `N/M` 이 읽히면 그 값, 아니면 비어 남는다(`순위 미확인`).
- **순위표 화면의 `N위` 보조 출처**는 만들지 않았다 — 두 게임 풀영상 끝에 순위표 화면이 없어 화면 배치를 실측하지 못했다. 순위표 탭이 녹화에 잡힌 프레임이 생기면 그 좌측 `N위` 를 읽어 본보기로 못 읽는 순위의 보조로 쓴다.
- **판독 시간**: 결과 판독이 게임당 6.3초(키프레임) → 풀영상 끝 30초 2fps 12.5~17.6초(HEVC 1440p 소프트웨어 디코딩 ~7초 + 결과 3장 OCR ~5초)로 늘었다. 하드웨어 디코딩(`hwaccel`)이 켜진 사용자 PC 에서 줄어드는지, 진행률 상수(결과 16%)를 다시 재야 하는지 확인.
- **코발트 게임**은 소급 도구가 건너뛴다(승패 화면은 다른 판독기). 필요하면 `find_result_in_video` 가 코발트 판독도 하게.
- 곁가지 관찰: 00:25 게임의 `full.mp4` 는 세그먼트 201(`[LOADING][GAME]`)부터라 캐릭터 선택(세그먼트 약 174)이 빠져 있다. 경계 변경(`a45c581`) 전에 처리된 게임인지 다음 게임에서 확인한다.

### 2-2. `clipUid` 서버 전송

로컬 부여는 끝났다([spec/pipeline.md §8](spec/pipeline.md)). **서버가 먼저 받아야** 한다 — 앱이 먼저 보내면 계약(`additionalProperties: false`) 위반으로 라벨이 버려진다.
1. 서버(`server/receiver`): 라벨 키를 `(installId, clipUid)` 로, `legacyClipId` 가 오면 `(installId, legacyClipId)` 행을 찾아 `clipUid` 로 승격(upsert).
2. 계약 `receiver.schema.json` 과 분류표(`clipUid` `excluded` → `sent`) 갱신.
3. 앱 전송 형식 변경(살아 있는 클립·보관소 항목 모두 `legacyClipId` = 옛 파일 ID 동봉), 이미 보낸 항목 기록(digest)을 `clipUid` 기준으로 재작성.
4. `tools/pull_labels.py` 가 새 키를 이해하게.

### 2-3. 작은 기능

- **서버 401 안내**: 전송이 401 을 받으면 "서버 연결 정보가 바뀌었습니다. 업데이트해 주세요" 를 보여 조용히 안 보내지는 상태를 알린다.
- **게임 패치 대비 데이터만 받는 업데이트**: HUD 가 바뀌면 검출이 조용히 깨진다. 프로필·본보기만 빠르게 배포하는 경로(우선순위 낮음). 판독 실패 통계(`readFailStats`)가 조기 경보다.
- **캐릭터 후보 선택 UI**: 초상화가 틀렸을 때 고칠 수단. 후보 목록이 없어 설계부터 — ① 앱에 전체 캐릭터 초상화 목록을 넣고 고르게 하거나 ② "이 캐릭터 아님" 표시만.
- **옛 클립 초상화 소급**, 게임 기록만 남은 행의 초상화(요약에 경로 저장).
- **영상 파일**: 원본을 지운 뒤 판독 캐시(`.states.jsonl.gz`)도 지울지, 분석 성공 후 클립을 다 지운 영상에 "원본이 없어 다시 뽑을 수 없다" 안내를 넣을지.
- **`pvpSignalValues`**: 검출기가 신호별 수치를 결과에 담게 하고 전송에 싣는다(가중치 튜닝 재료).

## 3. 검출 품질 — 라벨·표본이 있어야 진행

- **정식 라벨셋으로 파라미터 확정**(사람 작업): 교전 구간 라벨 5판 이상 → `tools/eval_detect.py` 로 `GAP_FILL`·`MIN_COMBAT`·카운터 `min_score/min_margin/nms_radius`·사망 임계를 정한다. 지금 값은 research 수치에서 역산한 출발점.
- **영상 파일 라벨** → `eval_pvp.py --source vod` 로 스팀 표본과 비교(지금은 두 쪽 다 라벨 0 이라 수치 없음).
- `filter.minPvpScore` 를 올릴 시점 판단(라벨로 검증된 뒤).
- **결과 화면**: 탈출·일반 게임 화면 실측(샘플 없음, `matchType=unknown` 으로 버팀). 탈출 화면에 `N/M` 이 없으면 결과 화면으로 인식 못 한다.
- **코발트**: 2560x1440 **패배** 본보기(패배 판 녹화가 생기면), 2560x1440 두 자리 TK 간헐 `None`(K 본보기 리사이즈가 안 맞는 듯 — `matchTeamKills`·끝 연장에 영향), 팀원 카드 숫자 OCR 오독.
- **1080p**: 네이티브 본보기(일차 20% 미판독), 지역명(아바타 가림 외에도 본보기 불일치 의심).
- **새 신호 후보**(채택 절차: ROI 실측 → 라벨 대조 AUC → 채택/가중치 0):
  - 활성 효과 아이콘 개수 — 단순 밑줄 규칙 실패. "그 외" 라벨을 이동/전투로 나눠 분포를 봐야 한다.
  - 전멸 배너 — ROI 미측정, 내 팀 전과일 때만 뜨는지 미확인. 쓴다면 `배너 ∧ 내가 교전 중`.
  - 내 HP 급락, 팀원 HP 동시 급락.
  - 네임플레이트 — 색이 아니라 모양(눈금·레벨 상자)으로. 채택하면 **색약 설정 스크린샷 인식 옵션**도: 설정 화면 오른쪽 미리보기 패널 12행(자신~팀8)만 첨부 → `POST /api/profile/nameplate-colors` → 세로 위치로 역할별 대표 RGB → 사용자 확인 후 프로필 오버라이드 저장. 행 수가 안 맞으면 거부.
  - 캐릭터별 발동 특성(자주 쓰는 캐릭터 한둘만).
  - 팀원 링 판정을 색 대신 모양으로(빨간 머리 캐릭터 대응 — 지금은 바깥 띠로 충분).
  - R 쿨타임 값으로 궁 가중치 세분화(숫자 직접 판독은 실패 — 다른 접근 필요).
- 표본 재검증: `is_locked`(캐릭터 2명), `teammateDeathSplit`(표본 6개), 지역명 희소 이름(숲·창고 등), 일차 9 이상.

## 4. 실측 대기 — 다른 PC·환경이 필요

- **Windows 샌드박스**(절차 [DEVELOPMENT.md](DEVELOPMENT.md) "Windows 샌드박스 확인"): 깨끗한 윈도우에 `h264_mf` 가 있는지(없으면 프록시를 만들 방법이 없다), HEVC 없는 환경의 프록시 자동 전환, `canPlayType` 은 "probably" 인데 검게 나오는 경로(`videoWidth === 0`).
- **친구 배포 2차**: 다른 해상도·16:9 아닌 비율(16:10·21:9), 탈출·일반 결과 화면, 게임 중 분석 부하(우선순위 낮춤 효과 — 체감 프레임·분석 지연), Defender·백신, 전송(D10)·진단 보내기가 실제로 도는지·동의 재질문 화면. 피드백을 어디에 모을지(표·이슈)도 정한다.
- **과거 녹화 분석**: 로그에 없는 녹화가 친구 PC 에서 복구되는지, 4시간(약 40GB) 버퍼 소요 시간·메모리, 다른 해상도 게임 분할 정확도, 게임 중 실행 부하, **앞부분이 잘린 경기를 부분 클립으로라도 만들지**(지금은 건너뜀 — 사용자 의견 필요), 진행률 상수(검출 45%·결과 16%) 재보정.
- **업데이트**: 실제 GitHub 경로로 버튼·자동 업데이트를 0.1.5 이후 릴리스에서 한 번 더(절차 [DEVELOPMENT.md](DEVELOPMENT.md) "앱 안 업데이트 수동 확인"), 포트가 바뀐 경우 탭 자동 새로고침, 앱이 받은 설치기에 SmartScreen 이 뜨는지.
- **영상 파일**: 다른 스트리머 방송, 방송 한 편의 경기 경계를 손으로 표시해 자동 분할과 비교, `.mkv` `.ts` `.webm` `.mov` 실제 분석(되면 도움말의 "확인된 형식"으로), 스팀 감시와 동시 실행 시 스팀 처리가 밀리지 않는지.
- 개발 환경: pywebview(WebView2) 가 `*.localhost` 를 여는지(트레이 경로는 기본 브라우저라 영향 작음), Playwright 로 실제 클립 `<video>` `videoWidth>0` 확인, 새 주소에서 저장 폴더 선택 회귀.

## 5. 확인 필요 — 추측으로 메우지 않은 것

- 멀티킬 때 카운터가 `+2` 한 번인지 `+1` 두 번인지.
- 팀원이 살아 있을 때 내 사망 → 관전 화면의 **영상** 표본, 부활 순간 HUD 복귀 형태(사망 구간 끝 판정은 잠정), 리스폰 중 팀원 체력바 색, 체력이 낮은 주황+초록 혼합 바.
- 회색 화면이 팀 전멸에서만 뜨는가, 1일차 전멸(BREAK) 회색 화면 + 카운트다운(클립 60개에서 0건).
- 평상시 배지 색(파랑/노랑/초록) 규칙, 낮/밤 판독의 배경 간섭 마진.
- 하드웨어·소프트웨어 디코딩의 픽셀 동일성.
- 다른 해상도에서 UI 가 비례 스케일되는가.
- 일본어·한자 닉네임 OCR.
- 일자 타임라인: 페이즈 길이가 일차별로 고정인가, 경과 시간 기준(`matchStartUtc` vs HUD 첫 판독), 1~3일차를 못 읽어 클립이 뒤로 밀린다는 제보(원인 미확인), 추정도 안 되는 클립은 세션 안 촬영 순서로 정렬하는 안, 페이즈가 많은 게임의 가로 폭.
- 태그 필터·정렬이 "작동하지 않는다"는 제보(영상 파일 탭) — 재현 못 함. 가설: 태그가 OR 라 여러 개 켜면 늘어난다 / 정렬은 게임 순서에만 적용 / 타임라인 보기에서 필터 적용 단위. 재현 후 버그인지 안내 부족인지 정한다.
- 경기 종료 직후 `session.mpd` 상태와 `.tmp` 확정 타이밍(`watch.delaySec` 로 완화 중).
- `20260920_131701_01`(구간 전체가 `브리핑 룸`)을 사용자가 교전으로 라벨했다 — 맞다면 대기방 제외를 "구간 전체가 대기방일 때만"으로 좁힌다.
- clipUid 백필 소요 시간(클립 수백 개), 라벨 보관소 사본과 Windows 휴지통에서 복원한 클립이 같은 `clipUid` 로 두 번 다뤄지지 않는지.
- 자동 정리 재계산 비용(클립 수천 개), `notify_clips_changed()` 를 안 거치는 클립 쓰기·삭제 경로가 없는지.
- 분할 조각이 많을 때 `-c copy` 프리롤로 총 용량이 원본보다 커지는 정도.

## 6. 서버·운영

- **공인 IP 를 예약 IP 로**(infra 저장소에 아직 없음 — VM 재생성 시 도메인이 끊긴다), Terraform 상태 파일 백업.
- 과금·트래픽 알림, 디스크 용량 감시(메모리 1GB 에 컨테이너 3개 — OOM 가능).
- 운영 최소 절차(재부팅·docker 재기동·인증서 갱신 실패·디스크 가득)를 infra README 에.
- 서버 코드 이관 뒷정리(I6): GitHub 패키지 `receiver` 의 Actions access 에 이 저장소 추가, push 로 이미지 갱신 확인.
- 개인정보 약속 관측: 90일 자동 삭제의 실제 동작, 인터넷 스캐너 TLS 오류 기록에 IP 가 남는지.
- **파일 → DB(I5)**: 착수 기준 ① 라벨 파일이 수천 개를 넘어 조건 조회가 불편 ② 로그 검색·집계 요구. 그 전엔 `pull_labels.py` 로 내려받아 분석한다. DB 종류는 그때 정한다(정형 라벨 + 반정형 근거, 보관 기간·삭제 요청, OCI 무료 한도).
- Defender 오탐 대응: 릴리스마다 Microsoft 오탐 신고, SignPath Foundation(오픈소스 무료 서명) 신청, PyInstaller UPX·부트로더 점검. 코드 서명 인증서는 이용자가 늘면.
- 요청 제한은 IP 기준이라 VPN 으로 우회 가능(알려진 한계).

## 7. 보류 — 만들지 않기로 했거나 조건이 올 때

- **dak.gg 전적 조회로 캐릭터 채우기** — 닉네임 외부 전송(동의 항목·개인정보 안내 추가 필요, "닉네임은 보내지 않는다" 약속과 충돌), HTML 구조 변경에 약함, 약관·반영 지연·닉네임 중복 미확인. 수동 보정으로 충분하면 안 한다.
