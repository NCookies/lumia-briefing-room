## 2. 기능

### 2-1. 옛 화면 코드 제거와 태그 필터 (풀영상 전환의 마지막 단계)

풀영상 중심 전환([SPEC.md §1](SPEC.md))은 이 두 가지만 남았다.

- **옛 화면 제거**(v0.2.x 피드백 확인 후, **단독 커밋** — 되돌릴 수 있게): `ClipBrowser`·`GameSection`·`ClipCard`·`GamePlayer`·`ClipLibrary`·`LibraryFolderPicker`·`PlayerModal` 중 안 쓰게 된 것, `/api/games/reprocess`, 옛 클립 카드의 삭제 예정 배지·필터(키가 안 맞아 이미 비어 있다). [spec/ui.md](spec/ui.md) 의 "옛 화면은 코드로만 남아 있다" 문장도 같이 지운다.
  - **지우지 않는 것**: 이전 버전 데이터 이전 코드(library 이전·폴더 이름·옛 게임/영상 합치기) — 0.1.x 사용자 업그레이드에 필요하다.
  - `pipeline/reprocess.py` 의 `clear_saved_marks` 는 다른 곳이 쓰므로 옮긴 뒤 지운다.
- **태그 필터 UI**(풀영상 화면의 후보 목록). 후보 라벨 UI 는 만들지 않는다(§4 라벨링 재설계).

### 2-2. 클립 일괄 정리 (2026-10-02 사용자 피드백, 나중에)

- 여러 게임을 분석하며 쌓인 클립을 한꺼번에 정리하는 화면(예: 클립 탭에서 기간·카테고리·게임별로 골라 삭제, `자동 보관` 비우기). 지금은 게임 행 `⋯` 메뉴(`자동 보관 클립 삭제`·`게임 전체 삭제`, [spec/pipeline.md §9](spec/pipeline.md))로 게임마다 정리한다.
- **남은 정보 파일**: 앱의 삭제 경로는 모두 `delete_helper.delete_clip` 을 거쳐 정보 `json`·썸네일·재생용 변환 영상까지 같이 지운다. 쌓이는 경우는 **탐색기에서 영상만 지운 클립**의 정보·썸네일이다. 일괄 정리에서 이런 정보를 찾아 지우는 항목을 같이 둔다(영상이 잠시 다른 드라이브에 있을 수 있으니 바로 지우지 말고 보여 주고 고르게).

### 2-3. 과거 녹화 분석이 연습 모드 판을 게임으로 만들 때 (2026-10-02 실측, 보류)

- **증상**: 설치판(0.2.0)의 과거 녹화 분석이 연습 모드 판을 게임으로 만들었다. 실시간 감시는 같은 판을 잘 건너뛰었다.
- **원인으로 본 것**: 실시간 감시는 `Player.log` 의 `"matchingMode":"Practice"`·`Invoked: Practice`(`pipeline/playerlog.py`)로 거르는데, 과거 녹화 분석은 선택 화면 `PRACTICE` 글자만 읽는다(`session_scan.py` 의 `span.practice`, `detect/select_screen.py`). 그 판은 화면 판독이 놓쳤고 로그에는 연습 표시가 분명히 있었다. 화면 판독이 왜 놓쳤는지는 녹화를 지워 확인하지 못했다.
- **할 일**: 과거 녹화 분석이 `Player.log`·`Player-prev.log` 의 연습 시간대와 겹치는 게임도 건너뛴다(`playerlog` 파서가 연습 구간을 따로 돌려주게). 로그가 없는 오래된 녹화는 지금처럼 화면 판독에만 기댄다.

### 2-4. 결과 화면 판독 — 남은 것

- **순위 숫자 본보기 추가**(낮음 — 본보기가 없는 숫자도 숫자만 자른 OCR 로 읽힌다): 지금 **1·3 만** 있다. 2·4~8 은 그 순위의 결과 화면 프레임이 생길 때 `tools/build_rank_templates.py` 에 `숫자=프레임.png` 를 더 줘서 다시 만든다(기존 숫자도 같이 넣어야 한다).
- **순위표 화면의 `N위` 보조 출처** — 순위표 탭이 녹화에 잡힌 프레임이 생기면 좌측 `N위` 를 읽어 본보기로 못 읽는 순위의 보조로 쓴다.
- **판독 시간**: 결과 판독이 게임당 12.5~17.6초(HEVC 1440p 소프트웨어 디코딩 ~7초 + OCR ~5초). 하드웨어 디코딩이 켜진 PC 에서 줄어드는지, 진행률 상수(결과 16%)를 다시 재야 하는지.
- **코발트 게임**은 소급 도구(`backfill_game_result.py`)가 건너뛴다. 필요하면 `find_result_in_video` 가 코발트 판독도 하게.

### 2-5. `clipUid` 서버 전송

로컬 부여는 끝났다([spec/pipeline.md §8](spec/pipeline.md)). **서버가 먼저 받아야** 한다 — 앱이 먼저 보내면 계약(`additionalProperties: false`) 위반으로 라벨이 버려진다.
1. 서버(`server/receiver`): 라벨 키를 `(installId, clipUid)` 로, `legacyClipId` 가 오면 `(installId, legacyClipId)` 행을 찾아 `clipUid` 로 승격(upsert).
2. 계약 `receiver.schema.json` 과 분류표(`clipUid` `excluded` → `sent`) 갱신.
3. 앱 전송 형식 변경(살아 있는 클립·보관소 항목 모두 `legacyClipId` = 옛 파일 ID 동봉), 이미 보낸 항목 기록(digest)을 `clipUid` 기준으로 재작성.
4. `tools/pull_labels.py` 가 새 키를 이해하게.

### 2-6. 작은 기능

- **서버 401 안내**: 전송이 401 을 받으면 "서버 연결 정보가 바뀌었습니다. 업데이트해 주세요" 를 보여 조용히 안 보내지는 상태를 알린다.
- **게임 패치 대비 데이터만 받는 업데이트**: HUD 가 바뀌면 검출이 조용히 깨진다. 프로필·본보기만 빠르게 배포하는 경로(낮음). 판독 실패 통계(`readFailStats`)가 조기 경보다.
- **캐릭터 후보 선택 UI**: 초상화가 틀렸을 때 고칠 수단. ① 전체 캐릭터 초상화 목록에서 고르기 ② "이 캐릭터 아님" 표시만 — 설계부터.
- **옛 클립 초상화 소급**, 게임 기록만 남은 행의 초상화(요약에 경로 저장).
- **영상 파일**: 원본을 지운 뒤 판독 캐시(`.states.jsonl.gz`)도 지울지, 클립을 다 지운 영상에 "원본이 없어 다시 뽑을 수 없다" 안내를 넣을지.
- **`pvpSignalValues`**: 검출기가 신호별 수치를 결과에 담게 하고 전송에 싣는다(가중치 튜닝 재료).
- **외장 드라이브의 풀영상 폴더를 뽑으면 게임 목록이 안 보인다**(게임 기록이 풀영상과 한 묶음). "풀영상 드라이브를 찾을 수 없습니다" 안내를 줄지, 게임 기록만 앱 경로에 캐시할지는 쓰면서 본다. 드라이브가 없는 것을 "게임이 지워졌다"로 읽어 자동 정리·기록 삭제가 돌면 안 된다.

### 2-7. 정리

- 코발트 1920x1080 전용 하드코딩 ROI(`cobalt_tk/k/a_value`)·`COBALT_COUNTER_MIN_MARGIN` 을 카운터 자동 보정으로 대체하고 지운다.
- 미사용 설정 키([spec/config.md](spec/config.md) "미사용") — 쓸 기능이 없으면 스키마에서 지운다(저장된 설정 호환 확인).
- **코드·테스트 주석의 옛 plan 링크**(`plan.md §10-13`, `plan-ui.md §0`, `plan-fullvideo.md §3.9` 등 약 150곳)가 없어진 문서·절을 가리킨다. `docs/spec/<영역>.md` 로 바꾸거나 링크를 뺀다.

## 3. 릴리스 검증 자동화

> 실측 체크리스트가 릴리스마다 50개를 넘어 사람이 다 눌러 볼 수 없게 됐다(2026-10-01). **눌러 보면 아는 것은 기계가 누르게 하고, 사람은 기계가 원리상 못 보는 것만 본다.** 사람 항목의 기준(H1~H4 고정 + 조건부 C1~C4)은 이미 쓰고 있다([DEVELOPMENT.md §13](DEVELOPMENT.md)). 화면 E2E 기반과 시나리오는 있다([e2e-scenarios.md](e2e-scenarios.md)).

**남은 것 (순서대로)**: R1 → R5 → R2~R4. R1 이 끝나면 R5 의 규칙 전환을 바로 해서, 그 뒤 새로 생기는 확인 항목은 처음부터 테스트로 쓴다.

- **R1 — 검증 묶음 실행기 `tools/release_check.py`**: 한 명령으로 ① `pytest`(문서 검사 포함) ② `npm test`·`npm run lint` ③ `npm run build` 뒤 `git diff --exit-code frontend/dist`(dist 최신 확인) ④ 화면 E2E ⑤ 파이프라인 E2E(R3) ⑥ 골든 셋(R4 — 데이터 폴더가 없으면 "건너뜀"이고 `--no-golden` 을 명시해야 통과) ⑦ 마지막 태그 이후 바뀐 경로로 조건부 사람 항목 제안(`installer/`·`build.bat` → C2, `updater` → C3). 결과는 `build/release-report/` 에 `report.json`(커밋 해시·단계별 결과)·`index.html`(결과 + 스크린샷 모음). `--only e2e` 처럼 골라 돌리기. 같이 할 것: 시드 `edge`(스팀 녹화 오류 게임, 풀영상만 지운 게임, 편집 저장 대기 후보, 앱 밖 OBS mp4), 시드를 앱의 저장 함수로 만들기(지금은 `game.json` 을 직접 쓴다).
- **R5 — 체크리스트 형식·규칙 전환**: "다음 릴리스" 절을 `새로 구현된 기능 / 고친 버그`(패치노트 재료) · `자동 검증`(체크박스 없이 이번에 추가한 시나리오·골든 이름) · `사람 확인`(H1~H4 + 해당 C + 이번 릴리스 고유 항목, 왜 자동화가 안 되는지 한 마디)으로. CLAUDE.md "릴리스 체크리스트 관리"와 DEVELOPMENT §13 선행 조건(`report.json` 이 HEAD 로 전부 통과 + 사람 확인 미체크 0개)을 고치고, `tools/check_docs.py` 가 "자동 검증"에 적힌 이름이 실제로 있는지 검사하게.
- **R2 — 테스트 전용 가짜 환경**: `LUMIA_E2E_FAKES=<json>` 일 때만 `cli.serve` 가 읽는다(배포본 `sys.frozen` 에서는 무시, 테스트로 고정). 경로별 여유 공간, 경로 → 물리 디스크 번호, 스팀 녹화 중 여부, 폴더 선택 창 응답, 실패 주입(클립 추출 실패·ffmpeg stderr), 트레이 알림 기록. 기존 함수 주입·monkeypatch 지점을 쓰고 가짜를 위한 제품 코드 경로를 새로 만들지 않는다. 이걸로 감시 실패 배너·디스크 부족(노란 배너·트레이 알림 한 번·풀영상만 건너뜀)·같은 물리 디스크 경고·저장 폴더 옮기기 화면을 시나리오로 쓴다.
- **R3 — 파이프라인 E2E**: 합성 스팀 세션(`tests/conftest.py` `build_synthetic_session`)에 가짜 검출기(정해진 경계·후보·사망·결과)를 끼워 감시/과거 녹화 분석/다시 분석/풀영상 만들기를 실제 ffmpeg 로 끝까지. `pytest -m e2e`. 확인: `full.mp4` 길이, `game.json`, `clip.saveMode`, 디스크 부족 대체 동작, 다시 분석 때 보관 클립·고정·직접 추가 구간 유지, 실패 시 이전 풀영상 유지, 원본 삭제 조건, `.staging` 이 비는지, 진행률 단조 증가. 검출 정확도는 보지 않는다.
- **R4 — 실녹화 골든 셋(개발 PC 전용)**: 미디어는 `LUMIA_GOLDEN_DIR` 에, 기대값만 `tests/golden/*.json` 으로 커밋, `pytest -m golden`(폴더가 없으면 skip). 표본: 2560x1440 일반·랭크, 연습 모드, 흰 머리 팀원, 코발트.mp4(1080p), 방송 오버레이 1080p 영상 파일, 녹화 오류로 끊긴 세션. 비교: 게임 시작·끝(±10초), 연습/닷지 제외, 일반/랭크, 순위, 초상화 수, 코발트 게임별 클립 수, 사망 시각(±3초). `--update-expected` 로 갱신하고 diff 를 보고 커밋. `tools/eval_detect.py` 와 합칠지는 이때 정한다.
- **업그레이드 도우미(H2 보조)**: 실행기가 백업 사본에 새 버전 이전을 돌려 이전 전·후 게임 수·클립 수·제목/메모 붙은 클립 수·용량을 표로 내고 차이를 빨갛게.

**확인 필요(사용자)**: 골든 셋 위치·용량(예: `H:\lumia_golden`)과 넣을 녹화, 태그 단계에서 `release_tools check-tag` 가 `report.json` 을 확인해 막을지, 화면 E2E 를 GitHub Actions 윈도우 러너에서도 돌릴지, H2 를 매 릴리스 볼지 저장 구조를 건드린 릴리스만 볼지.

## 4. 검출 품질 — 라벨·표본이 있어야 진행

- **라벨링 재설계(다음 버전, 2026-10-02 결정)**: 사용자에게 교전/그 외를 직접 고르게 하지 않는다 — 규칙 검출기라 라벨 수가 늘어도 임계값 몇 개만 바뀌고, 이진 라벨은 놓친 교전·경계를 알려 주지 못한다. 대신 ① 사용자 편집 흔적(직접 추가한 구간 = 놓친 교전, 고친 범위 = 경계, 후보 삭제 = 약한 "필요 없음")을 동의받고 수집(전송 계약·동의 버전 변경, 서버 먼저) ② 개발자가 직접 만든 정답 몇 판(골든 셋과 같이 관리)으로 값을 맞추고 흔적의 잡음 비율을 잰다. 풀영상 화면 후보 라벨 UI 는 만들지 않는다.
- **정식 라벨셋으로 파라미터 확정**(사람 작업): 교전 구간 라벨 5판 이상 → `tools/eval_detect.py` 로 `GAP_FILL`·`MIN_COMBAT`·카운터 `min_score/min_margin/nms_radius`·사망 임계를 정한다. 지금 값은 research 수치에서 역산한 출발점.
- **영상 파일 라벨** → `eval_pvp.py --source vod` 로 스팀 표본과 비교.
- `filter.minPvpScore` 를 올릴 시점 판단(라벨로 검증된 뒤).
- **결과 화면**: 탈출·일반 게임 화면 실측(샘플 없음, `matchType=unknown` 으로 버팀). 탈출 화면에 `N/M` 이 없으면 결과 화면으로 인식 못 한다.
- **코발트**: 2560x1440 **패배** 본보기, 2560x1440 두 자리 TK 간헐 `None`(`matchTeamKills`·끝 연장에 영향), 팀원 카드 숫자 OCR 오독.
- **1080p**: 네이티브 본보기(일차 20% 미판독), 지역명(본보기 불일치 의심).
- **새 신호 후보**(채택 절차: ROI 실측 → 라벨 대조 AUC → 채택/가중치 0):
  - 활성 효과 아이콘 개수 — 단순 밑줄 규칙 실패. "그 외" 라벨을 이동/전투로 나눠 분포를 봐야 한다.
  - 전멸 배너 — ROI 미측정, 내 팀 전과일 때만 뜨는지 미확인. 쓴다면 `배너 ∧ 내가 교전 중`.
  - 내 HP 급락, 팀원 HP 동시 급락.
  - 네임플레이트 — 색이 아니라 모양(눈금·레벨 상자)으로. 채택하면 **색약 설정 스크린샷 인식 옵션**도(설정 화면 미리보기 12행 → 역할별 대표 RGB → 사용자 확인 후 프로필 오버라이드).
  - 캐릭터별 발동 특성(자주 쓰는 캐릭터 한둘만).
  - 팀원 링 판정을 색 대신 모양으로(빨간 머리 캐릭터 대응).
  - R 쿨타임 값으로 궁 가중치 세분화(숫자 직접 판독은 실패 — 다른 접근 필요).
- 표본 재검증: `is_locked`(캐릭터 2명), `teammateDeathSplit`(표본 6개), 지역명 희소 이름(숲·창고 등), 일차 9 이상.

## 5. 실측 대기 — 다른 PC·환경이 필요

- **Windows 샌드박스**([DEVELOPMENT.md §15](DEVELOPMENT.md)): 깨끗한 윈도우에 `h264_mf` 가 있는지, HEVC 없는 환경의 프록시 자동 전환, `canPlayType` 은 "probably" 인데 검게 나오는 경로(`videoWidth === 0`).
- **친구 배포 2차**: 다른 해상도·16:9 아닌 비율(16:10·21:9), 탈출·일반 결과 화면, 게임 중 분석 부하(체감 프레임·분석 지연), Defender·백신, 전송·진단 보내기가 실제로 도는지·동의 재질문 화면. 피드백을 어디에 모을지(표·이슈)도 정한다.
- **과거 녹화 분석**: 로그에 없는 녹화 복구, 4시간(약 40GB) 버퍼 소요 시간·메모리, 다른 해상도 게임 분할 정확도, 게임 중 실행 부하, **앞부분이 잘린 경기를 부분 클립으로라도 만들지**(지금은 건너뜀 — 사용자 의견 필요), 진행률 상수(검출 45%·결과 16%) 재보정.
- **풀영상**: 25분 경기 `-c copy` 컷 시간과 게임 중 디스크 쓰기 부하, 링버퍼 여유가 적을 때 풀영상 컷과 클립 컷의 순서, 풀영상 폴더가 다른 드라이브일 때 복사 시간, 프록시(H.264) 폴백에서 풀영상 전체 변환 비용.
- **업데이트**: 포트가 바뀐 경우 탭 자동 새로고침, 앱이 받은 설치기에 SmartScreen 이 뜨는지.
- **영상 파일**: 다른 스트리머 방송, 방송 한 편의 경기 경계를 손으로 표시해 자동 분할과 비교, `.mkv` `.ts` `.webm` `.mov` 실제 분석(되면 도움말의 "확인된 형식"으로), 스팀 감시와 동시 실행 시 스팀 처리가 밀리지 않는지, 게임 풀영상 끝(결과 화면 첫 판독 + 15초)이 랭크 점수 화면이 긴 영상에서 잘리는지.
- 개발 환경: pywebview(WebView2) 가 `*.localhost` 를 여는지.

## 6. 확인 필요 — 추측으로 메우지 않은 것

- 멀티킬 때 카운터가 `+2` 한 번인지 `+1` 두 번인지.
- 팀원이 살아 있을 때 내 사망 → 관전 화면의 **영상** 표본, 부활 순간 HUD 복귀 형태(사망 구간 끝 판정은 잠정), 리스폰 중 팀원 체력바 색, 체력이 낮은 주황+초록 혼합 바.
- 회색 화면이 팀 전멸에서만 뜨는가, 1일차 전멸(BREAK) 회색 화면 + 카운트다운.
- 평상시 배지 색(파랑/노랑/초록) 규칙, 낮/밤 판독의 배경 간섭 마진.
- 하드웨어·소프트웨어 디코딩의 픽셀 동일성.
- 다른 해상도에서 UI 가 비례 스케일되는가.
- 일본어·한자 닉네임 OCR.
- **게임 경계**: 닷지 표본 — "닷지 = 캐릭터 선택 뒤 `[LOADING][GAME]` 없이 `StartMatching` 이 다시 찍힘"이라는 가정으로 구현했다. 닷지 때 `Player.log` 에 어떤 줄이 남는지, 화면이 선택 화면에서 바로 로비로 가는지. 사용자 설정 게임의 로그 모양, 코발트의 선택 화면 흐름, 다시보기에서 선택 화면이 방송 전환으로 가려지는 경우.
- 일자 타임라인: 페이즈 길이가 일차별로 고정인가, 경과 시간 기준(`matchStartUtc` vs HUD 첫 판독), 1~3일차를 못 읽어 클립이 뒤로 밀린다는 제보(원인 미확인).
- 태그 필터·정렬이 "작동하지 않는다"는 제보(영상 파일 탭) — 재현 못 함. 가설: 태그가 OR 라 여러 개 켜면 늘어난다 / 정렬은 게임 순서에만 적용. 재현 후 버그인지 안내 부족인지 정한다.
- 경기 종료 직후 `session.mpd` 상태와 `.tmp` 확정 타이밍(`watch.delaySec` 로 완화 중).
- `20260920_131701_01`(구간 전체가 `브리핑 룸`)을 사용자가 교전으로 라벨했다 — 맞다면 대기방 제외를 "구간 전체가 대기방일 때만"으로 좁힌다.
- clipUid 백필 소요 시간(클립 수백 개), 라벨 보관소 사본과 Windows 휴지통에서 복원한 클립이 같은 `clipUid` 로 두 번 다뤄지지 않는지.
- 자동 정리 재계산 비용(클립 수천 개), `notify_clips_changed()` 를 안 거치는 클립 쓰기·삭제 경로가 없는지.
- 분할 조각이 많을 때 `-c copy` 프리롤로 총 용량이 원본보다 커지는 정도.
- 공간 부족 경고 기준(여유 공간 < 예상 게임 용량 × 5)이 실사용에서 맞는지.

## 7. 서버·운영

- **공인 IP 를 예약 IP 로**(infra 저장소에 아직 없음 — VM 재생성 시 도메인이 끊긴다), Terraform 상태 파일 백업.
- 과금·트래픽 알림, 디스크 용량 감시(메모리 1GB 에 컨테이너 3개 — OOM 가능).
- 운영 최소 절차(재부팅·docker 재기동·인증서 갱신 실패·디스크 가득)를 infra README 에.
- 서버 코드 이관 뒷정리: GitHub 패키지 `receiver` 의 Actions access 에 이 저장소 추가, push 로 이미지 갱신 확인.
- 개인정보 약속 관측: 90일 자동 삭제의 실제 동작, 인터넷 스캐너 TLS 오류 기록에 IP 가 남는지.
- **파일 → DB**: 착수 기준 ① 라벨 파일이 수천 개를 넘어 조건 조회가 불편 ② 로그 검색·집계 요구. 그 전엔 `pull_labels.py` 로 내려받아 분석한다.
- Defender 오탐 대응: 릴리스마다 Microsoft 오탐 신고, SignPath Foundation(오픈소스 무료 서명) 신청, PyInstaller UPX·부트로더 점검. 코드 서명 인증서는 이용자가 늘면.
- 요청 제한은 IP 기준이라 VPN 으로 우회 가능(알려진 한계).

## 8. 보류 — 만들지 않기로 했거나 조건이 올 때

- **dak.gg 전적 조회로 캐릭터 채우기** — 닉네임 외부 전송(동의·개인정보 안내 추가 필요, "닉네임은 보내지 않는다" 약속과 충돌), HTML 구조 변경에 약함, 약관·반영 지연·닉네임 중복 미확인. 수동 보정으로 충분하면 안 한다.
- **님블 Open API(`open-api.bser.io`)** — 쓸지 정하지 않았다. 명세는 개발 PC 에만 둔다(`docs/eternal-return-openapi.json`, 키 발급자만 볼 수 있는 자료라 git 제외).
- **클립 공유 호스팅** — 앱과 분리된 별도 서비스로만. 영상은 앱 밖으로 보내지 않는다는 원칙 때문에 앱 안 업로드는 없다.
- 하이라이트 자동 선별(원래의 팟지 목표), 한글 킬피드 판독, 사망 시점 정밀 검출.
- 설치·사용자 수 신호 — 새 동의 항목을 만들지 않기로 결정(2026-09-27). 부족하다고 느낄 때 다시.
