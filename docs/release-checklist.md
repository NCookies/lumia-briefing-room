# 릴리스 체크리스트

> 마지막 릴리스 태그 이후 **새로 구현된 기능 / 고친 버그**를 정리하고, 그중 손으로
> 직접 확인해야 하는 항목을 체크리스트로 관리하는 문서다. 자동 테스트(pytest)로
> 이미 고정된 것은 여기 올리지 않는다 — 여기 적는 건 **사람이 실제로 눌러 봐야
> 아는 것**만이다.
>
> **작업 단위(버그 하나 고침, 기능 하나 추가 등)가 끝나면 그 커밋 안에서 바로
> "다음 릴리스" 절을 갱신한다.** [CLAUDE.md](../CLAUDE.md) "릴리스 체크리스트 관리"
> 참고. 릴리스 태그를 달기 전에는 반드시 이 문서의 미확인 체크박스를 확인한다
> ([DEVELOPMENT.md §13](DEVELOPMENT.md)).

## 다음 릴리스 (기준: v0.1.8 이후, 미출시)

### 새로 구현된 기능

- **코발트 프로토콜(배틀로얄 모드) 지원** — 모드 자동 판별, `Phase N` 기반 게임 경계,
  `PROTOCOL COMPLETE` 승/패 판독, 팀원 4인 스쿼드, UI 배지, 클립 제목 `Phase N`.
  1920×1080·2560×1440 실측 완료. ([plan.md §10](plan.md), SPEC §2.9)
- **다시보기(VOD) 분석 후 원본 삭제 옵션 (V7)** — 묻기/항상/안 함 + 휴지통/영구
  삭제 선택, 기본값 휴지통. ([plan-vod.md V7·§8-10](plan-vod.md))
- **자동 정리 "삭제 예정" 표시** — 빨간 계열 배지·필터, 자동 정리를 켤 때 확인 창.
  ([plan-ui.md §0](plan-ui.md))
- **실시간 감시 실패를 화면에 표시하고 "계속하기"로 재시도** — 디스크 용량 부족 등으로
  클립 추출이 실패하면 상단에 빨간 배너로 원인을 보여주고(새로고침해도 유지), 재시도
  횟수 제한과 무관하게 즉시 다시 시도시킬 수 있다. ([SPEC §7.2 실패 재시도](SPEC.md))
- **다시보기 목록에서 항목을 완전히 삭제** — "전체 삭제"(클립만 비움)와 달리 색인
  자체를 지운다. 원본 영상까지 이미 지워졌으면 목록에서도 완전히 사라진다.

- **스팀 녹화 게임 목록을 날짜별로 구분** — 커뮤니티 피드백. 자정 기준으로 날짜 머리줄
  (`9월 30일 (수) · 오늘`, 게임·클립 수와 용량)을 두고, 스크롤해도 머리줄이 위에 붙어 있다.
- **영상 파일 탭도 날짜별로 구분** — 스팀 녹화 탭과 같은 날짜 머리줄을 영상 날짜 기준으로 둔다
  (`영상 N개 · 게임 · 클립 · 용량`, 날짜 없는 영상은 맨 뒤 `날짜 모름`).
- **게임 경계를 캐릭터 선택 화면부터로 넓히고 연습 모드를 뺌(풀영상 전환 F1)** —
  로그 감시가 캐릭터 선택·루트 선택 약 80초를 게임에 포함하고, 닷지한 선택은 버리며,
  연습 모드는 게임으로 치지 않는다. ([plan-fullvideo.md §3.8](plan-fullvideo.md))
  과거 녹화 분석도 화면의 캐릭터·루트 선택 화면을 찾아 게임 시작을 앞당기고, 닷지한
  선택 화면은 버린다.
- **게임마다 풀영상 저장 + 게임 기록(풀영상 전환 F1)** — 분석이 끝나면 게임 전체를
  `games\<경기키>ull.mp4`(24분 게임 약 4GB)로, 교전 후보·킬/어시/사망 마커를 `game.json` 으로
  남긴다. 기존 클립 저장은 그대로(`clip.saveMode` 기본 `auto`). 풀영상을 못 만들면 확실한
  후보(킬·어시·사망)만 클립으로 남긴다. 화면(UI)에는 아직 나오지 않는다. ([spec/pipeline.md §11](spec/pipeline.md))
- **저장 공간 부족 트레이 알림(풀영상 전환 F2)** — 앱 시작 때와 게임 분석 직전에 여유 공간을
  재서 `max(게임 5개 몫, 20GB)` 미만이면 트레이 알림을 띄운다. 풀영상 저장이 실패해도
  알린다. 화면 상단 노란 배너로도 보이고, 첫 실행 화면에는 "50~100GB 여유 공간" 경고와 현재 여유
  공간, "확인했습니다" 체크가 생겼다. ([spec/pipeline.md §12](spec/pipeline.md))
- **자동 정리 대상이 클립에서 풀영상으로 바뀜(풀영상 전환 F3)** — 새 설치의 기본값은 자동 정리 켬 +
  총 용량 40GB. 풀영상만 지우고 게임 기록(`game.json`)과 저장한 클립은 남는다. 이미 설정을 저장한
  사용자는 기존 값 그대로지만 대상이 풀영상으로 바뀌어, **저장한 클립은 더 이상 자동으로 지워지지 않는다**(패치노트에 쓸 것).
  옵션 → 자동 정리 화면 문구도 풀영상 기준으로 바뀌었다. ([spec/pipeline.md §9](spec/pipeline.md))
- **"스팀 녹화" 탭이 게임 목록 → 풀영상 화면으로 바뀜, 스팀 편집기식 재생 막대(풀영상 전환 F4-b)** —
  "게임(풀영상)" 탭은 없어지고 "스팀 녹화" 탭에서 날짜별 게임 목록 → 열기로 풀영상 화면이 뜬다
  (영상 + 오른쪽 후보 목록, 재생 막대는 하나). 막대 어디를 눌러도(노란 구간 안도) 그 자리로 이동하고,
  구간 편집은 선택한 구간의 양 끝 손잡이(놓으면 자동 기록)·되돌리기·돋보기 +/−(좌우 스크롤 띠)·"+ 여기서 구간 추가"로만 한다
  (구간 통째 옮기기·빈 곳 끌어 만들기는 없어짐). 단축키 Space·←/→·N/P·S·D·I/O. 옛 카드 뷰는 코드만 남아 있다(F5 에서 제거).
  ([spec/ui.md](spec/ui.md))
- **이전 버전 게임을 스팀 녹화 탭에 합침(풀영상 전환 F4-c)** — 풀영상 전환 전에 만든 클립·게임 기록이 날짜 머리줄 아래
  게임 행으로 나온다("풀영상 없음(이전 버전)" 배지). 열면 안내와 함께 저장된 클립 목록·재생이 뜬다. 원본이 스팀 링버퍼에
  남은 게임은 "풀영상 만들기" 버튼 또는 과거 녹화 분석으로 풀영상·후보를 새로 만든다(기존 클립은 다시 만들지 않음).
  **패치노트 후보**: 이전 버전 게임은 풀영상 없음, 원본이 남았으면 과거 녹화 분석으로 풀영상 생성.
  ([spec/pipeline.md §11](spec/pipeline.md))
- **"과거 녹화 분석" 버튼을 스팀 녹화 탭 도구 줄로 이동(풀영상 전환 F4-d)** — 헤더의 옵션 버튼 옆에서 게임 목록 위 "게임 N개" 줄 오른쪽 끝으로. 영상 파일 탭에서는 보이지 않는다. ([spec/ui.md](spec/ui.md))
- **날짜 접기·바로가기(풀영상 전환 F6-a, 스팀 녹화·영상 파일 공통)** — 커뮤니티 피드백("9/27, 9/28 이렇게 넘어가서 딱 그것만"). 날짜 머리줄을 누르면 그 날짜 목록이 접히고(머리줄 한 줄은 남음), 모두 펼치기/접기와 접힘 기억(새 날짜는 펼침)이 있다. 영상 파일 탭의 날짜 칩은 거르기에서 바로가기(누르면 그 날짜로 스크롤, 접혀 있으면 펼침)로 바뀌었고 스팀 녹화 탭에도 같은 줄이 생겼다. ([spec/ui.md](spec/ui.md))
- **영상 파일(1080p)에서도 캐릭터 초상화를 찾음** — 선택 화면 판독으로 찾도록 바꿔 방송 오버레이가 미니맵 자리를
  덮은 다시보기에서도 초상화 3장이 나온다. 1080p 에서도 게임 시작을 선택 화면부터로 잡고 닷지·연습 모드를 거른다.

- **영상 파일 분석이 게임마다 풀영상을 만듦(풀영상 전환 F6 백엔드)** — 영상 한 편을 분석하면 게임마다 캐릭터 선택 화면 ~ 결과 화면 끝을
  원본에서 그대로(`-c copy`) 잘라 `games\vod_<영상id>_g<번호>\full.mp4` 와 `game.json`(후보·마커·결과·초상화)으로 남긴다. 스팀 게임과 같은 폴더·같은 형식이고
  자동 정리 한도(합산)에 함께 들어간다. `clip.saveMode` 를 따른다(`auto` 는 클립도 자름, `manual` 은 풀영상·후보만). 연습 모드 게임은 게임으로 치지 않는다.
  **원본 자동 삭제(V7)의 조건이 "클립 1개 이상"에서 "게임 풀영상 1개 이상 저장됨"으로 바뀌었다.**
  화면(UI)은 아직 옛 카드 화면이다. ([spec/vod.md](spec/vod.md))

- **영상 파일 탭이 스팀 녹화 탭과 같은 풀영상 방식으로 바뀜(풀영상 전환 F6 화면)** — 날짜 머리줄 > 영상 묶음(분석 시작·취소·진행률, 날짜·이름 고치기, 다시 분석, 전체 삭제 그대로) > 게임 행(초상화·순위·TK/K/A, 스팀 녹화와 같은 모양) → 게임을 누르면 풀영상 화면(후보 다듬기·저장·일괄 저장). 필터 바는 스팀 녹화 탭처럼 없어졌고 새로고침만 남았다. 옛 카드 화면은 코드로만 남아 있다(F5 에서 제거).
  **이전 버전에서 분석한 영상**은 원본이 남았으면 영상 머리의 "풀영상 만들기 (N)" 로 풀영상·초상화를 새로 만든다(누르는 방식 - 디스크를 크게 쓴다. 하이용가리 12GB 원본 ≈ +9.7GB). 원본이 지워졌으면 "풀영상 없음(이전 버전)" 과 저장된 클립으로 보인다.
  **패치노트 후보**: 영상 파일도 게임마다 풀영상 저장, 전체 삭제가 풀영상까지 지움, 풀영상이 자동 정리 합산 한도에 들어감. ([spec/vod.md](spec/vod.md), [spec/ui.md](spec/ui.md))
- **옵션에 "클립 저장 방식"(자동/직접)과 "지우기 전에 확실한 교전 후보를 클립으로 남기기" 추가(풀영상 전환 F-opt)** — 일반 탭에서 자동 저장/직접 저장을 고른다(자동 옆에 "게임마다 1.5~2GB 씩 쌓입니다" 안내). 자동 정리 탭의 체크박스(기본 꺼짐)를 켜면 풀영상을 지우기 직전 킬·어시·사망이 있는 후보 중 저장 안 된 것을 클립으로 남기고, 하나라도 못 남기면 그 풀영상은 지우지 않는다. 삭제 예정 배지·정리 확인 결과에 남길 클립 수가 보인다. ([spec/pipeline.md §9](spec/pipeline.md), [spec/ui.md §6](spec/ui.md))
- **게임 목록에 용량 막대와 "삭제 예정만 보기"(풀영상 전환 F3)** — 스팀 녹화·영상 파일 두 탭의 "게임 N개" 줄에 `이 탭 6.2GB · 전체 10.8GB / 40GB` 막대(한도에 가까우면 노랑·빨강, 자동 정리가 꺼졌거나 한도가 없으면 숨김)와 삭제 예정 게임만 보는 버튼이 생겼다. ([spec/ui.md](spec/ui.md))
- **클립 정보를 앱 데이터 폴더로 옮기고, 클립 영상은 하위 폴더 어디 있어도 찾음(풀영상 전환 F8·F7 기반)** — 앱을 켤 때 옛 클립 폴더에 mp4 와 섞여 있던 정보(json·썸네일·라벨 보관·게임 기록·영상 색인)를 `%LOCALAPPDATA%\LumiaBriefingRoom\library\{steam,vod}` 로 옮긴다(영상은 그대로, 두 번 돌려도 같고 중간에 꺼져도 이어 한다). 클립 폴더 안 하위 폴더로 영상을 옮겨도 파일 이름으로 찾는다. 재생용 변환 영상·영상 작업 폴더는 영상 드라이브에 둔다. 옛 앱 버전으로 돌아가려면 `python -m lumia_briefing_room.cli.library_migrate --undo`. **패치노트 후보**: 클립 정보 위치가 바뀜(자동 이전, 영상은 안 옮김). ([spec/pipeline.md §9](spec/pipeline.md))
- **저장 폴더 하나로 정리 + 옵션에서 옮기기(풀영상 전환 F8)** — 옵션 → 일반 → "저장 폴더"에서 폴더 하나를 고르면 그 안에 `클립\{스팀 녹화,영상 파일}`·`풀영상\…` 으로 나뉜다(새로 설치하면 `내 비디오\LumiaBriefingRoom` 이 자동으로 잡히고 첫 실행 화면에서 바꿀 수 있다). 이전 버전 사용자는 쓰던 폴더를 그대로 쓰고, "새 구조로 옮기기…"를 고르면 클립 영상·풀영상·재생용 변환 영상을 진행률과 함께 옮긴다(충돌하면 거부, 끝난 뒤 되돌리기 가능). "고급"에서 풀영상 위치만 다른 드라이브로 둘 수 있다. 영상 파일 탭 설정의 클립 저장 폴더 칸은 없어졌다. **패치노트 후보**: 새 폴더 구조, 옮기기는 선택. ([spec/pipeline.md §9](spec/pipeline.md), [spec/ui.md §6](spec/ui.md))
- **클립을 탐색기에서 이름을 바꾸거나 옮겨도 정보가 이어짐(풀영상 전환 F7 기반)** — 새 클립은 영상 안에 ID(`clipUid` mp4 태그)를 넣어 두고, 태그가 없는 옛 클립은 앱이 켜질 때 영상 내용 지문을 기록해 이어 준다(옛 mp4 는 다시 쓰지 않는다). 같은 클립을 복사해 두면 둘 다 보이고 제목·태그·라벨은 같이 쓴다.

([spec/ui.md](spec/ui.md))
- **게임 다시 분석(F10)** — 스팀 녹화 탭 게임 행 `⋯` 와 풀영상 화면 머리줄 메뉴의 `다시 분석`. 원본 스팀 녹화가 남아 있으면 풀영상·후보·결과표·초상화를 전부 새로 만들고, 시간이 지나 원본이 지워졌으면 저장한 풀영상에서 후보·결과표·초상화만 다시 찾는다(풀영상은 그대로). 보관한 클립·고정·직접 추가한 구간은 이어지고 후보의 무시·이름·범위 수정은 초기화된다. 결과 화면·초상화를 잘못 읽었을 때 쓴다. ([spec/pipeline.md](spec/pipeline.md))
- **게임 행 `⋯` 메뉴로 풀영상·클립 삭제(F10)** — 스팀 녹화·영상 파일 두 탭의 게임 행 오른쪽 `⋯`(풀영상 화면 머리줄에도 같은 메뉴)에서 `풀영상만 삭제`·`클립만 전체 삭제`·`게임 전체 삭제`(풀영상·클립·게임 기록까지 지워 목록에서 사라짐 - 연습 모드 게임 정리용). 확인 창에 지워질 풀영상 크기와 클립 수가 뜬다. 고정한 게임은 "다시 묻지 않기"를 켰어도 경고한다. ([spec/ui.md](spec/ui.md))
- **보관 해제·게임 전체 삭제·보관 기본값 정리(2026-10-01 사용자 피드백)** — ① 후보 행에 `클립 삭제`(보관됨 여부와 상관없이 클립이 있으면)가 생겼다 — 클립 영상과 그 구간(후보)을 함께 지운다(되돌릴 수 없음, `보관 해제`는 없앰). 자동 보관 카테고리의 클립은 보관됨이 아니라 `보관` 상태로 보이고, 카테고리를 고르면 그 클립이 옮겨져 보관됨이 된다. ② 게임 행·풀영상 화면 머리줄 `⋯` 메뉴에 `게임 전체 삭제`(풀영상·클립·게임 기록까지 지워 목록에서 사라짐)가 생겼다 — 연습 모드 게임 정리용. ③ `clip.saveMode` 기본값이 `직접 보관`이 되어 새 설치에서는 후보가 보관되지 않은 상태로 시작한다(이미 저장된 설정은 그대로). ④ 보관 위치 팝업에 `자동 보관` 칸이 항상 보인다. ⑤ 후보 행의 `확실`·태그 배지와 막대의 확실 구분을 뺐고, 재생 막대를 마우스 휠로 확대/축소할 수 있다. ⑥ 메모 입력칸 안내 문구를 "원하시는 내용을 작성해 주세요"로 바꿨다. ([spec/ui.md](spec/ui.md))
- **클립 탭 "찾을 수 없는 폴더입니다" 오류 수정, 초상화 자동 복구** — 카테고리 기본 폴더(`보관함`·`자동 보관`)가 없어서 클립 탭이 오류를 띄우던 것을 고쳤다(목록을 읽을 때 폴더를 만든다, 다른 카테고리로 옮겨도 오류 배너가 남지 않는다). 다시 분석 등으로 `game.json` 이 초상화 이름을 잃어도 게임 폴더에 초상화 파일이 남아 있으면 다시 보여 준다.
- **코발트 게임에 남은 초상화 파일이 다시 보이던 문제 수정** — 코발트는 초상화를 쓰지 않기로 했는데(`game.json` 의 초상화는 비어 있음), 위 "초상화 자동 복구"가 게임 폴더에 남은 `portrait_*.jpg` 를 되살려 영상 파일 탭 코발트 게임 행에 초상화가 떴다. 코발트 게임은 폴더에 파일이 있어도 복구하지 않는다. ([spec/detection.md §9](spec/detection.md))
- **흰 머리 캐릭터 등 채도 낮은 팀원 초상화도 읽음** — 선택 화면이 보이는데도 흰 머리 팀원 카드가 "초상화다운 색" 기준(채도 높은 픽셀 10%)에 걸려 게임 전체 초상화가 비던 문제. 밝기의 결(표준편차 40 이상)로도 채워진 카드로 보고, 회색 `EMPTY` 자리표시는 여전히 거른다. ([spec/detection.md §9](spec/detection.md))
- **풀영상이 없는 게임에서도 클립 재생** — 풀영상만 삭제(또는 자동 정리)한 게임을 열면 안내만 뜨고 클립을 볼 방법이 없던 것을 고쳤다. 클립은 풀영상과 별개 파일이라 그대로 있으므로, 후보 목록에서 클립이 있는 후보를 누르면 왼쪽에서 그 클립이 재생된다. 같은 화면에서 범위가 `3:19~0:00 (-199초)` 로 깨지고 `수정됨 · 저장 대기`가 잘못 뜨던 것도 고쳤다.
- **저장 폴더가 스팀 녹화와 같은 디스크면 옵션에서 경고** — 풀영상·클립 폴더가 녹화와 같은 물리 디스크(한 하드디스크를 나눈 드라이브 포함)에 있으면, 게임 중 복사 속도 제한 때문에 늦게 만들어진다는 것과 다른 디스크로 옮기기를 권하는 안내를 옵션 "저장 폴더"에 띄운다.

([spec/ui.md](spec/ui.md))

- **게임 정보·제목 직접 고치기** — 게임 행·풀영상 화면 `⋯` 메뉴의 `게임 정보 수정하기`에서 제목과 순위·일반/랭크·TK/K/A
  (코발트는 승리/패배)를 고친다. 순위·TK/K/A 를 고치면 그 값으로 고정되고 다시 분석·결과 채우기가 덮어쓰지 않으며 그 게임의
  클립 결과도 같은 값으로 바뀐다. 제목은 게임 행 초상화 옆과 풀영상 화면 머리줄에 보인다(빈 값 = 제목 없음).
  ([spec/pipeline.md §11](spec/pipeline.md))
- **분석 요청 대기열(두 탭 공통)** — 스팀 게임 `다시 분석`·`풀영상 만들기`, 영상 파일 `분석 시작`·`다시 분석`·`풀영상 만들기 (N)` 를
  앞 작업이 도는 중에 눌러도 거부("다른 게임을 분석하는 중입니다")하지 않고 줄을 선다. 행·영상 머리에 `대기 중 (N번째)` 와 `대기 취소` 가 뜨고,
  앞 작업이 끝나면 차례로 돈다(한 번에 하나, 동시 실행 없음). 실시간 감시가 게임을 처리하는 동안은 대기 중인 분석이 시작하지 않는다.

  그렇게 했다고 알린다. 확인 창은 "이 게임을 다시 분석합니다. 몇 분 정도 소요될 수 있습니다." 두 줄로 줄였다. ([spec/pipeline.md §11](spec/pipeline.md), [spec/vod.md](spec/vod.md))
  **패치노트 후보**: 분석 버튼을 여러 개 눌러도 대기열에 쌓여 차례로 실행, 다시 분석은 자동 저장 클립만 새로 만들고 보관한 클립은 유지, 원본이 없어도 풀영상으로 다시 분석.
- **게임 목록(스팀 녹화·영상 파일 탭)이 훨씬 빨리 열림** — 보관한 클립마다 클립 폴더를 다시 훑던 것을 요청당 한 번으로 줄였다(실측 영상 27게임 8.0초 → 0.5초, 스팀 9게임 2.1초 → 0.2초).
- **영상 파일 탭이 불러오는 중에 "게임 0개"·"이 영상에서 찾은 게임이 없습니다"를 보이지 않음 / 풀영상 화면에서 돌아오면 목록이 바로 맞음** — 게임을 읽는 동안은 "게임 불러오는 중…"과 막대만 보이고, 풀영상 화면에서 보관·무시한 뒤 목록으로 돌아오면 게임 행의 `보관 M` 이 새로고침 없이 바뀐다(스팀 녹화 탭도 같음).
- **풀영상 화면 키보드 조작** — `Ctrl+←/→` 이전/다음 클립, 이전 클립은 현재 클립 시작 후 3초 안이면 바로 앞 클립, `Delete` 클립 삭제, `Ctrl+S` 보관 위치 팝업(↑/↓·Enter·Esc), `M` 메모(`Ctrl+Enter` 저장하고 닫기), 확인 창 ←/→·Space·Enter·Esc, `?`/`⌨` 단축키 표(처음 한 번 펼침). 버튼·체크박스를 누른 뒤 Space 등이 안 먹던 것(체크박스·슬라이더를 글자 입력칸으로 오인, 확인 창 체크박스를 Space 로 못 켬)과 한글 자판에서 글자 단축키가 안 먹던 것을 고쳤다. ([spec/ui.md](spec/ui.md) 풀영상 화면 키보드 조작)

### 고친 버그 / 개선

- **캐릭터 초상화 검출·크롭 반복 재보정** — 실전에서 초상화가 항상 비던 문제,
  카드 테두리 침범·상단 배경 침범 크롭 재조정(3차), 정사각형이 아닌 원본 비율로
  표시. 이번 릴리스에서 가장 많이 손댄 영역.
- **백필(과거 녹화 분석) 진행률 바** — 스캔 후 50%에 고정되던 것을 실제 작업량
  비율로 계산하도록 수정. ([plan-backfill.md §0 B8](plan-backfill.md))
- **클립 재생 모달** — 바깥 클릭으로 닫히던 것을 닫기 버튼·ESC로만 닫히게 변경.
- **라벨링 자동 다음 이동 제거** — 개발 모드에서도 라벨을 매기면 다음 클립으로
  자동으로 넘어가지 않도록 변경.
- **VOD 게임 목록/삭제 개선 + 코발트 프론트엔드 표시 + 필터 정리**.
- **다시보기 분석 실패 메시지에 디스크 용량 부족 구분 표시** — ffmpeg 실패의 실제
  원인(stderr)을 읽어 "저장 공간이 부족합니다"처럼 명확히 보여준다(기존엔 종료
  코드만 남아 원인을 알 수 없었다).
- **"성공 시 원본 삭제" 뒤 "영상 파일을 찾을 수 없습니다" 오해 방지** — 사용자가
  설정으로 직접 지운 경우 빨간 오류 대신 "설정에 따라 원본을 자동 삭제했습니다"로
  구분해서 보여준다.
- **다시보기 분석 진행률이 게임 넘어갈 때 뒤로 튀던 문제 수정** — 클립이 앞쪽
  게임에 몰려 있으면(예: 85%) 다음 게임 처리로 넘어가는 순간 막대가 훨씬 낮은
  값(예: 24%)으로 떨어져 보이던 계산 버그.
- **코발트 모드 사망 검출이 안 돼 게임 전체가 클립 하나로 뭉치던 문제 수정** —
  얼굴·미니맵 헤더 아이콘 ROI 가 배틀로얄 좌표 그대로라 코발트 화면에서는 캐릭터
  UI 자체를 못 읽고 있었다(실측, 코발트.mp4 2026-09-29). 코발트 전용
  `cobalt_face`/`cobalt_minimap_icons` 좌표를 추가하고 game_mode 가 밝혀진 뒤 그
  값으로 사망을 판정하도록 수정 — 실제 재분석으로 게임 6판이 클립 1개(통짜)에서
  42개(목숨 개수만큼)로 정상 분리됨을 확인.
- **게임 결과 화면 판독 누락 줄이기** — 게임 끝 30초를 초당 2장으로 읽고 여러 장을 항목별 다수결로
  정한다. "일반" 칩이 `unknown` 으로 남던 것(3배 확대 먼저), 순위 숫자 `3` 을 못 읽어 결과 전체가
  "결과 미확인"이 되던 것(숫자 본보기 대조, 그래도 못 읽으면 순위만 비우고 `순위 미확인` 표시)을 고쳤다.
  이미 저장된 게임은 `python tools/backfill_game_result.py` 로 채운다. ([spec/detection.md §8](spec/detection.md))
- **풀영상 없는 이전 버전 게임 화면에서 영상 아래쪽이 잘리던 것을 고침, 게임 목록에서 바로 "풀영상 만들기"** — 저장된 클립 영상이 화면 높이에 맞게 줄어 재생 컨트롤까지 보인다. 원본이 남은 이전 버전 게임 행에는 "풀영상 만들기" 버튼이 붙는다(누르면 행에 진행률).
- **게임 중 풀영상을 만들다 스팀 녹화가 끊기던 문제** — 판이 끝나 풀영상(수 GB)을 녹화와 같은 HDD 에서 몰아서 복사하면 스팀이 프레임을 버리다 녹화를 오류로 끝내, 게임을 다시 켤 때까지 다음 판들이 녹화되지 않았다("세그먼트를 찾을 수 없다"). 스팀이 녹화 중이면 녹화 폴더를 읽고 녹화 디스크에 쓰는 속도를 초당 32MB 로 제한한다(같은 물리 디스크면 드라이브 문자가 달라도 제한).
- **스팀 녹화가 멈춰 비어 있는 게임에 원인 표시** — 녹화가 오류로 멈춘 뒤의 게임이 "세그먼트를 찾을 수 없다: 680-1180"·"결과 미확인"으로만 보이던 것을, 게임 목록에 `스팀 녹화 오류로 녹화 없음`(제목 `녹화 없음`)·`스팀 녹화 오류로 일부만 녹화` 배지로 보여 주고, 배너도 "스팀 녹화가 멈췄습니다"로 원인을 알린다. 이미 저장된 게임에도 적용된다.
- **결과 화면이 아닌 화면을 결과로 저장하던 것을 고침** — 다시보기에서 스트리머가 결과 화면 대신 다른 게임 화면을 띄우면, 그 화면의 `4/9` 같은 글자만으로 결과(예: `9/10`, 나머지 빈칸)가 저장됐다. 순위 글자 외에 결과 문구·닉네임·스탯 중 하나가 함께 읽혀야 결과로 받는다.
- **1080p 결과 화면의 순위·총원을 못 읽던 것을 고침** — 결과 패널을 통째로 OCR 하면 `3/8`·`6/7` 이 깨져 총원이나 순위가 비었다(치지직 다시보기 13판 중 2판). 큰 순위 숫자와 `/총원` 을 따로 잘라 읽는다. 이미 분석한 게임은 "처음부터 다시" 또는 `tools/backfill_game_result.py` 로 다시 읽는다.
- **풀영상이 잘 재생되는데도 "재생하지 못했습니다(HEVC)" 경고가 뜨던 것을 고침** — 재생 버튼을 눌렀을 때 영상이 아직 불러와지는 중이라 재생 요청이 끊기기만 해도(H.264 영상이어도) 경고를 띄우고, 재생이 시작된 뒤에도 지우지 않았다. 끊긴 요청은 오류로 보지 않고, 재생이 시작되면 경고를 지운다. 문구도 HEVC 로 단정하지 않는다.
- **랭크 게임이 "일반"으로 저장되던 것을 고침** — 모드 칩 OCR 이 `{0` 같은 쓰레기 글자를 내면 "랭크"가 없으니 일반 게임으로 정했다. 한글이 없는 글자는 못 읽은 것으로 보고 다른 방식으로 다시 읽는다.
- **방송 다시보기에서 초상화·캐릭터 선택 화면을 못 찾던 것을 고침(1080p)** — 스트리머가 선택 화면 동안 왼쪽 위에 다른 게임 창을 띄우면 선택 화면을 알아보는 머리띠가 가려져, 그 게임은 초상화가 비고 풀영상이 게임 10초 앞부터 잘렸다(치지직 13판 중 8판). 아래쪽 팀원 카드 3장 밑의 팀 색 막대로도 선택 화면을 알아본다. 판독 캐시 버전이 올라 이미 분석한 영상은 "처음부터 다시" 분석해야 적용된다.
- **설정을 저장하는 순간 다른 동작이 실패하던 것을 고침** — 설정 파일을 비운 뒤 다시 쓰는 방식이라, 그 찰나에 다른 요청(영상 삭제 등)이 설정을 읽으면 빈 파일을 보고 오류로 실패했다. 임시 파일에 다 쓴 뒤 바꿔치기한다.
- **게임 행이 "클립 0개"로만 보여 헷갈리던 것을 고침** — 직접 보관 모드에서는 교전 후보가 여러 개 있어도 보관한 클립이 없으면 "클립 0개"였다. 이제 `후보 N · 보관 M` 으로 둘을 따로 보여 준다.
- **영상 파일 분석이 끝나도 새로고침 전까지 게임 목록이 비어 있던 것을 고침** — "분석 완료"로 바뀌었는데 게임 0개로 보였다. 분석 중이던 영상이 끝나는 순간 항상 게임 목록을 다시 읽는다.
- **결과 화면이 있는데도 "결과 미확인"이던 게임을 고침(영상 파일)** — 결과 화면 뒤 로비 그림이 낮/밤 아이콘으로 잘못 읽혀 게임 끝이 결과 화면 뒤로 늘어났고, 결과는 게임 끝 뒤에서 찾으므로 지나쳤다. 게임 끝을 확실한 인게임 신호가 마지막으로 읽힌 곳으로 잡는다. 이미 분석한 영상은 "다시 분석(캐시 재사용)"으로 적용된다.
- **게임 행 초상화를 원에서 카드 비율 직사각형으로 되돌림** — 새 게임 목록에서 초상화가 원으로 바뀌어, 가로로 긴 카드 그림의 좌우와 위 모서리가 잘려 얼굴이 잘려 보였다. 클립 탭 카드와 같은 직사각형으로 보여 준다.

- **보관한 클립이 일괄 삭제·다시 분석에 지워지지 않게 보호** — 사용자가 보관한 클립(`자동 보관` 이 아닌 카테고리, 저장 폴더를 안 정한 옛 경로 모드는 전부)은 클립 탭 삭제와 풀영상 화면의 보관 해제·클립 삭제 말고는 어떤 경로로도 지워지지 않는다. 게임 행 `⋯` 메뉴 `클립만 전체 삭제` 는 `자동 보관 클립 삭제` 로 이름이 바뀌어 `자동 보관` 클립만 지우고(없으면 꺼짐), `게임 전체 삭제`·영상 파일 탭의 `전체 삭제`·`목록에서 삭제`·게임 삭제도 보관한 클립은 클립 탭에 남긴다. 확인 창이 지워질 자동 보관 클립 수와 남는 보관 클립 수를 적는다. 옛 경로 모드의 영상 파일 다시 분석과 옛 카드 화면의 게임 다시 분석도 기존 클립을 지우지 않는다. ([spec/pipeline.md §9](spec/pipeline.md))
- **스팀 녹화·영상 파일 탭 사이를 오갈 때 풀영상이 뒤에서 계속 재생되고 단축키도 숨은 화면이 받던 것을 고침** — 탭을 바꾸면 그 탭의 영상이 멈추고 단축키는 보이는 화면만 받는다.

- [ ] 스팀 녹화·영상 파일 두 탭에서 게임 행을 눌러 풀영상 화면을 열면 소리와 함께 바로 재생되는지, 다시 분석이 끝나 화면이 새로 읽힐 때는 저절로 재생되지 않는지 확인 (HEVC 를 못 읽는 브라우저에서는 기존 안내 문구가 뜨는지도)
- [ ] 스팀 녹화 탭에서 게임 행을 열고 브라우저 뒤로 가기(Alt+←, 마우스 뒤로 버튼)를 눌러 목록으로 돌아오는지, 목록을 스크롤한 위치와 접어 둔 날짜가 그대로인지, `← 게임 목록` 버튼도 똑같이 동작하는지 확인 (영상 파일 탭도 `← 영상 목록` 으로)
- [ ] 클립 탭에서 카테고리를 여러 번 눌러 바꾼 뒤 뒤로 가기가 이전 카테고리로 가는지, 탭을 옮겼다 돌아와도 보던 카테고리·열어 둔 풀영상 화면이 유지되는지, 주소창의 주소를 복사해 새 탭에 붙여 넣으면 같은 화면이 열리는지(풀영상 화면은 자동 재생 없이 일시정지로), 지운 게임의 주소를 열면 목록으로 가는지 확인
- [ ] 클립 탭에서 클립을 재생하던 중 브라우저 뒤로 가기(또는 다른 탭 클릭)를 하면 소리가 바로 멈추는지, 클립 탭으로 돌아와도 재생 화면이 닫혀 있는지 확인
- [ ] 게임 행 `⋯` → `게임 정보 수정하기`로 순위·TK/K/A 를 고쳐 저장하면 행에 새 값이 뜨고, 그 게임의 클립 탭 카드 순위도 같이 바뀌는지, 그 게임을 `다시 분석`한 뒤에도 고친 값이 남는지, 대화상자에 `잠금 해제` 버튼이 없는지
- [ ] 코발트 게임의 `게임 정보 수정하기`에 순위 대신 승리/패배 선택이 뜨는지, 제목 칸(또는 행 초상화 옆 `✎`, 호버 `제목 편집`)에 제목을 적어 저장하면 게임 행 초상화 옆과 풀영상 화면 머리줄에 보이고 비워 저장하면 사라지는지, 영상 파일 탭 게임의 제목이 머리줄에 `스트리머 · 게임 N` 대신 보이는지
- [ ] 스팀 녹화 탭에서 게임 A 의 `다시 분석`(또는 `풀영상 만들기`)이 도는 중에 게임 B 의 `다시 분석`·`풀영상 만들기`를 연달아 눌러, B 행에 `대기 중 (1번째)` 배지와 `대기 취소` 가 뜨고 A 가 끝나면 B 가 저절로 시작되는지, `대기 취소` 를 누르면 줄에서 빠지는지, 확인 창이 두 줄("이 게임을 다시 분석합니다 … 몇 분 정도 소요")인지 확인
- [ ] 영상 파일 탭에서 영상 하나를 분석하는 중에 다른 영상의 `분석 시작`이 눌리고(막히지 않고) 그 영상 머리에 `대기 중 (1번째)`·`대기 취소` 가 뜨며, 앞 영상이 끝나면 이어서 분석되는지 확인
- [ ] 게임을 한 판 하는 동안(감시가 판을 처리하는 중) 대기 중인 다시 분석·영상 분석이 감시 처리가 끝나기 전에는 시작하지 않고, 감시가 만든 풀영상·클립이 평소처럼 나오는지 확인
- [ ] 스팀 녹화 탭에서 `보관`으로 둔 클립이 있고 자동 보관 클립도 있는 게임을 `다시 분석`하면 보관한 클립은 그대로(게임에서 보관됨으로 이어짐)이고 자동 보관 클립은 지워졌다가 새 후보로 다시 만들어지는지(클립 탭 `자동 보관` 카테고리에서 중복이 쌓이지 않는지) 확인. 원본 녹화가 지워진 게임이면 끝난 뒤 "원본 녹화가 없어 저장된 풀영상에서 클립만 다시 추출했습니다"가 뜨는지도 본다
- [ ] 영상 파일 탭에서 원본 영상을 지운 분석 완료 영상(풀영상은 남김)의 `다시 분석`을 눌러 버튼이 막히지 않고 "원본 영상이 없어 저장된 게임 풀영상에서 클립만 다시 추출합니다" 확인 창 → 끝난 뒤 같은 안내가 뜨고 보관한 클립은 그대로인지 확인. 원본이 있는 영상의 `다시 분석`이 보관한 클립을 지우지 않는지도 본다
- [ ] 클립을 `보관함`·다른 카테고리·`자동 보관` 에 섞어 둔 게임의 `⋯` → `자동 보관 클립 삭제` 확인 창이 "자동 보관 클립 N개를 삭제합니다. 보관한 클립 M개는 남습니다"로 뜨고, 삭제 뒤 `자동 보관` 클립만 사라지며 보관한 클립은 후보에 `보관됨` 그대로(`다시 저장` 이 뜨지 않음)·클립 탭에 남는지, `자동 보관` 클립이 하나도 없는 게임은 이 메뉴가 흐리게 꺼지는지 확인
- [ ] 같은 게임에서 `게임 전체 삭제` 확인 창이 "보관한 클립 M개는 클립 탭에 남습니다"를 적고, 삭제 뒤 행이 사라져도 보관한 클립이 클립 탭에서 보이고 재생·삭제되는지 확인(앱을 껐다 켜도 그 게임 행이 다시 나타나지 않는지도 본다)
- [ ] 영상 파일 탭 영상 머리의 `전체 삭제`·`목록에서 삭제` 확인 창이 지워질 자동 보관 클립과 남는 보관 클립을 적고, 지운 뒤 보관한 클립이 클립 탭에 남는지, 보관한 클립을 하나도 안 둔 영상은 지금처럼 클립이 모두 지워지는지 확인
- [ ] 게임·클립이 많이 쌓인 상태에서 영상 파일 탭·스팀 녹화 탭을 열고 새로고침을 눌러 목록이 1~2초 안에 뜨는지, 풀영상 화면을 열 때(후보에 `보관됨`·카테고리 표시)도 느려지지 않는지 확인
- [ ] 영상 파일 탭을 새로고침(F5)해 불러오는 동안 "게임 0개"·"이 영상에서 찾은 게임이 없습니다"가 한 번도 안 보이고 막대만 보이다가 목록이 한꺼번에 뜨는지, 풀영상 화면에서 후보를 보관한 뒤 브라우저 뒤로 가기로 돌아오면 그 게임 행의 `보관 M` 이 새로고침 없이 바뀌어 있는지(스팀 녹화 탭도 같게) 확인
- [ ] 스팀 녹화 탭 풀영상 화면에서 영상을 재생한 채 영상 파일 탭으로 옮기면 소리·재생이 멈추는지, 거기서 풀영상을 틀어도 하나만 재생되는지(반대 방향도), 그 상태에서 Space·S·D 가 보이는 화면에만 먹는지 확인
- [ ] 풀영상 화면에서 `Ctrl+←/→`(왼쪽·오른쪽 Ctrl 모두)·`N`/`P` 로 클립이 바뀌고, 현재 클립 시작 후 3초 안에 `P`/`Ctrl+←`/`이전 클립` 버튼을 누르면 바로 앞 클립으로, 그 뒤에 누르면 현재 클립 시작으로 가는지 확인
- [ ] 풀영상 화면에서 `무시한 후보도 보기`·`고정` 체크박스, 볼륨 슬라이더, 후보 행 버튼(보관·메모·클립 삭제 등)을 마우스로 누른 뒤에도 Space(재생)·←/→·`Ctrl+←/→` 가 바로 먹는지, 한글 자판 상태에서도 N·P·S·D·I·O·M 이 먹는지 확인
- [ ] 클립이 있는 후보를 선택하고 `Delete` → 확인 창에 `삭제` 가 포커스된 채 뜨고, ←/→ 로 `취소`/`삭제` 를 옮겨 Space·Enter 로 누르고 Esc 로 취소되는지, 확인 창의 "다시 확인하지 않기" 체크박스를 Space 로 켜지는지, 클립이 없는 후보에 `Delete` 는 `D` 처럼 무시되는지 확인
- [ ] `Ctrl+S` 가 브라우저 "페이지 저장" 창을 띄우지 않고(앱 창·일반 브라우저 모두) 선택한 후보의 보관 위치 팝업을 여는지, ↑/↓ 로 카테고리·`+ 새 카테고리` 를 옮기고 Enter 로 보관, Esc 로 닫히는지, 팝업이 떠 있는 동안 Space 가 영상을 재생하지 않는지 확인
- [ ] 보관한 후보를 선택하고 `M` 으로 메모 칸이 열려 바로 입력되고 `Ctrl+Enter` 로 저장하고 닫히는지(다시 열면 내용이 남아 있는지), 메모 입력 중에는 Space·N 등이 영상에 먹지 않는지 확인
- [ ] 풀영상 화면을 처음 열면 단축키 표가 펼쳐져 있고(닫으면 다음부터는 접힌 채), `?` 와 재생 막대의 `⌨` 버튼으로 열고 닫히며 표의 키가 실제 동작과 같은지 확인
- [ ] 풀영상 화면에서 범위 수정·무시·`+ 여기서 구간 추가` 를 한 뒤 `Ctrl+Z` 로 되돌리고 `Ctrl+Y`(또는 `다시 실행` 버튼)로 되살려 지는지, 되돌린 뒤 새 편집을 하면 `다시 실행` 이 꺼지는지, 추가한 구간을 되돌렸다 다시 실행해도 그 위 편집이 이어서 되돌려지는지 확인
- [ ] 보관한 클립의 범위를 고쳐 `다시 저장`(또는 `전부 저장`·Ctrl+S)을 누르면 저장이 끝날 때까지 머리줄에 `저장 중…` 이 깜빡이고 저장 버튼 글자도 `저장 중…` 으로 바뀌었다가, 끝나면 원래대로 돌아오는지 확인
- [ ] 풀영상 화면 후보 행의 `메모` 칸 아래 `저장` 버튼을 누르면 메모가 저장되고 칸이 닫히는지(다시 열면 내용이 남아 있는지, 저장 요청이 한 번만 가는지) 확인
- [ ] 보관한 클립의 범위를 고친(`수정됨 · 저장 대기`) 상태에서 `Ctrl+S` 를 누르면 먼저 클립에 저장("고친 범위를 보관한 클립에 저장했습니다")된 뒤 보관 위치 팝업이 뜨는지 확인
