## 1. 왜 만드나

- plan-deploy [§7-11](plan-deploy.md) "라벨·로그 수신처 — 서버를 둘지, 어떤 무료 수단을 쓸지" 의 답이다. 지금은 수신처가 없어서 D8 배포본이 첫 실행 화면의 전송 항목을 숨기고 진단 zip 으로만 받는다.
- 받으려는 것은 **여러 PC·환경에서 나온 라벨(교전/사냥 + 근거)과 오류 로그·환경 정보**다. 라벨은 여러 환경에서의 테스트 데이터로 쌓아 분류기 학습·가중치 튜닝에 쓴다([plan-deploy §5](plan-deploy.md)).
- 이 저장소 밖의 다른 서버도 같은 인프라에 올릴 예정이라 수신 서버 하나만을 위한 구성으로 만들지 않는다.
- 만드는 사람의 학습 목표(백엔드 취업 준비: IaC·컨테이너·DB·비정형 데이터 수집)도 범위에 포함한다. 그래서 "가장 쉬운 무료 수단"이 아니라 직접 구성하는 쪽을 택한다.

## 3. 이 저장소와 서버의 계약

수신 서버가 생겨도 이 앱의 핵심 기능(검출·클립·열람)은 네트워크 없이 동작해야 한다([SPEC §3](SPEC.md)). 서버 장애가 앱을 멈추게 하지 않는다.

- **보내는 것**: [SPEC §7.11](SPEC.md) 과 [plan-deploy §5](plan-deploy.md) 표 그대로 — 라벨(`telemetry.sendLabels`), 오류 로그·환경 정보(`telemetry.sendLogs`). 서버는 이 밖의 필드를 받지 않고 버린다.
- **식별**: `telemetry.installId`(무작위 UUID)만. 계정·닉네임과 연결하지 않는다. "보낸 데이터 삭제 요청"은 이 ID 로 서버에서 지운다.
- **전송 방식**: 앱이 하루 1회 묶음으로 보내고 실패하면 조용히 다음으로 미룬다(대기분 상한 예: 20MB — SPEC §7.11).
- **서버가 해야 할 것(수신 API 최소 범위)**: 수신·크기 상한·스키마 검증·`installId` 별 삭제. 조회·분석은 서버 밖(로컬 도구)에서 한다.
- **API 명세와 버전**은 서버 저장소가 정한다. 이 저장소는 D10 구현 때 [plan-deploy.md](plan-deploy.md) 에 확정한 계약을 링크한다.

## 4. 저장 계층: 파일 → DB

**1단계 — 파일.** 수신한 라벨과 로그를 파일로 저장한다(라벨은 건당 JSON, 로그는 줄 단위 JSON). 서버·API·도커 구성을 먼저 굴려 보는 것이 목적이다.

**2단계 — DB.** 파일에 쌓인 데이터를 DB 로 옮긴다. 옮기려는 이유는 (1) 여러 환경의 라벨을 조건(해상도·버전·라벨 값)으로 골라 학습·평가에 쓰기 위해서, (2) 비정형 로그를 검색·집계하기 위해서, (3) DB 운용 경험을 쌓기 위해서다.

**DB 종류는 정하지 않는다.** 정할 때의 비교 기준만 적어 둔다.

- 라벨은 필드가 정해진 정형 + 근거(`pvpSignals` 등) 는 형태가 바뀌는 반정형 → 한 DB 안에서 둘 다 다룰 수 있는지
- 로그처럼 양이 늘고 잘 수정되지 않는 데이터를 어떻게 쌓고 지울지(보관 기간·삭제 요청 대응)
- OCI 무료 한도 안에서 운용 가능한지, 도커 한 대에 같이 올려도 되는지
- 후보 예: PostgreSQL(JSONB), MongoDB 등. **후보로만 적으며 배제·확정하지 않았다.**

## 5. Claude Code 와 연동되는 MCP

"연동되는 MCP 가 있나"에 대한 조사 결과(2026-09-24 웹 검색). 이 프로젝트에 설치·연결하지는 않았고 실측하지 않았다.

- **[HashiCorp Terraform MCP Server](https://github.com/hashicorp/terraform-mcp-server)** — 공식. Terraform 레지스트리의 프로바이더·모듈 문서를 조회하고, HCP Terraform / Terraform Enterprise 워크스페이스를 다루는 기능이 있다. **HCP Terraform 없이 로컬 `terraform apply` 를 대신 실행해 주는 도구인지는 확인하지 못했다** — 코드 작성 때 최신 OCI 프로바이더 문서를 정확히 참조하는 용도로 유용할 것으로 본다.
- **OCI 용**: Oracle 공식 저장소 [oracle/mcp](https://github.com/oracle/mcp) 는 **참고·학습용 구현이며 프로덕션 용도가 아니라고 명시**돼 있고 내용도 OCI IoT, SQLcl/Database Tools 등 특정 서비스용이다. 그 밖에 [dockndevai/mcp-oci](https://github.com/dockndevai/mcp-oci)(리소스 탐색·Terraform 생성 표방) 같은 **비공식** OCI MCP 서버가 여럿 있다. 계정 자격 증명을 다루므로 비공식 서버를 쓰기 전에 코드를 읽어 보고 읽기 전용 권한 키로 시험한다.
- 권장: 처음에는 MCP 없이 Terraform CLI 로 진행하고, 필요해지면 위 공식 Terraform MCP 부터 붙인다.

## 6. 확인 필요 (추측으로 메우지 않은 것)

1. **OCI 무료 한도와 가용성** — 계정 상태(리전·무료 등급)에서 어떤 인스턴스·스토리지·DB 를 무료로 쓸 수 있는지 아직 확인하지 않았다. 리전에 따라 인스턴스 용량이 부족할 수 있는지도 실제로 만들어 보고 정한다.
2. **Terraform 상태 파일 저장 위치** — 로컬 파일 vs OCI Object Storage 등 원격 백엔드. 자격 증명·상태 파일을 저장소에 넣지 않는 방식(`.gitignore`, 변수 파일 분리)을 별도 저장소를 만들 때 정한다.
3. **수신 서버 언어·프레임워크** — 정하지 않았다(취업 준비 목적이면 사용자가 익히려는 스택을 우선한다).
4. **수신 API 인증 방식** — 익명 `installId` 만으로 받으면 남용 방지가 필요하다. 요청 크기·빈도 제한과 간단한 토큰 여부를 정한다.
5. **개인정보 처리 안내·삭제 요청 방법·보관 기간** — plan-deploy §5 "D10 구현 시 정할 것" 과 같은 항목이다. 서버를 만들기 전에 정한다(국내 이용자 대상이면 개인정보 보호법).
6. **호스팅 공유(클립 공유 서버)와의 관계** — SPEC §6 "호스팅 공유" 는 영상 전달이 필요해 이 수신 서버(영상 안 받음)와 성격이 다르다. 같은 인프라를 쓰되 서비스는 분리하는 것으로 가정하며 확정하지 않았다.
7. **서버 비용·트래픽 상한** — 무료 한도를 넘었을 때 과금 알림·자동 중단 방법.
8. **DB 종류** — [§4](#4-저장-계층-파일--db) 참고. 정하지 않았다.
