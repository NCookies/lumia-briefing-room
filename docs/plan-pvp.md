## 1. 순서를 지켜야 하는 이유

**앞 단계가 뒤 단계의 정답 라벨을 만들어준다.**

확정 증거(K/A, 내 사망, 팀원 사망)로 판정된 구간이 곧 "이건 확실히 PvP"라는 라벨이다.
그 라벨이 있어야 추정 증거(미니맵)의 임계를 **추측이 아니라 실측으로** 정할 수 있다.
라벨 없이 미니맵부터 건드리면 잘 되는지 판단할 기준 자체가 없다.

그래서 0단계가 최우선이다. 지금은 확정 증거 중 가장 강한 것이 꺼져 있어 라벨이 거의 없다.

## 2. 단계별 설계

### 2.0 `K`/`A` 템플릿 자동 탑재 ← 최우선

**문제.** `cli/watch.py::run()` 이 `args.k_templates` 가 있을 때만 `load_templates()` 를 부른다.
`run.bat` 도 `cli/app.py` 도 그걸 안 넘긴다. 그래서 실사용 클립 60개가 전부 `killDelta=0` 이었다.
**조용히 꺼지는 게 특히 나쁘다** — 로그에 아무 말이 없어서 몇 주를 모르고 지나쳤다.

**고칠 것.**

```python
# config.py — ffmpeg / 녹화 경로 자동 탐지와 같은 방식
def discover_digit_templates(width: int, height: int) -> Path | None:
    """data/templates/digits/<W>x<H>.npz 를 찾는다. 없으면 None."""
```

- 해상도 프로필이 이미 있으니(`profiles/`) 그 해상도로 파일명을 만들어 찾는다.
- **못 찾으면 경고를 남긴다.** `log.warning("숫자 템플릿을 찾을 수 없다 - kill/assist 태그가 비어서 나온다")`
- `--k-templates` 는 그대로 두되, 안 주면 자동 탐색이 기본이 된다.

**✅ 완료.** `detect/match.py::resolve_templates()` 가 해상도 프로필의 템플릿을 자동으로 싣고, 없으면 경고를 남긴다.
`--k-templates` 는 그대로 동작한다(명시하면 그게 우선).

실제 녹화 프레임으로 검증하다 **별개의 버그를 하나 더 찾았다.** `a_value` ROI 가 35px 인데 템플릿은 36px 이라
슬라이딩 자체가 성립하지 않아 **`A` 는 애초에 한 번도 읽힌 적이 없었다.** ROI 를 36px 로 맞추고
(`2513..2549`), 프로필 ROI 폭과 템플릿 폭이 같아야 한다는 회귀 테스트를 추가했다.
실측: 사망 클립 프레임 4개에서 `A=2`, 다른 클립에서 `A=4` — 결과 화면의 `A 4` 와 일치. `K` 는 `4`/`3` 을 정확히 읽었다.

`A` 는 `K` 와 같은 글꼴이라 **같은 숫자 템플릿을 공유**한다.

⚠ **(해소됨: 조합 본보기 `with_two_digit_templates`, plan-vod §4-1)** 템플릿이 ROI 전체 폭(36px)이라 **두 자릿수(`10` 이상)는 읽지 못하고 `None` 을 냈다**
(오판이 아니라 보수적 실패). 킬 10 이상은 드물지만 어시스트는 넘을 수 있다. 문제가 되면 자릿수별 슬라이딩으로 확장한다.

**재처리.** 이미 만들어진 클립 60개는 원본이 아직 링버퍼에 남아있는 것만 재처리 가능하다.
`cli/process_match.py` 로 매치 단위 재실행이 되므로 별도 도구는 필요 없다.
남아있지 않은 건 포기한다 — 라벨은 앞으로 쌓이는 것으로도 충분하다.

### 2.1 개인 사망 = 관전 UI 전환

**지금 `death` 태그는 개인 사망이 아니라 팀 전멸을 잡고 있을 가능성이 높다** (SPEC §2.12 5-0).
개인 사망은 매치당 여러 번 일어나고 **확정 PvP 증거**인데 비어 있다.

**신호.** 사망 후 캐릭터 UI가 통째로 사라진다. 초상화·스킬바·팀 패널·미니맵 헤더 ROI가 전부 0이 된다.
"신호가 약해지는" 게 아니라 "ROI가 비는" 상태라 판정이 쉽다.

```python
# detect/spectator.py
def is_spectating(frame) -> bool:
    """캐릭터 UI ROI 들이 동시에 비었는지. 암전과 구분하려면 미니맵도 같이 본다."""
```

- ⚠ **암전과 구분해야 한다.** 사망 직후 수 초는 화면 전체가 어둡다(밝기 50 → 5).
  그 구간은 관전이 아니라 전환 중이다. **미니맵이 살아있으면서 캐릭터 UI만 없을 때**가 관전이다.
- 초상화 빨강(0% → 71.5%)은 그 직전 국면이라 **사망 시점을 집는 데** 쓴다.

**관전 구간 제외가 이 작업의 절반이다.** 관전 화면은 **팀원 시점**이라,
그 구간의 미니맵·지역명·배지를 내 것으로 읽으면 전부 오판이 된다.
`detect/match.py` 가 프레임을 훑을 때 관전 구간을 통째로 건너뛰게 한다.

**✅ 완료.** `detect/spectator.py` — 관전 = **미니맵 헤더 아이콘 보임 ∧ 하단 띠에 내 체력바(초록) 없음.**
미니맵도 없으면(암전·로비·결과 화면) 판정하지 않고 `None`. 프로필에 `minimap_icons`, `hp_strip` ROI 를 추가했다.

- `analyze_frame()`: 관전이면 배지·초상화 판독을 버린다(팀원 시점을 내 것으로 읽는 오판 방지).
- `finalize_match()`: **2샘플 이상 연속**이어야 관전 구간으로 인정(암전 진입 순간의 1샘플을 거른다).
  관전 샘플은 교전으로 치지 않아 구간이 관전 시작에서 끊긴다. 교전 종료 후 8초 안에 관전이 시작되면 `died`/`death` 태그.
  `MatchDetection.spectator_ranges` 에 구간을 남겨 이후 단계(미니맵·지역명)가 그 구간을 건너뛸 수 있게 했다.

**실측.** 사망 클립 60프레임(1fps)에서 `.`(생존) 43 → `SSSS` 4 → `?`(암전·결과) 13 으로 갈렸다.
사용자 스크린샷으로도 확인: 관전 화면 → `spectating=True, combat=None`, 생존 대치 화면 → `False, combat=True`.

⚠ **관전 화면 영상 표본이 없다.** 내 클립은 전부 팀 전멸 → 결과 화면이라 팀원이 살아있는 개인 사망 영상이 없다.
검증은 사용자 스크린샷 1장 + 사망 직후 4프레임뿐이다. 스크린샷은 창 테두리 때문에 절대 좌표가 어긋나
(생존 스샷의 HP 좁은 ROI 가 0%) **좁은 ROI 가 아닌 넓은 띠 영역**(`860,1300,1300,1440`)을 쓴 이유다.
새 매치가 쌓이면 개인 사망 클립으로 다시 검증한다.

### 2.2 팀원 사망

**신호: 팀 슬롯 체력바 색.** 초록 = 생존, **주황 = 사망(리스폰 대기)**. 슬롯이 고정이라 누가 죽었는지도 나온다.

```python
# detect/teammate.py
def slot_is_dead(bar_rgb) -> bool:   # 주황 >= 2% AND 초록 < 0.5%
def dead_slots(bars) -> list[int]
def new_deaths(series) -> list[(t, slot)]   # 살아있다가 죽은 순간만
```

- 구간 내에서 **살아있다 → 죽은 순간**만 사건으로 센다. 첫 샘플에 이미 죽어 있던 슬롯은 이 구간의 사건이 아니다.
- 미니맵이 안 보이는 샘플(암전·로비)은 판정하지 않고 건너뛴다.
- 교전 구간의 앞뒤 8초 안에 팀원 사망이 있으면 `teammate_death` 태그가 붙고 `no_result` 는 붙지 않는다.
- ROI 는 프로필의 `team_bar1`, `team_bar2` (`2112,1228,2170,1244` / `2112,1365,2170,1381`).

**✅ 완료. 그런데 처음 방식이 틀려서 두 번 갈아엎었다.** 기록해둔다.

1. **초상화 슬롯 전체 빨강 비율 (실패).** 사망 클립에서 0% → 7~12% 로 튀는 걸 보고 "슬롯 1은 17초, 슬롯 2는 37초에 죽었다"고
   SPEC 에 적었는데, **슬롯 1은 사망이 아니라 전투 중 빨간 링/아이콘이었다.** 실제로 죽은 건 슬롯 2 하나.
2. **초상화 원판 빨강 (실패).** 전체 클립을 재보니 절반 이상에서 오탐 — **팀원 링은 전투 중이면 빨갛다**(내 배지와 같은 원리).
   링을 빼고 얼굴 안쪽만 봐도 생존 최대 0.6% vs 사망 12~18% 로 갈리긴 했으나, 빨간 머리 캐릭터(`124925_07` 슬롯 2 = 72%)에서 깨진다.
3. **체력바 색 (채택).** 그림과 무관하다. 생존 클립 24샘플×2슬롯에서 주황 0건, 눈으로 사망을 확인한 슬롯 4개 전부 주황 검출.

실측 시리즈(사망 클립): 슬롯 2 가 f_038~043 에서 검출(`. . . 1 1 1 1 1 1 . .`), 생존 클립은 전 구간 `.`.

⚠ **한계.** 표본이 사망 슬롯 4개뿐이다. 체력이 낮아 **주황+초록이 섞인 바**를 사망으로 오판하지 않도록 "초록 없음"을 조건에 넣었으나,
그런 프레임의 표본은 없다. 리스폰 직후(부활 중) 바 색이 어떻게 변하는지도 미확인.

### 2.3 지역명 판독

미니맵 헤더의 지역명 텍스트를 읽는다. 지도 분석도 모양 학습도 필요 없다.

```python
# detect/region.py
def region_score(rgb) -> ndarray              # 밝기만 본다. 색 무관
def build_region_template(samples) -> ndarray
def read_region(score, templates) -> RegionRead(name|None, confidence)
```

- ROI: 프로필의 `region_text` = `2210,1080,2330,1114` (120×34). 글자는 왼쪽 정렬이고 가장 긴 이름(`전투 연구실`)이 ~85px.
- **색을 보지 않는다.** 글자색이 **흰색 / 빨강(금지구역) / 주황(예정)** 세 가지로 실제로 바뀐다(K/A 의 무채도 항을 뺀 이유).
- **ROI 폭 전체를 비교한다.** 템플릿 폭만 비교하면 접두어가 같은 다른 이름을 오인한다.
  0 패딩 템플릿의 상관계수가 x 와 무관한 통계라 `cv2.matchTemplate` 한 번으로 닫힌 형태로 풀었다(런타임 판독 속도).
- 교전 구간의 **첫 판독값**을 지역으로 쓴다(SPEC §2.10 "교전 시작 시점"). 관전 중에는 읽지 않는다 — 팀원 시점의 지도다.

### 2.3-b 일차 판독 — 제목에 `4일차 낮`

```python
# detect/day.py

```

- ROI: 프로필의 `day_digit` = `1129,6,1144,32` — `N일 차` 의 **숫자 한 글자만**. `일 차` 가 매일 공통이라 낱말 전체를 비교하면 숫자 차이가 묻힌다.
- 구간의 **최빈값**이 그 클립의 일차. 메타데이터 `gameDay` → `phaseIndex`(=(일차-1)×2 + 낮0/밤1), `reviveCost` 도 함께 채워진다.
- 제목: `4일차 낮 묘지 교전`. 템플릿: `data/templates/days/2560x1440.npz` (1~8).
- **이미 만든 클립은 `tools/backfill_day.py`** — 클립 영상 자체의 HUD 에서 읽어 재처리 없이 채운다(사용자 라벨·직접 바꾼 제목은 보존, 쓰기 직전에 다시 읽어 경쟁 상태 방지, 키프레임만 디코딩해 59개에 47초).

**✅ 완료. 그런데 처음 결과가 틀렸고, 원인이 배경색이었다.** 기록해둔다.

1. `max` 채널 점수(지역명과 같은 방식)로 만들었더니 **`6일차`와 `7일차`가 뒤바뀌어 읽혔다**(`5→7→7→6` 로 나옴, 실제는 `5→6→6→7`). 화면을 열어보고 발견했다.
   원인: **진한 빨강 배경**(6~8일차 후반)이 `max` 채널로는 글자처럼 밝아서, 군집도 템플릿도 **숫자가 아니라 배경색**을 학습했다.
2. 일차 글자는 **항상 흰색/크림색**이라 `min` 채널(모든 채널이 밝아야 글자)로 바꿨다. 빨강·주황 배경은 0 이 된다.
   (지역명은 글자색이 흰/빨강/주황으로 바뀌어서 `max` 가 맞다 — 텍스트마다 점수 함수를 다르게 골라야 한다.)
3. 군집 임계도 0.8 → 0.96 으로 올렸다. 3/8, 5/6, 6/8 은 모양이 비슷해 낮은 임계에서 섞였다(지역명 때와 같은 함정).
   군집 대표를 눈으로 확인해 이름을 붙이고, **`8일차`가 존재한다는 것**도 이때 알았다.

**정확도.** 508개 크롭에서 정답 508 / 오답 0 / 모름 0. 자기일관성이라 새 매치에서 다시 잴 것.
59개 클립 전부 일차가 읽혔고, **매치 8개 모두 일차·낮밤이 시간 순서대로 단조 증가**했다(독립적인 정합성 확인).
전체 프레임 실측: `death_36s` 는 화면에서 확인한 `4일 차` 와 일치.

⚠ **한계.** 템플릿에 없는 숫자는 대체로 `None` 이지만 **`8` 을 빼고 읽혔더니 `6` 으로 읽혔다**(5/5).
9일차 이상은 오독할 수 있다 — 그런 매치가 나오면 라벨셋에 추가한다. 두 자릿수(`10일 차`)는 ROI 폭상 읽지 못한다.

### 2.7 팀 전투 상태 — 내 배지가 꺼진 교전을 잇는다

**발견.** 사용자가 "교전이 잘린다"고 준 피드백(`1일차 낮 묘지 교전`, 141초)을 원본으로 열어보니 클립이 잘린 게 아니라 **배지가 진짜 교전을 놓치고 있었다.**
클립은 3148초에 끝났는데 그 뒤 3150~3180초에 스킬 이펙트가 터지는 교전이 계속됐고(끝에 사망), 그동안 좌하단 배지는 **검(✕)이 사라진 평범한 노란 레벨 숫자**였다.
배지는 "내가 방금 치거나 맞았다"일 뿐이라 구도를 잡거나 거리를 벌리는 동안 꺼진다 — 사용자가 말한 "본격 교전 전의 구도 잡기"가 안 잡히는 이유다.
같은 시간대 **팀원 슬롯은 초상화 둘레가 빨간 링 + 주황 ✕ 배지**였다.


- ROI: 프로필의 `team_ring1/2` = `2100,1165,2180,1225` / `2100,1302,2180,1362`.
- `finalize_match(use_team_combat=True)` 가 **내 배지 OR 팀원 전투**를 교전 신호로 쓴다. 관전 중엔 무조건 꺼짐. 팀 상태를 못 읽은 샘플(암전)은 배지 판독을 가리지 않는다.

**실측 A/B (실제 8매치, 같은 프레임 판독으로 두 방식 비교).**

| | 배지만 | 배지 OR 팀 전투 |
|---|---|---|
| 교전 구간 | 106 | 110 |
| **증거가 있는 구간** | 36 | **44 (+22%)** |
| 증거 없는 구간 | 70 | 66 |

놓쳤던 12:49 매치는 `(3114~3138) + (3186~3195)` 두 조각이 **`3114~3195` 하나**가 되었고 그 안에서 `kill` 까지 새로 검출됐다.
라벨과 대조: 교전으로 라벨한 클립 중 증거가 걸리는 것 28/36 → 29/36 (**정확히 그 141초 클립 복구**), 사냥 라벨 클립 2개에 새로 증거가 붙었으나
확인해보니 오탐이 아니라 **옛 경계가 어긋나 있던 것**이다: 하나는 팀원 사망 직후의 뒷정리가 교전과 한 구간이 됐고, 다른 하나는 옛 구간이 교전 도입부에서 끊겨 그 뒤의 어시스트를 놓치고 있었다.

**대가.** 구간이 길어진다(+25%) — 교전 직후의 사냥이 교전에 붙는다. 사용자 기준("교전 앞뒤 구도 잡기·뒷정리도 교전 내용")과는 맞지만 혼합 클립이 늘 수 있다.

**새 경계로 재처리하고 라벨을 이관해 다시 잰 결과 (2026-09-21).** 옛 경계에 붙은 라벨로는 팀 전투의 효과를 공정하게 못 재서(옛 경계가 어긋난 걸 오탐으로 셌다),
`tools/migrate_labels.py` 로 옛 라벨을 시간이 겹치는 새 클립에 옮긴 뒤 같은 지표로 비교했다.

| 클립 / 라벨된 클립 | 59 / 57 | 64 / 52 |

- 표본이 작다(교전 33, 증거 없는 교전 5). 미니맵 가중치를 빼는 결정은 같은 라벨로 했으므로 약간 유리하게 나온다.

### 2.8 신규 후보 신호 — 궁극기·활성 효과 개수 (2026-09-22 제안, 미검증)

§3-4("이겼지만 킬이 없는 교전", 라벨의 22%)와 증거 없는 교전 5개를 메우기 위해 사용자가 제안한 신호 셋. 상세 근거는 [SPEC §2.12 #9~#11](SPEC.md).
아직 ROI 실측도, 라벨 대조도 안 했다 — **순서는 §2.4-b(미니맵)·§5-3(네임플레이트)와 동일하게 "실측 → 라벨 대조 → AUC 확인 → 채택/기각" 을 따른다.**

#### 2.8-a 활성 효과 아이콘 개수 — 먼저 검증할 것

가장 범용적이다(캐릭터·특성 식별 불필요). 우선순위 1순위.

```python
# detect/effects.py (가칭)
def count_effect_icons(row_rgb) -> int
    """스킬바 위 버프/디버프 줄에서 뚜렷한 아이콘 경계 개수만 센다. 아이콘 종류는 구분하지 않는다."""
```

- **먼저 할 일**: ROI 실측 (좌표는 실제 녹화 프레임에서 재야 한다 — 스크린샷은 창 크롭이라 좌표를 그대로 못 쓴다, §2.1 의 교훈과 동일).
- **1차 육안 확인 (2026-09-22).** 예상과 달리 **스킬바 위가 아니라 화면 최상단 중앙, "날씨"(해·바람) 박스 왼쪽**에 아이콘이 하나씩 이어 붙는 줄이었다. 날씨 박스 왼쪽 변(대략 `x 970`, `y 20..70`, 2560x1440 기준)이 고정 기준점, 왼쪽으로 아이콘당 ~80px씩 늘어난다(정밀 측정 전 눈대중 값 — `resolve_templates()` 류로 정식 실측 필요).
- **주의 — 실측으로 이미 걸렸다.** `tools/eval_pvp.py` 로 교전/사냥 분포를 잴 때 **"사냥" 라벨을 이동 위주/전투 위주로 나눠서라도 따로 봐야 한다.** 라벨된 사냥 클립(`20260920_134809_03.mp4`, 실제로는 멧돼지와 전투 중)의 8초 시점에 벌써 아이콘 3개가 떠 있었다 — 같은 세션 킬 클립(`20260920_134809_01.mp4`)의 교전 시작 시점(0개)보다 많고 170초 지난 시점(2개)과 비슷하거나 더 많다. 안 나누면 §2.4-b(미니맵)처럼 "겹쳐서 못 가른다"는 결론이 나올 위험이 실측으로 확인됐다(SPEC §2.12 #10 참고). 나누는 방법은 사용자가 다시 라벨링하거나, 클립 안에서 HP 변화·스킬 사용 여부 등 다른 신호로 사후에 나누는 것도 가능.

#### 2.8-b 궁극기(R) 사용

```python
# detect/ultimate.py (가칭)
def r_cooldown_entered(prev_frame, frame) -> int | None
    """R 아이콘이 활성 -> 쿨타임(회색조 + 숫자)으로 바뀐 프레임에서 쿨타임 초기값을 읽는다. 안 바뀌었으면 None."""
```

- 숫자 판독은 K/A·일차 숫자와 같은 글자 매칭 기법 재사용 (`detect/match.py`).
- **가중치는 이진(궁 사용 여부)이 아니라 "읽힌 쿨타임 값"에 거는 안을 우선 검토한다** — 쿨타임이 길수록(예: ≥15초) 가중치를 높인다. 짧은 캐릭터를 위한 별도 예외 처리(캐릭터별 표)는 만들지 않는다 — 그 자체가 §2.10 이 미룬 캐릭터 식별 작업이라 비용이 크다.
- ROI 미측정. `R` 칸만 자른 좌표가 필요하다 (스킬바 전체 ROI `880,1290,1300,1365` 안의 일부).
- **1차 육안 확인 (2026-09-22).** 대략 `x 1110..1170, y 1290..1360` 부근(눈대중, 정밀 측정 전). **준비 상태는 원래 색, 쿨타임 상태는 파르스름한 반투명 오버레이 + 흰 숫자**로 뚜렷이 갈렸다. `20260920_134809_01.mp4`(pvp, kill)에서 5초 시점엔 준비 상태, 60초 시점엔 `37`(궁을 썼다는 뜻)이었다. 같은 방식으로 확인한 `20260920_134809_03.mp4`(pve, 멧돼지 전투)는 8초 시점까지 계속 준비 상태(안 씀).

- **★ 라벨 110개로 검증 완료 (2026-09-22).** `scripts/probe/ultimate_skill.py`(R 칸 파란기 비율 판독) + `scripts/probe/eval_ultimate_signal.py`(라벨 대조 배치)로 확인했다.
  - **1차 시도(전역 고정 임계 0.10)는 가짜 신호였다.** AUC 0.894 로 나왔지만, 캐릭터마다 `R` 아이콘 원화 자체의 파란기 베이스라인이 달라 궁을 안 써도 항상 ~0.25 근방이 나오는 캐릭터가 있었다 — 같은 세션의 사냥 클립 여러 개가 거의 똑같은 값을 반복해서 낸 게 단서였다. 절대 임계는 캐릭터 아이콘 원화 색에 오염된다.
  - **고쳐서 클립 자체의 최솟값을 그 클립의 "준비" 기준선으로 잡고, 최댓값과의 차이(delta ≥ 0.15)로 재계산**하니 훨씬 견고해졌다: pvp 73개 중 66개(90%) 검출, pve 37개 중 10개(27%) 검출, **AUC(delta) = 0.914**.
  - 미니맵(§2.4-b, AUC 0.53)·네임플레이트(§5-3, AUC 0.62)보다 훨씬 강하고, 확정 증거(킬/어시 1.0) 다음가는 수준이다. §3-4("이겼지만 킬이 없는 교전")를 메울 유력한 후보다.
  - 놓친 pvp(10%)는 킬/사망 태그가 있어도 실제로 궁을 안 쓴 경우로 보인다(`20260921_163314_05` 는 kill 태그인데 delta 0.000). 걸린 pve(27%)는 실제 보스·야생동물 전투에서 궁을 쓴 경우이거나 `teammate_death` 처럼 애매한 클립이 섞여 있다.
  - **아직 안 한 것**: ROI 정밀 측정, `filter.pvpWeights` 실배선(가중치 결정 + `detect/pvp.py` 반영 + TDD), R 쿨타임 숫자 자체를 읽어 "얼마나 긴 궁인지"로 가중치를 세분화하는 것(§2.8-b 원안).

#### 2.8-c 캐릭터별 발동 특성 — 후순위

캐릭터 식별이 전제되므로 §2.8-a/b 보다 비용이 훨씬 크다. 2.8-a 가 범용 신호로 채택된 뒤, 사용자가 자주 쓰는 캐릭터(마르티나 등) 한둘에 한해 보조 신호로 얹는 것을 검토한다. 전체 캐릭터 커버는 목표로 하지 않는다.

#### 검증 절차 (2.8-a/b 공통)

1. ROI 를 실제 녹화 프레임에서 실측한다 (해상도 프로필에 새 ROI 추가).
2. `tools/eval_pvp.py` 에 신호를 추가해 라벨 57개+ 로 분포·AUC 를 잰다. §2.8-a 는 위 사냥 라벨 혼입 주의사항을 반영해 나눠서도 본다.
3. 갈리면(AUC 가 미니맵의 0.53 보다 뚜렷이 높으면) `filter.pvpWeights` 에 추가하고 `rescore_clips.py` 로 재적용. 안 갈리면 §2.4-b 처럼 값만 기록하고 가중치 0.

## 3. 확인 필요

### 3-0. `131701_01` — 대기방인데 사용자가 교전으로 라벨했다 (2026-09-21)

`20260920_131701_01` (1일차 낮 브리핑 룸)은 구간 전체가 `브리핑 룸` 프레임인데 **사용자가 직접 `교전` 으로 찍었다**(`labelSource: user`). 대기방에서는 교전이 불가능하다는 설명과 어긋난다.
- 프레임을 보면 내 배지는 한 번도 안 켜졌고 팀원 전투 링만 켜져 있다가, 구간이 끝난 직후 지역이 `바지선` 으로 바뀐다 — **대기방 직후 실제 게임 시작 장면이 클립 뒤쪽에 붙어 있을 가능성**이 있다.
- 사용자가 이 클립을 다시 보고 라벨을 확정해야 한다. **교전이 맞다면 브리핑 룸 제외 규칙도 "구간 전체가 대기방일 때만" 으로 좁혀야 한다.**
- 참고로 같은 대기방 클립 `133645_01` 은 `사냥` 라벨(이관됨)이고, 그 안에서 내 배지가 여러 번 켜졌다 — **대기방에서도 전투 배지는 켜진다**(연습용 타격?). 배지가 교전의 근거가 못 된다는 §1의 사례가 하나 더 늘었다.

### 3-1. BREAK 회색 화면 — 보류

제보: 1일차에 전멸당하면(BREAK) 회색 화면 + 중앙에 흰 숫자로 부활 카운트다운이 뜬다. 여러 번 가능.

**클립 60개를 전부 훑었으나 찾지 못했다** (채도 < 16 이면서 암전은 아닌 프레임 = 0건).
추정 원인 둘: ① 클립이 교전 구간 ±preroll/postroll 만 잘라서 **BREAK 화면이 범위 밖**이다,
② 회색 화면에 색 있는 UI 가 남아 채도 임계에 안 걸렸다.

언제 당했는지 기억에 없어 원본에서 찾기도 어렵다. **보류.**
팀 전멸은 회색화·전멸 배너로도 잡히므로 막히는 항목은 아니다.

### 3-2. 회색화가 정말 팀 전멸에서만 뜨는가

§2.1 의 전제다. 제보는 있으나 실측 전이다. 개인 사망을 관전 UI 로 잡기 시작하면
둘이 따로 노는지 자연히 드러난다 — 그때 확인한다.

### 3-3. 전멸 배너 — 후순위

ROI 미측정(배너가 찍힌 프레임을 못 찾음), 내 팀 전과일 때만 뜨는지도 미확인.
다른 확정 증거와 상당 부분 겹쳐서 급하지 않다.
쓰게 된다면 배너 단독이 아니라 **`배너 ∧ 내가 교전 중`** 으로 본다 — 남의 싸움이면 나는 교전 중이 아니다.

### 3-4. "이겼지만 킬이 없는" 교전 — 가장 어려운 하위 케이스 (라벨로 확인: 교전의 22%)

아군이 아무도 안 죽고, 체력도 거의 안 닳고, 킬도 없이 이긴 경우(적이 도망가는 등).
**확정 증거가 전부 없고 HP 급락 같은 보조 신호도 못 쓴다.** 남는 건 미니맵 적 링뿐이다.
적과 붙어 있었을 테니 미니맵에 계속 잡혔을 가능성이 높아 오히려 유리할 수 있다.

미니맵이 안 갈리면 다음 후보는 **적 네임플레이트**다: 플레이어는 머리 위에 `레벨 상자 + 이름 + 체력바`가 뜨고 야생동물에는 이름표가 없다.
의미상 가장 확실한 구분선이지만 위치가 고정이 아니라 화면 전체를 뒤져야 한다(교전은 화면 중앙 근처에서 벌어지니 범위를 좁힐 수 있다).

점수가 낮아도 클립은 만들어진다 — 판별에 실패해도 영구히 놓치는 게 아니라 목록에서 밀릴 뿐이고, 가중치를 고치면 `rescore_clips.py` 로 다시 적용된다.

## 4. 다음 — 라벨로 튜닝하기

### 4-0. 라벨링 기준 — "이 클립에 사람과의 교전이 **포함**되어 있는가"

목적이 **볼 만한 교전을 놓치지 않는 것**이므로, 클립 전체가 교전일 필요는 없다. 포함 여부로 찍는다.

| 상황 | 라벨 |
|---|---|
| 사냥 하다가 **플레이어와 교전** (사냥이 앞뒤에 섞여 있어도) | **교전** |
| 교전 **이후** 야생동물·오브젝트(알파/오메가/위클라인)를 잡음 | **교전** |
| 야생동물·보스·오브젝트만 상대함 | **사냥** |
| 보스를 잡는데 **다른 팀이 끼어들어** 싸움 | **교전** |
| 다른 팀이 보이기만 하고 **싸우지 않음** | **사냥** |
| 판단이 안 되는 것 | **안 찍고 넘어간다** (다시 보고 싶으면 `0`) |

- **일관성이 정확성보다 중요하다.** 애매한 것을 억지로 찍으면 노이즈가 된다. 넘어가는 편이 낫다.
- **혼합 클립이 많다는 것 자체가 신호다.** 클립이 교전과 사냥을 한꺼번에 담을 만큼 길다는 뜻이라, 라벨링을 마친 뒤
  혼합이 체감상 많았다면 알려줄 것 — 세 번째 라벨(`혼합`)이나 클립을 증거 시점에서 나누는 개선이 필요하다는 근거다.
- 평가 도구(`eval_pvp.py`)는 혼합 클립을 `교전`으로 센다. 혼합 클립은 구간 평균 적 링이 희석되므로 미니맵 분포가 실제보다 겹쳐 보일 수 있다.

### 4-1. 절차

1. UI 에서 클립에 **교전 / 사냥** 을 찍는다 (`1` / `2`, 안 한 것만 보기 필터). 확정 증거가 없는 클립(점수 0~0.7)부터 찍는 게 가치가 크다.
2. `python tools/eval_pvp.py` — 확인하는 세 가지:
   - **확정 증거가 있는데 사냥으로 라벨된 클립** — 검출기 오탐이거나, 사망이 PvP 가 아니라는 뜻(0.9/0.8 을 더 낮출지 판단).
   - **확정 증거 없는 클립의 적 링 평균 분포** — 교전과 사냥이 갈리는가? **겹치면 미니맵 신호를 버린다.**
   - 임계별 정밀도/재현율과 최적 임계.
3. 결과에 맞춰 `filter.pvpWeights` 를 고치고 `python tools/rescore_clips.py` 로 다시 계산.
4. 충분히 믿을 만해지면 `filter.minPvpScore` 를 올린다 — 그 전까지는 0 (전부 남김).

## 5. 재현율 우선 — 방향 재정리 (2026-09-21)

> "중요한 건 교전 장면들을 놓치지 않는 거야. 교전이 아닌 몇몇 장면들을 제외하겠다고 핵심인 교전 장면들을 빠뜨리면 안 돼." — 사용자
>
> 원칙은 [SPEC §1](SPEC.md) 에 못 박았다. **제외 규칙은 라벨된 교전을 몇 개 버리는지부터 재고, 1개라도 버리면 채택하지 않는다.**

### 5-1. 오늘 넣은 제외 규칙 재검증 — 하나는 실패, 되돌렸다

세션 8개(라벨 클립 57개)의 프레임 상태를 다시 모아서 규칙별로 "버려지는 클립"을 직접 셌다.

| 규칙 | 버리는 교전 | 버리는 사냥 | 판정 |
|---|---|---|---|
| 팀원 전투 링만 있고 내 배지가 안 켜진 구간을 버린다 | **4** (`122301_04`, `130245_06`, `131701_01`, `134809_07`) | 0 | ❌ **되돌렸다** |
| 지역명이 `브리핑 룸` 인 프레임은 교전이 아니다 | 0 (§3-0 확인 필요 1건) | 1 (`133645_01`) | ⭕ 유지 |

- **팀 전투 단독 구간 버리기는 완전히 역효과였다.** 막으려던 것은 사용자가 지적한 `2일차 낮 경찰서`(=이미 끝난 교전, 라벨 없음) 1개인데, 같이 날아가는 것이 진짜 교전 4개다. 원거리에서 보거나 도망치는 동안 내 배지는 안 켜진다.
- **되돌렸다**(`finalize_match`). 이 구간은 `confidence == 0.0`(내 배지가 한 프레임도 없음)으로 구분되므로 UI 에서 뒤로 보내거나 걸러 볼 수 있다. 새 필드는 필요 없다. `2일차 경찰서` 같은 "끝난 뒤 클립"은 경계 문제로 남겨두고 버리지 않는다.
- **브리핑 룸(대기방)은 유지한다.** 교전이 물리적으로 불가능한 구간이라 SPEC §1의 예외에 해당하고, 오독 위험도 실측했다 — 지역명이 읽힌 2004 프레임 중 `브리핑 룸` 76(3.8%), 전부 매치 시작부의 연속 구간이고 **다른 지역 사이에 낀 고립 프레임은 0개**였다.

### 5-1-b. 놓친 교전 찾기 — 구간 밖의 증거 (2026-09-21)

검출 결과에서 **구간 밖에 있는 확정 증거**(K/A 증가, 내 사망, 팀원 사망)를 세션 8개에서 전부 찾아봤다. 이게 "놓친 교전"의 직접 근거다 — 정답 라벨 없이도 잴 수 있다.

- K/A 증가가 구간 밖인 것: **0개.**
- 팀원 사망이 구간 밖인 것: 4개 — 전투 프레임이 전혀 없어 스플릿·금지구역 사망일 가능성이 커서 **만들지 않는다**(1~2일차 스플릿, §5-2).
- **내 사망이 구간 밖인 것: 2개** (`122301` 2205초, `130245` 4407초). 배지가 한두 프레임만 켜져 `min_combat_samples` 에 걸려 구간이 못 되었거나, 살아있는 프레임이 없는 경우다. 내 사망은 교전일 확률이 높은 신호(0.9)인데 클립이 없는 건 명백한 빈틈이다.
- **고쳤다**: 어떤 구간에도 안 걸리는 내 사망(관전 시작)마다 **직전 12초를 구간으로 만든다.** 살아있는 프레임이 없으면(매치 기록이 이미 관전 상태로 시작) 만들지 않는다. 결과: `130245` 4395~4404초 구간 1개 추가, `122301` 은 대상이 아님(첫 프레임이 이미 관전).
- 한계: 이 검사는 **증거가 있는 놓침**만 본다. 증거도 배지도 없이 지나간 교전은 원리상 세지 못한다 — 사용자가 클립 목록에서 빠진 교전을 발견하면 그 시각을 알려주는 것이 유일한 확인 수단이다.

### 5-2. "아군이 근처에 있어야 의미가 있다" — 미니맵으로는 못 잰다

1~2일차 무료 부활 구간에는 팀원이 흩어져 사냥하다(스플릿) 혼자 죽는다는 사용자 지적을 미니맵 **아군 링 수**(`ally_rings`, 새로 추가)로 재봤다.

- 클립 구간 평균이 사냥 2.1~3.4 / 교전 1.3~4.9 로 **완전히 겹친다.** 오탐 클립(`131701_04`)도 최대 5였다.
- 아군 색 범위(hue 45~260)에 팀원 아이콘 말고 다른 표식이 섞이는 것으로 보인다(평균 3 이상이 흔한데 팀원은 최대 2명).
- **채택하지 않았다.** 값은 `ally_rings` 로 기록만 한다.

대신 사용자 도메인 지식을 직접 가중치로 넣었다 — **1~2일차 팀원 사망은 `teammateDeathSplit` 0.5** (기본 0.8). 클립을 버리지 않고 점수만 낮추므로 위 원칙에 어긋나지 않는다.
근거는 팀원 사망만 걸린 클립의 라벨: 1~2일차 교전 2 / 사냥 1(`131701_04`), 3일차 이후 교전 3 / 사냥 0. **표본 6개짜리 임시값이다.**

### 5-3. 네임플레이트 — 색이 사용자 설정이라는 게 밝혀졌다

프로토타입([SPEC §2.12-8](SPEC.md) 에 색표 정리): HSV 마스크 + 가로 닫힘 + 레벨 상자 + 눈금 개수로 머리 위 체력바를 셌다.

- 잡힌 **파란 눈금 바는 적이 아니라 팀원**이었다(기본 아군 색 = 파랑). 즉 이 신호는 "팀원이 화면에 있다"이고, AUC 0.62 로 약하다.
- 적 플레이어는 **팀1~8 의 8색 집합**이고 기본값에서 **팀1 = 몬스터 색(진홍)** 이라 색만으로는 야생동물과 못 가른다.
- **보류한다.** 다시 시도한다면 색이 아니라 모양(눈금 분절·실드 띠·레벨 상자)으로 플레이어와 몬스터를 가르는 쪽이다.
- **추후 구현 옵션(지금은 만들지 않음)**: 옵션 화면에서 게임의 `색약 간단 설정` 스크린샷을 첨부하면 역할별 색을 자동으로 읽어 프로필에 저장 → [plan-ui.md §5](plan-ui.md). 네임플레이트 신호를 채택하기로 결정한 뒤에 만든다.
