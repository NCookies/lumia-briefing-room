## 1. 목적

스팀 백그라운드 녹화에서 **사람과의 교전 장면을 자동으로 잘라 보관**한다.

1. 복기 — 내 교전의 판단·포지셔닝 점검
2. 감상 — 잘 나온 교전 다시 보기
3. 잘하는 사람의 교전 모으기 — 방송 다시보기 영상에서도 같은 방식으로(별도 탭). 사용자가 찍는 교전/그 외 라벨은 PvP 판별 튜닝의 정답이 된다.

개인용 도구다. 공유·편집은 목표가 아니다. 원래 목표였던 하이라이트 자동 선별은 태그·점수 위에 얹는 후보로 남긴다.

### 무엇을 뽑는가

- **내가 참여한 사람과의 교전 전부** — 이기든 지든, 킬이 있든 없든.
- 이 게임은 야생동물 사냥이 대부분이고 **교전 배지는 사냥에도 똑같이 켜진다.** 배지는 "무슨 일이 일어나는 시점"을 잡는 앵커일 뿐이고, 사람과의 교전인지는 여러 약한 증거를 모은 **PvP 점수**로 판단한다.
- **재현율이 목적 함수다.** 잘못 버리면 영구 손실(링버퍼), 잘못 남기면 디스크만 쓴다. 그래서 생성은 느슨하게 하고 판단은 열람 단계(점수 정렬·필터·태그)에서 한다. 구간 경계 규칙도 필터로 본다 — [spec/detection.md §1](spec/detection.md).
- 일단 전부 만들고 정리는 사용자가 한다: 삭제(Windows 휴지통/영구), 고정, 내보내기, 자동 정리. 태그·점수가 메타데이터에 남아 생각이 바뀌어도 재추출이 필요 없다.

> **방향 전환 진행 중(2026-09-29)**: 교전만 완벽히 골라내는 것은 원리상 어렵다고 보고 "게임 전체 영상 위에서 후보를 빨리 찾고 쉽게 고치기"로 옮기는 중이다. 아직 구현 전이므로 이 명세는 현재 동작(클립 중심)을 적는다 — [plan-fullvideo.md](plan-fullvideo.md).

## 2. 핵심 설계 원칙

- **녹화 소스는 인터페이스로 추상화한다**(`FrameSource`). 스팀 녹화 포맷은 문서화되지 않은 내부 포맷이라 언제든 깨질 수 있다. 이것이 최대 리스크에 대한 방어선이다.
- **실시간 화면 캡처를 하지 않는다.** 스팀이 이미 녹화한 파일을 사후 분석한다(인게임 오버헤드 0, 검출 시각 = 영상 타임코드).
- **핵심 기능은 외부 서비스에 의존하지 않는다.** 공식 API·타임라인 마커를 쓰지 않는다. 네트워크는 동의한 부가 기능과 사용자가 누른 동작에만.
- **검출은 전부, 필터는 나중에.** 판독 불가(`None`)는 "아님"과 다르다.
- **LLM 을 핫패스에 넣지 않는다.** 고정 UI 영역 픽셀 판독은 OpenCV 로 충분하다.

## 3. 불변 사항 (설정으로 바꿀 수 없다)

- 스팀 원본 녹화는 절대 수정하지 않는다. 영상 파일(다시보기) 원본은 수정·이동하지 않고, 사용자가 `vod.deleteSourceAfter` 로 고른 경우에만 분석이 끝난 그 파일 하나를 지운다.
- 핵심 기능(검출·클립 생성·열람)은 네트워크 없이 동작한다. 앱은 영상을 내려받지 않는다.
- 영상·화면 이미지·결과표 이미지는 어떤 경우에도 밖으로 보내지 않는다.
- 게임 프로세스를 건드리지 않는다.
