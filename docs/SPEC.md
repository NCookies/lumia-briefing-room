## 1. 목적

스팀 백그라운드 녹화(와 방송 다시보기 영상 파일)에서 **게임 하나하나의 전체 영상을 남기고, 그 위에서 사람과의 교전 후보를 빨리 찾아 고쳐 보관**하게 한다.

1. 복기 — 내 교전의 판단·포지셔닝 점검
2. 감상 — 잘 나온 교전 다시 보기
3. 잘하는 사람의 교전 모으기 — 방송 다시보기 영상에서도 같은 방식으로(`영상 파일` 탭)

개인용 도구다. 공유·편집은 목표가 아니다.

### 풀영상 중심 (2026-09-29 전환)

이 게임은 야생동물 사냥에도 궁극기를 쓰는 등 변수가 많아 **교전만 100% 골라내는 것은 원리상 어렵다.** 그래서 "자동으로 완벽히 자르기" 대신 아래 구조를 쓴다.

- **게임마다 풀영상**(캐릭터 선택 화면 ~ 결과 화면)을 저장한다. 매칭 대기 로비·닷지·연습 모드는 넣지 않는다 — [spec/game.md](spec/game.md), [spec/pipeline.md §11](spec/pipeline.md).
- 화면은 **게임 목록 → 풀영상 플레이어** 두 층이다. 풀영상 위에 검출한 **교전 후보**를 구간으로 보여 주고, 사용자가 범위를 고쳐 **보관**하면 클립이 된다 — [spec/ui.md](spec/ui.md).
- 분석이 끝나면 후보를 자동으로 클립으로 보관할지(`clip.saveMode=auto`, 기본) 직접 고를지 옵션으로 정한다.
- **클립 탭**은 보관한 클립을 카테고리(= 실제 폴더)별로 모아 보는 곳이다. 분류는 앱이 하지 않고 사용자가 카테고리를 만들어 한다.
- **자동 정리는 풀영상만** 대상으로 한다(스팀·영상 파일 합산 기본 40GB). 보관한 클립은 사용자의 선택이라 자동으로 지우지 않고, 게임 행 `⋯` 메뉴로 쉽게 정리한다.
- 풀영상은 게임당 1.5~5GB(2560x1440 스팀 녹화 약 190MB/분)라 첫 실행 화면에서 50~100GB 여유 공간이 필요하다는 것을 강조하고, 부족할 것 같으면 미리 알린다 — [spec/pipeline.md §12](spec/pipeline.md).

### 무엇을 후보로 뽑는가

- **내가 참여한 사람과의 교전 전부** — 이기든 지든, 킬이 있든 없든.
- **교전 배지는 사냥에도 똑같이 켜진다.** 배지는 "무슨 일이 일어나는 시점"을 잡는 앵커일 뿐이고, 사람과의 교전인지는 여러 약한 증거를 모은 **PvP 점수**로 판단한다.
- **재현율이 목적 함수다.** 잘못 버리면 영구 손실(링버퍼), 잘못 남기면 디스크만 쓴다. 생성은 느슨하게 하고 판단은 열람 단계(점수·태그·사용자 편집)에서 한다 — [spec/detection.md §1](spec/detection.md).

## 2. 핵심 설계 원칙

- **녹화 소스는 인터페이스로 추상화한다**(`FrameSource`). 스팀 녹화 포맷은 문서화되지 않은 내부 포맷이라 언제든 깨질 수 있다. 이것이 최대 리스크에 대한 방어선이다.
- **실시간 화면 캡처를 하지 않는다.** 스팀이 이미 녹화한 파일을 사후 분석한다(인게임 오버헤드 0, 검출 시각 = 영상 타임코드).
- **핵심 기능은 외부 서비스에 의존하지 않는다.** 공식 API·타임라인 마커를 쓰지 않는다. 네트워크는 동의한 부가 기능과 사용자가 누른 동작에만.
- **검출은 전부, 필터는 나중에.** 판독 불가(`None`)는 "아님"과 다르다.
- **LLM 을 핫패스에 넣지 않는다.** 고정 UI 영역 픽셀 판독은 OpenCV 로 충분하다.
- **이전 버전 데이터를 버리지 않는다.** 0.1.x 의 클립·영상 색인·폴더 구조는 새 구조로 옮겨 그대로 보이게 한다 — [spec/pipeline.md §11](spec/pipeline.md), [spec/vod.md §4](spec/vod.md).

## 3. 불변 사항 (설정으로 바꿀 수 없다)

- 스팀 원본 녹화는 절대 수정하지 않는다. 영상 파일(다시보기) 원본은 수정·이동하지 않고, 사용자가 `vod.deleteSourceAfter` 로 고른 경우에만 분석이 끝난 그 파일 하나를 지운다.
- 핵심 기능(검출·풀영상·클립·열람)은 네트워크 없이 동작한다. 앱은 영상을 내려받지 않는다.
- 영상·화면 이미지·결과표 이미지는 어떤 경우에도 밖으로 보내지 않는다.
- 게임 프로세스를 건드리지 않는다.

## 6. 문서 규칙

- 기능을 끝내면 결론(무엇을·왜·어떤 함정)만 해당 spec 파일에 적고 plan 에서 지운다. 실측 경위·사고 서술은 커밋 메시지에 남긴다.
- 함정은 다시 밟지 않도록 한 줄씩 해당 spec 의 "함정" 에 남긴다.
- spec 에는 아직 만들지 않은 것을 쓰지 않는다. 그건 plan 에 둔다. `tools/check_docs.py`(pytest 에 포함)가 링크·완료 체크·계획 표현·설정 키 목록을 검사한다.
- 지난 릴리스·처리한 할 일의 기록은 문서에 쌓지 않는다 — CHANGELOG.md 와 git 이력이 맡는다.
