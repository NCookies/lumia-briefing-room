## 1. 현재 배포를 막는 것 (코드 조사 결과)

| 항목 | 현재 | 문제 |
|---|---|---|
| 실행 | `run.bat` → `.venv\Scripts\python.exe -m lumia_briefing_room.cli.app --open-ui` | 파이썬·가상환경 필요 |
| 프론트 | `frontend/dist` 를 `api/static.py` 가 서빙, `npm run build` 는 손으로 | 설치본에는 빌드 결과를 넣어야 한다 |
| ffmpeg | `LUMIA_FFMPEG` 환경변수 → 시스템 `PATH` 탐색 (`config.py`) | 없는 PC 는 실행 불가. SPEC §4 가 "번들은 선택이 아니라 필수" 라고 이미 적었다 |
| ffprobe | `shutil.which("ffprobe")` (`video/vod.py`) | 같이 번들해야 한다 |
| 본보기·프로필 경로 | `profiles/models.py` 와 `detect/character.py` 가 `Path(__file__).parents[N]` 로 `data/…` 를 찾는다 | PyInstaller 로 묶으면 소스 트리가 없어 **파일을 못 찾는다.** 실패가 조용히 날 수 있다(템플릿 없이 검출) |
| `config.py` 의 `_PROJECT_ROOT` | 소스 트리 기준 | 같은 이유 |
| 자동 시작 명령 | `cli/app.py::autostart_command()` = `"{sys.executable}" -m lumia_briefing_room.cli.app` | 빌드본에서 `sys.executable` 은 앱 exe 라 `-m` 인자가 의미 없다. **로그인 시 자동 시작이 깨진다** |
| 외부 프로세스 창 | `subprocess` 호출 7곳에 `CREATE_NO_WINDOW` 없음 | 콘솔 없는 빌드(`--noconsole`)에서 ffmpeg 를 부를 때마다 **검은 콘솔 창이 번쩍인다**(게임 중에 뜨면 포커스를 뺏을 수 있다) |
| 콘솔 출력 | `cli/app.py`·`serve.py`·`watch.py` 가 `logging.basicConfig`(stderr) | 콘솔 없는 빌드에서 `sys.stderr` 가 `None` 이라 출력이 사라지거나 오류가 난다. 파일 로그(`logsetup.py`)만 믿어야 한다 |
| 중복 실행 | 막는 장치 없음 | 자동 시작 + 사용자가 바로가기로 또 실행 + 설치기 "설치 후 실행" 이 겹치면 트레이 두 개·감시 두 개가 같은 경기를 동시에 처리할 수 있다 |
| 버전 | `pyproject.toml` 의 `0.1.0` 뿐, 앱 안에서 읽는 곳 없음 | 진단 정보·설치기·업데이트 확인 모두 버전이 필요하다 |
| HEVC 프록시 | `config.py` 에 `ProxyConfig`(enabled/height/crf)와 `.proxy` 폴더 경로만 있고 **만드는 코드가 없다** | D4 는 "켜기만 하면 되는" 일이 아니라 새 기능이다 |
| rapidocr | `pip install --no-deps rapidocr` 따로, 첫 실행 때 모델 수십 MB 다운로드 | 설치본에는 모델을 포함해야 한다(핵심 기능은 네트워크 없이 — SPEC §7.8). 패키징 때 `opencv-python` 충돌을 다시 풀어야 한다 |
| 분석 부하 | 분석 프로세스·ffmpeg 가 보통 우선순위로 돈다 | 경기가 끝나면 분석이 시작되는데, 그동안 사용자가 다음 경기를 시작하면 **게임 프레임이 떨어질 수 있다**. 내 PC 에서는 괜찮았어도 친구 PC 사양은 모른다 |
| pywebview | 트레이 경로는 항상 기본 브라우저를 연다(plan-ui.md §4-1) | 배포와 무관하게 유지 |
| 설정·클립 위치 | 설정·로그 `%LOCALAPPDATA%\LumiaBriefingRoom\`, 클립 `%USERPROFILE%\Videos` 기준 | 설치 폴더에 쓰지 않으므로 좋다. 유지 |

가장 위험한 것은 **D1(경로·자동 시작)** 과 **D5(콘솔 없는 실행)** 다. 개발 환경에서는 멀쩡히 돌다가 설치본에서만 조용히 망가지는 종류라서, D5 에서 반드시 빌드본으로 재확인한다.

## 2. 단계별 상세

### D1. 경로·버전·실행 명령 정리

- 리소스(프로필 JSON, `data/templates/**/*.npz`, `data/characters.json`, 프론트 `dist`)를 찾는 한 곳(`paths.resource_dir()` 같은 것)을 만든다. 개발 시에는 저장소 루트, 빌드본에서는 `sys._MEIPASS`(또는 exe 옆)를 가리킨다.
- `profiles/models.py`, `detect/character.py`, `config.py`, `api/static.py` 가 이 한 곳만 쓰게 한다. 순수 로직이라 TDD.
- **본보기를 못 찾으면 조용히 넘어가지 않고 경고를 남긴다**(SPEC §6 4단계 "K/A 템플릿이 조용히 꺼져 있던 사고"의 재발 방지).
- **버전 한 곳**: `lumia_briefing_room.__version__` 을 기준으로 두고 `pyproject.toml`·설치기·API(`GET /api/app-info`)가 모두 여기서 읽는다.
- **실행 명령 한 곳**: `autostart_command()` 가 빌드본이면 `"<앱>.exe"`, 개발 환경이면 지금처럼 `python -m …` 을 돌려준다. 이미 등록된 옛 명령(개발 PC 의 `python -m`)은 앱이 시작할 때 현재 명령으로 덮어쓴다(`apply_autostart_setting` 이 이미 매번 호출된다).

### D2. 개발/배포 모드 분리

- 판별: 빌드본이면 배포 모드(`sys.frozen`), 그 외는 개발 모드. 설정 키 `app.mode` 로 강제 지정 가능(디버깅용).

### D3. 첫 실행 화면 · 옵션 · 진단 정보 · 중복 실행 방지

**첫 실행 화면** (설정의 `consent.version` 이 현재 동의 화면 버전보다 낮으면 뜬다 — SPEC §7.11)

앱이 처음 뜰 때 UI 를 자동으로 열고(평소 `ui.startMinimized` 와 무관하게) 한 화면에서 차례로 확인한다. 설치기에서는 묻지 않는다(한 곳에서만 묻는다 — SPEC §7.11).

**설치 직후 반응(2026-09-26)** — 설치 뒤 아무 일도 안 일어난 것처럼 보이지 않게 세 가지를 했다. ① 설치기가 마침 화면의 "실행" 체크를 묻지 않고 앱을 바로 띄운다(조용한 설치 제외, `[Run]` 에서 `postinstall` 제거). ② 마침 화면 문구가 "몇 초 뒤 브라우저에 첫 화면이 열리고, 안 열리면 트레이(∧ 안) 아이콘을 누르라" 고 알린다(`FinishedLabel`). ③ 앱이 첫 실행 화면이 필요할 때 트레이 알림("실행됐습니다. 곧 브라우저에 첫 화면이 열립니다")을 띄운다(`announce_first_run`). 또 스팀 녹화 폴더를 인식했으면 첫 실행 화면에서 "과거 녹화도 분석하기"(기본 선택)를 물어 시작하기와 함께 과거 녹화 분석을 시작한다([plan-backfill §0](plan-backfill.md)). Defender 가 exe 를 막으면 위 동작도 못 하므로 그 경우 안내는 포스트·README 의 번외 절.

1. **스팀 녹화 폴더** — 자동 탐지 결과를 보여 주고, 못 찾았으면 폴더를 고르게 한다. 스팀 배경 녹화가 꺼져 있으면 켜는 법을 안내한다. 클립 저장 폴더도 여기서 확인한다.
2. **녹화 해상도 확인** — 가장 최근 녹화 세션의 해상도를 읽어 지원 여부를 보여 준다: 측정한 프로필(2560x1440, 1920x1080) / 같은 비율이라 축척으로 대응(16:9 다른 크기) / **비율이 다름(16:10, 21:9 등 — 정확도를 보장하지 못함)**. 진행은 막지 않는다.
3. **업데이트 확인** — "새 버전이 나오면 알려 주기" (기본 선택: ~~켬~~ **끔** — D12) → `update.check`
4. **개발에 도움 주기** (기본 선택: 끔, 항목별 체크) — "교전/사냥 라벨 보내기" → `telemetry.sendLabels`, "오류 로그와 환경 정보 보내기" → `telemetry.sendLogs`. 무엇을 보내는지(영상·화면은 보내지 않는다)를 한 줄씩 적고 "보낼 내용 예시 보기" 를 둔다.
5. **세 항목(업데이트 확인·라벨 전송·오류 로그 전송) 모두 처음에는 체크가 꺼져 있고 사용자가 직접 켜야 한다(D12).** "시작하기" 를 누르면 설정에 저장하고 `consent.version` 을 현재 값으로 올린다. **창을 그냥 닫으면 전송·업데이트는 꺼진 채로 두고** 다음 실행 때 다시 묻는다.

> D10 전송이 구현되기 전의 빌드(D8 친구 배포본)에서는 4번 항목을 보이지 않는다. D10 이 들어갈 때 동의 화면 버전을 올려 **그 항목만** 다시 묻는다(SPEC §7.11 `consent.version`). 결정 필요 → §7-11.

**옵션 모달 "개인정보·업데이트" 탭** — 위 3·4번 설정을 언제든 끄고 켠다. 업데이트는 "업데이트 확인" 버튼과 현재 버전을 같이 보여 준다. 전송은 D10 이후 "보낸 데이터 삭제 요청"·"보낼 내용 미리보기" 를 둔다.

**진단 정보 내보내기** — 옵션에서 버튼 하나로 로그 파일 + 버전 + 해상도/코덱 정보를 zip 으로 묶어 준다(닉네임·경로 속 사용자 이름 제거). D8 배포본은 사용자가 이 zip 을 직접 첨부해 보냈다. **수신 서버가 생기면 zip 첨부 대신 앱이 서버로 보내는 방식으로 바꾼다 → [D14](#d14-진단-정보-서버-전송).** 친구 배포 단계의 피드백 수집에 바로 쓴다. 트레이 메뉴에 "로그 폴더 열기"를 넣는다.

**중복 실행 방지** — 이름 있는 뮤텍스(또는 포트/잠금 파일)로 두 번째 실행을 감지하면, 새로 띄우지 않고 이미 떠 있는 앱의 UI 를 연 뒤 종료한다.

### D4. ffmpeg 번들 + HEVC 재생 폴백

**ffmpeg**

- 배포 파일에 ffmpeg.exe·ffprobe.exe 를 포함하고 `config.py` 의 탐색 순서를 `LUMIA_FFMPEG` → **번들** → `PATH` 로 바꾼다.
- 라이선스: **LGPL 빌드를 쓰고 GPL 빌드를 동봉하지 않는다.** 지금 쓰는 동작은 디코딩·`-c copy` 컷(클립·자르기·VOD)·썸네일이라 GPL 인코더가 필요 없다. 새로 만들 H.264 프록시가 유일한 인코딩이므로 LGPL 로 쓸 수 있는 인코더(Windows Media Foundation `h264_mf`, 하드웨어 `h264_nvenc`/`h264_qsv`/`h264_amf`)로 한다(→ §7-2).
- 모든 `subprocess` 호출에 `CREATE_NO_WINDOW` 를 넣고, ffmpeg·분석 작업은 **낮은 우선순위(`BELOW_NORMAL_PRIORITY_CLASS`)** 로 돌려 게임 중 프레임 저하를 줄인다. 한 곳(`run_ffmpeg` 같은 도우미)으로 모은다.

**HEVC 재생** (plan-ui.md §7 의 채택안)

- 디코더는 배포 파일에 못 넣는다(Microsoft Store 확장, 재배포·특허 문제). 이 PC 는 OS 코덱이 있어 원본 HEVC 가 재생되지만(plan-ui.md §4-2), 친구 PC 는 다를 수 있다.
- 프론트가 시작 시 `canPlayType('video/mp4; codecs="hvc1"')` / MediaCapabilities 로 재생 가능 여부를 확인하고, **추가로 첫 재생에서 `videoWidth === 0` 이거나 오류가 나면** 불가로 판단한다(`canPlayType` 이 "probably" 인데 실제로는 검게 나오는 경우 대비). 불가하면 클립별 H.264 프록시로 자동 전환한다.
- 프록시는 **처음 재생하려고 할 때 만든다**(전체를 미리 만들면 용량·시간이 크다). 만드는 동안 진행 표시. `GET /api/clips/{id}/video?proxy=1` 식으로 서빙.
- 프록시는 `clips/.proxy/` 에 두고 클립 삭제·자르기·자동 정리 때 같이 지운다.
- 이 단계는 "친구 PC 에서 검은 화면" 문제를 막는 핵심이라 D8 전에 반드시 끝낸다.

### D5. PyInstaller `--onedir` 빌드

- SPEC §4 결정: `--onefile` 은 첫 실행이 느리고 오탐이 심하므로 `--onedir`.
- 빌드 스크립트(`tools/build_release.py` + `build.bat`): ① `npm ci && npm run build` ② PyInstaller ③ 리소스(`data/` 의 npz·json, 프로필, 프론트 dist, ffmpeg, OCR 모델) 복사 ④ 버전 주입 ⑤ 결과 폴더를 zip 으로도 만든다(설치기 없이 테스트용). 순서가 바뀌면 안 되므로 한 스크립트로 묶는다(README "실행 방법"에 같이 적는다 — CLAUDE.md 규칙). 빌드 도구(PyInstaller)는 `.venv` 의 개발 의존성으로 설치한다.
- 잡아야 할 것:
  - **rapidocr**: `--no-deps` 설치 상태 그대로 묶고, **OCR 모델(ONNX)을 배포 파일에 포함**해 첫 실행 다운로드를 없앤다(→ §7-3).
  - **onnxruntime, opencv, pystray(윈도우 트레이), pywebview**: PyInstaller hook 누락이 흔하다. 빌드본에서 각각 실제로 실행해 본다.
  - **콘솔 없이(`--noconsole`) 뜨게 한다.** 그러면 `basicConfig` 의 stderr 출력이 없으므로 빌드본에서는 파일 로그만 붙이고, 처리되지 않은 예외도 파일 로그로 남긴다(`sys.excepthook`, 스레드 `threading.excepthook`). 시작 자체가 실패하면(포트·파일 권한 등) 메시지 상자로 알린다.
  - 앱 아이콘(exe·트레이·설치기) 한 벌.
- 검증: **Windows 샌드박스**(이 PC 가 Windows 11 Pro 라 기본 제공 — 파이썬·ffmpeg·HEVC 확장이 없는 깨끗한 환경)에서 zip 을 풀어 실행 → 트레이 → UI → 첫 실행 화면 → 샌드박스에 녹화 폴더를 매핑해 클립 1개 생성 → 재생(HEVC 없는 환경이라 **프록시 폴백까지 실측된다**). 테스트 스위트는 빌드본을 못 검증하므로 이 수동 확인을 §3 체크리스트로 남긴다.

### D6. Inno Setup 설치기

- 설치 위치는 사용자 영역(`%LOCALAPPDATA%\Programs\LumiaBriefingRoom`) 기본으로 관리자 권한 없이 설치되게 한다.
- 바로가기(시작 메뉴·바탕화면 선택), 설치 후 실행(첫 실행 화면으로 이어진다).
- 제거: 자동 시작 레지스트리 값(`HKCU\…\Run\LumiaBriefingRoom`)을 지운다. 실행 중이면 먼저 종료한다. 설정·로그(`%LOCALAPPDATA%\LumiaBriefingRoom`)는 지울지 묻고, **클립 폴더는 지우지 않는다.**
- 재설치·업데이트 설치: 실행 중인 앱을 닫고 덮어쓴다(D9 가 이 경로를 쓴다). 설정은 유지.
- `THIRD_PARTY_NOTICES`(ffmpeg LGPL 고지와 소스 링크, 파이썬 패키지, OCR 모델)를 설치 폴더에 동봉한다 — 친구 배포라도 바이너리를 넘기므로 D8 전에 필요하다.
- **코드 서명이 없으면 SmartScreen 경고**가 뜬다. 초기에는 감수하고 "추가 정보 → 실행" 을 안내한다. 인증서는 이용자가 늘고 나서 판단한다. **Defender 오탐**은 D8 에서 실제 발생 여부를 본다.
- 설치기 파일 이름·버전 표기는 `__version__` 하나에서 만들어지게 한다.

### D9. 자동 업데이트

- `update.check` 가 켜져 있을 때만 **시작 시와 하루 1회 자동으로** GitHub Releases API 로 최신 버전을 확인한다. 끄면 자동 확인은 하지 않는다.
- **자동 확인을 꺼 두어도 수동으로 확인·업데이트할 수 있어야 한다(D12 로 기본값이 꺼짐이 되면서 필수가 됐다).** 옵션 "정보·진단" 탭의 "업데이트 확인" 버튼을 누르면 그때만 릴리스 API 를 호출하고, 새 버전이 있으면 같은 화면에서 "업데이트" 버튼(다운로드 → SHA-256 확인 → 설치기 실행)까지 이어진다. 사용자가 직접 누른 동작이므로 `update.check` 값과 무관하게 동작하고, 눌렀을 때만 네트워크를 쓴다. **(2026-09-25 변경)** 트레이 알림은 자동 확인이 켜져 있을 때만 뜨지만, **메인 화면 위 배너는 어떤 경로로든(자동·수동 확인) 새 버전이 알려지면 뜬다** — 옵션 안에만 있으면 눈에 띄지 않는다는 피드백. 배너는 30초마다·수동 확인 직후 갱신하고, "변경 내용 보기"(릴리스 본문 창)·"업데이트"·이 버전 알림 닫기를 둔다. 자동 확인 루프는 30초마다 설정을 읽어 "업데이트 알림"을 켜면 곧바로(최대 30초) 확인한다.
- 새 버전이 있으면 트레이 알림과 UI 배너로 알리고, 사용자가 누르면 설치기를 받아 SHA-256 을 확인한 뒤 실행한다(앱이 실행 중인 파일을 직접 교체하지 않는다 — 설치기가 앱을 닫고 덮어쓴다).
- 다운로드 URL 은 저장소 릴리스로 고정한다. **비공개 저장소는 인증 없이 릴리스 API 를 못 읽으므로** 업데이트 확인은 공개 저장소(또는 릴리스 전용 공개 저장소)가 전제다(→ §7-10).
- 게임 패치로 HUD 가 바뀌면 검출이 깨진다. 프로필·본보기·`characters.json` 만 빠르게 고쳐 배포할 수 있게 데이터만 받는 경로를 검토한다(우선순위 낮음).

- **(2026-09-26 업데이트 직후 안내)** 업데이트가 끝난 것을 사용자가 알아보도록 두 가지를 한다. ① 설치기를 띄우기 전에 `update_state.json` 의 `pendingUpdate={from,to}` 를 남기고, 새 버전이 뜨면(`from` 보다 현재 버전이 클 때) `GET /api/update/status.justUpdated` 로 알려 화면이 **"업데이트가 완료되었습니다 · vA → vB" 창**(패치노트 보기·확인)을 한 번 보인다(`POST /api/update/ack` 로 끔, 설치기 실행이 실패하면 남기지 않음). "패치노트 보기" 를 누르면 완료 창은 닫고(확인한 것으로 처리) 패치노트 창만 남긴다 — 처음엔 완료 창이 그대로 남아 그 창의 "확인" 이 패치노트까지 닫는 실측 버그가 있었다. ② 새 앱이 서버를 띄운 뒤 **8초 안에 열려 있던 탭의 요청이 오지 않으면 브라우저 창을 직접 연다**(탭이 스스로 새로고침해 돌아오면 중복으로 열지 않는다 — 서버가 `/api/` 요청 수를 세어 판단, `cli/app.py::open_after_update`). 옛 설치기가 서버 없이 재시작한 경우도 같은 안내가 뜬다.

#### D9 수동 확인 절차

덮어쓰기 설치는 자동화할 수 없으므로 실제 릴리스 두 개로 한 번 확인한다. **D9 가 들어간 빌드가 아직 배포된 적이 없으므로 릴리스가 두 번 필요하다**(0.1.3 앱에는 업데이트 기능이 없다).

1. **기준 버전 릴리스(예 0.1.4)**: `__version__`·CHANGELOG 를 올려 태그 푸시 → Release 가 자동으로 공개된다([D13](#d13-배포-자동화)). 확인 PC 에 이 설치기를 받아 설치한다. 이미 0.1.3 이 깔려 있다면 이것이 **첫 덮어쓰기 실측**이다 — 설치 폴더가 그대로인지, 프로그램 추가/제거에 항목이 하나뿐인지, 설정(`%LOCALAPPDATA%\LumiaBriefingRoom\config.json`)·클립이 남아 있는지 본다. 앱을 열어 옵션 "정보·진단"의 버전이 0.1.4 인지 확인.
2. **새 버전 릴리스(예 0.1.5)**: 버전·CHANGELOG 만 올려 다시 태그 푸시(내용 변경 없이도 된다).
3. **수동 경로**(선택 기능은 꺼진 채로): 옵션 → 정보·진단 → **업데이트 확인** → "새 버전 v0.1.5" 와 패치노트가 보이는지 → **업데이트**. 확인할 것: 진행률이 오르는지 / 설치기 진행 창이 뜨고 실행 중이던 앱이 닫히는지 / 끝나면 **앱이 다시 떠서 트레이에 상주**하는지 / 버전이 0.1.5 인지 / 설정·클립 유지 / 프로그램 추가/제거 항목이 여전히 하나 / 자동 시작을 켜 뒀다면 유지 / `%LOCALAPPDATA%\LumiaBriefingRoom\updates\` 에 받은 설치기가 남아 있는지(다음 업데이트 때 지워진다). 앱이 받은 파일에는 인터넷 출처 표시가 없어 SmartScreen 경고가 뜨지 않을 것으로 예상되지만 **직접 본 적은 없으니** 뜨는지 기록한다.
4. **자동 경로**: 0.1.4 로 되돌려(설치기 재실행) 옵션의 "업데이트 알림"을 켜고 앱을 다시 시작 → 잠시 뒤 트레이 알림과 화면 위 배너가 뜨는지 → 배너의 "업데이트"로 설치. 알림은 같은 버전에 한 번뿐이라 다시 보려면 `update_state.json` 의 `notified` 를 지운다.
5. **거부 경로**(선택): 릴리스의 `.sha256` 을 임시로 잘못된 값으로 바꿔 올린 뒤 업데이트를 눌러 "SHA-256 이 달라 실행하지 않았습니다" 가 뜨고 설치기가 실행되지 않는지 본다(`gh release upload --clobber`). 확인 뒤 원래 값으로 되돌린다.
6. 되돌리기: 문제가 있으면 이전 설치기를 다시 실행해 덮어쓴다(같은 `AppId`). 결과(특히 3번)를 이 절에 날짜와 함께 적고 roadmap 의 D9 항목 "남은 것"을 지운다.

**구현 결과(2026-09-25)** — 코드는 `src/lumia_briefing_room/telemetry/`:

결정한 것: ① 오류 수집은 `app.log` 파싱 대신 구조화 핸들러 outbox ② 서버 관리자 API(`GET /v1/admin/labels`)로 `tools/pull_labels.py` 가 라벨을 가져온다 ③ 토큰은 빌드 때 환경변수로 번들에 주입 ④ 다시보기 클립 라벨도 보낸다(`source=vod`) ⑤ 삭제 요청 성공 시 전송을 끄고 로컬 전송 기록을 지운다 ⑥ `consent.version` 3(라벨·오류 로그만 다시 묻는다). **발견·수정한 것**: 로그 핸들러가 같은 파일에 두 번 붙어 모든 줄이 두 번 기록되던 문제, 테스트 실행이 실제 사용자의 `app.log` 에 트레이스백을 남기던 문제(테스트가 사용자 폴더를 임시 폴더로 바꿔 쓴다). **환경 정보의 런타임 측정값(2026-09-25 추가, 버전 0.1.2)**: `telemetry/runtime_stats.py` 가 프록시를 만들 때 쓴 인코더·걸린 시간(최근 20개 평균), 실시간 분석 시간 ÷ 게임 길이(`analysisTimeRatio`, 게임 중 부하 판단용 — plan-deploy §7-14), 분석에 하드웨어 디코딩을 썼는지(`hwaccel`, 측정 전에는 다시보기 분석 설정)를 `%LOCALAPPDATA%\LumiaBriefingRoom\runtime_stats.json` 에 스스로 기록하고, 프론트가 시작할 때 `POST /api/client-capabilities` 로 알리는 HEVC 재생 가능 여부(`hevcPlayable`)와 함께 환경 정보에 싣는다. **아직 모으지 않는 것**: 신호별 수치 `pvpSignalValues`(검출기가 결과에 담지 않는다).

**계약의 원본은 이 저장소의 [`contract/receiver.schema.json`](../contract/receiver.schema.json)**(2026-09-26 infra 저장소에서 이관, 복사본 없음)이다. 수락·거부 예시는 `contract/fixtures/`. 서버 테스트(`server/receiver/tests/test_contract.py`)와 [`tests/test_contract.py`](../tests/test_contract.py)가 같은 파일을 쓰므로 한쪽만 고치면 그쪽 테스트가 깨진다. 서버 API·배포는 [server/README.md](../server/README.md), 인프라 운영은 infra 저장소 README.

| 경로 | 보내는 것 | 응답 |
|---|---|---|
| `POST /v1/labels` | 라벨 붙은 클립만. 묶음마다 `installId`·`appVersion`·`schemaVersion`(=1)·`mode`(`dev`/`release`) | `{saved}` |
| `POST /v1/logs` | 오류 로그 항목(로거·예외 종류·스택·오류 지문)과 환경 정보(`env`) | `{saved}` |

**앱이 클라이언트를 만들 때(D10) 지킬 것**

- 전송 대상은 `userLabel` 이 있는 클립뿐이고 값은 `pvp→combat`, `pve→other` 로 **변환해서** 보낸다(로컬 저장값·`.labels/`·`eval_pvp.py` 는 그대로).
- `matchKey`·`clipKey` 는 32자리 소문자 hex. 제안: `sha256(installId + "|" + sessionDir + "|" + matchStartUtc)`(`clipKey` 는 뒤에 `|videoOffsetSec` 추가)의 앞 32자 — 설치마다 소금이 달라 다른 설치와 이어 볼 수 없고 경로·시각 원문은 나가지 않는다. 같은 `clipKey` 를 다시 보내면 서버가 덮어쓰므로 라벨을 고친 뒤 재전송해도 중복되지 않는다. 다시 분석해 새 클립이 생기면 `clipKey` 가 달라져 새 라벨로 저장된다(이관된 라벨이 이중으로 쌓일 수 있음 — 분석 때 `matchKey` 로 묶는다).
- **`labeledAt`(라벨 붙인 시각)은 앱이 기록한다(구현됨)** — 라벨을 붙이거나 값을 바꿀 때만, 같은 값을 다시 눌러도 그대로. **`pvpSignalValues`(신호별 수치)는 앱이 아직 저장하지 않는다**(스키마에는 선택 필드, 계약 분류표의 `appMissing`). 검출기가 신호별 수치를 결과에 담게 되면 추가한다.
- **`mode`**: 개발 모드(`app.mode=dev`)는 기본적으로 전송하지 않는다. 시험용으로 보낼 때는 `mode=dev` 로 보내면 서버가 운영 데이터와 다른 폴더(`data/dev`)에 둔다.
- **보내지 않는 것**(`contract/app-metadata-fields.json` 의 `excluded`): `title`, `sessionDir`, `sessionStartUtc`, `matchStartUtc`, `matchEndUtc`, 세그먼트 번호, `videoOffsetSec`, `thumbnailPath`, `pinned`, `deletedAt`, `teamCharacters`, `matchResult`(닉네임·팀원 포함). 내 캐릭터(`myCharacter`)와 최종 K/A(`matchKills`·`matchAssists`·`matchTeamKills`)는 보낸다.
- **VOD 클립**: `source=vod` 클립의 라벨도 보낸다(결정 2026-09-25). `streamer`·`vodFile`·`vodId`·`vodGameIndex`·게임 위치는 보내지 않고, `vodId`·`vodGameIndex` 는 `matchKey` 를 만드는 데만 쓴다(계약의 `vodOnly`).
- **환경 정보(`env`)의 수집 항목**은 스키마의 `Environment` 를 그대로 따른다(CPU·GPU·메모리·배율·코덱·hevc 재생 가능·프록시 인코더·스팀 버퍼 분·분석 시간 비율 등, 값이 없으면 생략). `readFailStats` 의 키 목록은 클라이언트를 만들 때 확정한다(게임 패치 조기 경보용, roadmap §4-9).
- 응답 처리: 413(크기)·422(스키마 어긋남)는 재시도해도 같으므로 그 묶음을 버리고 앱 로그에만 남기고, 401(토큰)·5xx·타임아웃·연결 실패는 다음 전송으로 미룬다(대기분 상한 20MB). 어느 경우에도 앱이 멈추면 안 된다.

### D11. 화면에 현재 버전 표시

- 지금은 옵션 "정보·진단" 탭(`AboutPanel`)에서만 버전이 보인다. 헤더(제목 옆)에도 `v0.1.1` 처럼 항상 보이게 한다. 개발 모드는 `v0.1.1 (dev)`.
- 값은 `GET /api/app-info` 의 `version`(D1, `__version__` 한 곳) 그대로 쓴다. 못 읽으면(빈 문자열) 표시하지 않는다.
- 프론트만 바꾸므로 백엔드 변경은 없다. 완료 시 `npm run build` 까지 실행한다.

### D12. 동의 기본값 전부 꺼짐 · 라벨링 UI 숨김 · 라벨 메모

**1. 동의 화면 기본값** — 업데이트 확인(`update.check`)·라벨 전송(`telemetry.sendLabels`)·오류 로그 전송(`telemetry.sendLogs`) 모두 처음에는 꺼져 있고 사용자가 직접 켠다(네트워크를 쓰는 것은 전부 옵트인이라는 원칙과 맞춘다). 업데이트를 켜지 않은 사용자는 새 버전을 알림으로 받지 못하므로 화면에 "끄면 새 버전 알림을 받지 못합니다" 를 적고, 옵션 "정보·진단" 탭의 수동 "업데이트 확인"·업데이트 버튼([D9](#d9-자동-업데이트))으로 언제든 업데이트할 수 있다. SPEC §7.11 표의 "화면의 기본 선택" 을 함께 바꾼다. D3 의 첫 실행 화면에는 동의 항목이 없어 이 단계에서 세 항목을 새로 만들었다(`consent.version` 2 — 이미 1 로 답한 사용자에게는 새 항목만 묻는다). 옵션 "정보·진단" 탭의 "선택 기능" 에서 언제든 바꾼다.

**2. 라벨링 UI 는 `telemetry.sendLabels` 가 켜져 있을 때만 보인다.** 라벨링은 전송용 데이터를 만드는 기능이라 전송을 끄면 입력 화면도 필요 없다는 판단이다.

- 숨기는 것: 카드의 라벨 버튼, 플레이어 모달의 키보드 라벨링(1/2/0)·라벨 안내, 라벨 필터, 라벨 메모(아래 3). 이미 붙어 있는 라벨 값은 지우지 않고 파일에 그대로 두되 화면에서는 다루지 않는다.
- **교전 가능성 칩·점수·정렬은 라벨링이 아니라 검출 결과이므로 그대로 둔다**(단, 튜닝용 슬라이더·근거 상세는 D2 대로 배포 모드에서 숨김).
- **개발 모드(D2)에서는 설정과 무관하게 항상 보인다** — 라벨링은 검출기 튜닝의 재료(plan-pvp.md)라 개발자가 전송을 꺼도 계속 써야 한다.
- 라벨을 켰다 껐다 해도 로컬의 라벨 보관소(`clips/.labels/`)는 그대로다. 껐을 때 보내지 않는 것만 바뀐다.
- 라벨 값은 저장 형식(`userLabel` = `pvp`/`pve`/`null`) 그대로 두고, 화면 문구만 **`교전` / `그 외`** 로 바꾼다(지금은 `교전` / `사냥`). 사냥 외의 비교전(대기방·이동·대치 등)도 `그 외` 로 묶는다는 뜻이다. 키 1/2/0(해제)은 유지한다. **서버로 보낼 때만 중립 값 `combat`/`other` 로 변환**한다(서버 스키마와 어긋나 `pve` 가 거부되던 문제 — [roadmap §9](roadmap.md)).

**3. 라벨 메모(자유 입력)** — 라벨을 붙일 때 근거·설명을 적을 수 있는 텍스트 입력창을 라벨 옆(카드 펼침 또는 플레이어 모달)에 둔다.

- 메타데이터 필드는 새로 `labelNote`(문자열, 최대 길이 상한 — 예: 500자)를 둔다. 라벨 보관소(`clips/.labels/`)에도 같이 남긴다.
- **텍스트만 받는다.** 파일·이미지 첨부는 "영상·화면 이미지는 어떤 경우에도 보내지 않는다"(SPEC §7.8·§7.11) 와 충돌하므로 두지 않는다.
- 메모는 라벨과 함께 전송된다(`telemetry.sendLabels` 켠 사용자만). 자유 입력이라 닉네임·이름이 섞일 수 있으므로 입력창 아래에 "이 메모는 라벨과 함께 전송됩니다. 닉네임 등 개인정보는 적지 마세요" 를 표시한다. "보낼 내용 미리보기"에도 포함한다.
- **수신 서버 스키마와는 2026-09-25 에 맞췄다**(`labelNote` 500자 상한, 앱 메타데이터 필드 전수 대조) — [D10 전송 계약](#d10-라벨오류-로그-전송--서버-전송-계약).
- 순수 로직(길이 상한·정리, 라벨 UI 표시 조건)은 TDD, 완료 시 `npm run build`.

### D13. 배포 자동화

목표: 버전 태그를 푸시하면 사람이 손대지 않아도 빌드 → 설치기 → GitHub Release 업로드 → 바이러스 검사 결과 링크까지 되게 한다. 수동 빌드(D5·D6)가 안정된 뒤 D9(업데이트)·D7(공개 저장소 정리)과 같이 진행한다.

- **GitHub MCP 는 필요 없다.** 릴리스 생성·파일 업로드는 GitHub Actions 가 워크플로 안의 `GITHUB_TOKEN` 으로 한다. MCP 는 Claude 가 대화 중 릴리스를 대신 만들 때만 쓰는 것이라 이 자동화의 전제가 아니다.
- **버전 규칙**: 태그 `vMAJOR.MINOR.PATCH` = 릴리스 이름 = 설치기 파일 이름 = `__version__`. 워크플로 첫 단계에서 태그와 `__version__` 이 다르면 실패시킨다(D1 이 한 곳에서 읽게 해 둔 것의 연장).
- **워크플로 (`.github/workflows/release.yml`, 트리거: `v*` 태그 푸시)** — 러너는 `windows-latest`(exe·설치기가 Windows 전용): ① checkout ② Python·Node 설치 ③ `tools/fetch_ffmpeg.py` + `tools/build_release.py`(D5, LGPL 빌드 검증 포함) ④ `tools/build_installer.py`(D6, 러너에 Inno Setup 설치 — 확인 필요) ⑤ 설치기 SHA-256 계산 후 `.sha256` 파일 생성(D9 가 이 값을 확인) ⑥ GitHub Release 생성 + 설치기·`.sha256` 업로드 ⑦ VirusTotal 에 설치기 업로드 ⑧ 분석 결과 링크를 릴리스 본문에 덧붙이기.
- **바이러스 검사**: GitHub 이 릴리스 파일에 검사 결과를 자동으로 붙여 주는 기능은 아니고, 워크플로가 VirusTotal API 로 올려서 결과 링크를 릴리스 본문에 적는 방식이다. 서드파티 액션이 있다([crazy-max/ghaction-virustotal](https://github.com/crazy-max/ghaction-virustotal) 등 — 릴리스 파일을 검사하고 분석 링크를 릴리스 본문에 덧붙이는 기능을 표방). 어떤 액션을 쓸지는 구현 때 소스를 읽고 고른다. API 키는 GitHub Secrets(`VT_API_KEY`)에 둔다.
- 문서 갱신: 구현과 같은 커밋에 README 에 릴리스 절차(태그 푸시 방법, 필요한 Secrets)를 추가한다(CLAUDE.md 규칙).

**구현 결과 (2026-09-25)** — 파일: `.github/workflows/release.yml`, `tools/release_tools.py`(순수 로직 + CLI), `CHANGELOG.md`, `tests/test_release_tools.py`(30개). 실행 방법은 [DEVELOPMENT.md 13](DEVELOPMENT.md).

- **흐름**: 태그 형식·`__version__` 일치·CHANGELOG 절 존재를 **맨 먼저** 확인(`check-tag`) → 의존성(`pip install -e ".[dev,build]"`, `npm ci`) → 릴리스 도구 테스트 → `fetch_ffmpeg.py` → OCR 모델 미리 받기 → `build_release.py --skip-zip` → Inno Setup 준비 → `build_installer.py` → `release_tools.py prepare`(SHA-256 파일 `<설치기>.sha256`, 릴리스 본문 생성) → `gh release create --draft`(설치기·`.sha256` 업로드) → VirusTotal 업로드(`continue-on-error`) → 본문에 검사 링크를 붙여 `gh release edit --draft=false` 로 공개. **초안으로 만들어 두었다가 마지막에 공개하므로 사용자가 반쯤 올라간 릴리스를 볼 일이 없고, VirusTotal 이 실패해도 링크만 빠진 채 공개된다.**
- **VirusTotal 은 서드파티 액션 대신 API 를 직접 부른다**(`release_tools.py virustotal`, 표준 라이브러리만). 비밀 키를 넘기는 코드를 남의 액션에 맡기지 않으려는 것이다. 큰 파일은 `/files/upload_url` 로 받은 주소에 올린다(설치기 약 134MB, 상한 650MB). 링크는 파일 해시 주소(`virustotal.com/gui/file/<sha256>`)라 분석이 끝나기 전에 열면 "결과 없음"이 잠깐 보일 수 있다.
- **`workflow_dispatch`**: 태그 없이 수동 실행하면 빌드·설치기·SHA-256 까지만 하고 결과를 Actions 아티팩트(3일)로 남긴다 — 첫 실행(빌드 시간·Inno Setup 설치 확인)을 릴리스를 만들지 않고 해 볼 수 있다.
- **Secrets 세 개**: `LUMIA_RECEIVER_URL`·`LUMIA_RECEIVER_TOKEN`(빌드 때 번들에 주입 — 없으면 "서버 전송이 꺼진 빌드"로 나간다), `VT_API_KEY`. 설정 방법은 README 릴리스 절.
- **rapidocr 를 `pyproject.toml` 의존성에 추가했다**(런타임에 쓰는데 빠져 있었다). 빌드 전용 `pyinstaller` 는 `build` extra.
- **패치노트 방식**: 루트 `CHANGELOG.md` 가 원본이다. **사용자가 주로 보는 곳은 앱 안**(옵션 → 정보·진단 → 버전 옆 "패치노트 보기", `GET /api/changelog`, 설치본에 `CHANGELOG.md` 동봉, 현재 버전 표시)이고, 같은 절이 GitHub Release 본문에도 쓰인다. (처음에는 todo 를 Release 본문용으로만 읽고 구현했다가 앱 안 표시를 뒤에 추가했다.) 버전마다 `## [x.y.z] - 날짜` 절을 쓰고(`새로 생겼어요` / `좋아졌어요` / `고쳤어요`, 화면에서 보이는 변화 위주), 그 절이 그대로 Release 본문 앞부분이 된다. 뒤에 SHA-256 과 검사 링크(+오탐 안내)가 자동으로 붙는다. 절이 없으면 릴리스 빌드가 **처음 단계에서** 실패한다(패치노트 없이 나가는 릴리스를 막는다). 자동 생성(커밋 메시지 → 본문)은 쓰지 않는다 — 커밋 메시지가 개발자용 서술이라 todo 의 "기술적인 것보다 내용 위주" 와 맞지 않는다.

### D14. 진단 정보 서버 전송

지금(D3·D8)은 옵션의 "진단 정보 zip 받기"로 파일을 만들고 사용자가 그 zip 을 직접 첨부해 보낸다([friend-guide.md](friend-guide.md)). 수신 서버([plan-infra.md](plan-infra.md))가 생기면 이 흐름을 앱이 서버로 직접 보내는 것으로 바꾼다.

- **버튼 하나로 전송.** 옵션 "정보·진단" 탭에 "진단 정보 보내기" 를 둔다. 누르면 **보낼 내용 미리보기**(로그 발췌·버전·해상도·코덱·판독 실패 통계, 닉네임·경로 속 사용자 이름 제거 후)를 보여 주고 사용자가 확인하면 전송한다. 성공하면 서버가 돌려준 **접수 번호**를 화면에 표시해 개발자에게 알릴 수 있게 한다.
- **사용자가 직접 누른 1회성 전송이므로 `telemetry.sendLogs`(자동·정기 전송) 값과 무관하게 동작한다.** 누른 순간에만 네트워크를 쓰고 그 뒤로 자동 전송이 켜지지는 않는다(D9 의 수동 업데이트 확인과 같은 원칙). `sendLogs` 를 켜 두면 D10 의 정기 전송이 따로 돈다.
- **표시용 짧은 ID.** 컨택·커뮤니티 대화에서 사용자가 자기 설치를 가리킬 수 있게, 기존 `telemetry.installId`(무작위 UUID, SPEC §7.11)에서 `LUMIA-7K3F-9QX2` 같은 짧은 표시용 ID 를 만들어 옵션 "정보·진단" 탭(복사 버튼)과 전송 완료 화면에 접수 번호와 함께 보여 준다. 접수 번호는 전송마다 새로 생기고, 이 ID 는 설치 하나에 계속 붙는다. 새 식별자를 만드는 것이 아니라 `installId` 의 표시 형태다.
  - **닉네임·계정과 앱이 자동으로 연결하지 않는다**(SPEC §7.11 원칙 유지). 사용자가 직접 알려야만 사람과 이어진다. 화면에 "커뮤니티 등에 이 ID 를 알리면 이 ID 로 보낸 데이터가 본인과 연결될 수 있습니다" 를 표시한다.
  - **삭제 요청은 앱 안의 전체 `installId` 로만 한다.** 짧은 ID 는 남에게 알려질 수 있어 삭제 권한으로 쓰면 남의 데이터를 지울 수 있다. 짧은 ID 는 개발자가 서버에서 문의를 찾는 용도로만 쓴다.
  - 서버는 전체 `installId` 로 구분하고 짧은 ID 는 표시용으로만 쓴다(짧게 줄이면 겹칠 수 있다).
  - 재설치하면 설정 폴더가 지워질 때 ID 가 새로 만들어진다(D6 제거 시 "설정·로그를 지울지 묻는" 동작과 같이 안내 문구에 적는다).
- 전송 항목과 개인정보 제거 규칙은 zip 과 같다(내용은 [§5](#5-동의-기반-업데이트-확인과-데이터-전송) "보내는 것"·"보내지 않는 것" 그대로). 영상·썸네일·결과표 이미지·화면 조각은 포함하지 않는다.
- **zip 내보내기는 없애지 않고 대안으로 남긴다** — 서버 장애·오프라인·전송 실패 때 사용자가 파일로 보낼 수 있어야 한다. 전송이 실패하면 "파일로 저장" 을 안내한다.
- **서버 쪽(2026-09-25 구현·배포 완료)**: `POST /v1/diagnostics` 가 진단 번들을 받아 접수 번호(`R-20260925-K7M3QX`)를 돌려주고 `installId` 로 묶어 저장하며, 삭제 요청에 포함되고 90일 뒤 자동 삭제된다. 요청·응답 필드는 [D10 전송 계약](#d10-라벨오류-로그-전송--서버-전송-계약)의 `DiagnosticBundle`.
- 문서 갱신: 구현과 같은 커밋에 [friend-guide.md](friend-guide.md) 의 "진단 정보 zip 받기 → 파일 보내기" 절차를 "진단 정보 보내기 → 접수 번호 알려 주기"로 바꾸고 README 에 적는다.
- 순수 로직(개인정보 제거, 미리보기 내용 구성, 접수 번호 표시)은 TDD, 완료 시 `npm run build`.

## 4. 라이선스 검토와 제외할 것

저장소를 공개하면 게임 화면에서 자른 이미지가 공개된다. 아래는 조사한 결과이고 **법률 검토가 아니다** — 공개 전에 이터널 리턴 운영사(님블뉴런)의 이용 약관·저작물 이용 지침을 직접 확인해야 한다(→ §7-1).

| 자산 | 위치 | 런타임 필요? | 제외하면 |
|---|---|---|---|
| 숫자·지역명·일차 라벨셋 원본 이미지(수백 장) | `data/templates/days/_samples/`, `data/templates/digits/2560x1440_samples/`, `data/templates/regions/_samples/` | **아니오** — 코드는 npz 만 읽는다(`profiles/models.py`) | 실행에 영향 없음. 단 `tests/test_shipped_templates.py` 가 `digits/2560x1440_samples` 를 읽으므로 그 테스트를 함께 정리(파일이 없으면 skip)해야 한다 |
| 라벨 파일 | `*_labels.jsonl` | 아니오(본보기 재생성 도구용) | 영향 없음. 재생성 도구(`build_templates.py`)를 쓸 개발자만 필요 |
| 본보기 `.npz` | `data/templates/{digits,regions,days}/*.npz` | **예** | 빼면 K/A·지역명·일차 판독이 꺼진다. 게임 글꼴 글자 조각이 들어 있어 잠재 쟁점이지만 원본 화면 이미지는 아니다 |
| 캐릭터 한글·영문 이름 | `data/characters.json` | 예 | 사실 정보(이름 대응표)라 낮은 위험으로 본다 |
| 스크린샷·영상 | (저장소 규칙상 커밋 안 함) | — | `.gitignore` 로 막혀 있으나 `!data/templates/**/*.png` 예외 규칙 때문에 `_samples` PNG 가 들어가 있다 |

**정리 방침**

1. 공개 저장소에서 `_samples` 이미지와 라벨 파일은 빼고 `.gitignore` 예외 규칙도 없앤다. **git 이력에도 남아 있으므로**(처음 들어간 커밋: `d30a33c` 숫자, `c2c5dd8` 지역명, `d4bef52` 일차) 공개 전 이력에서 지우거나(`git filter-repo`), 새 저장소로 옮겨 이력을 정리한다(→ §7-6). 원본 라벨셋은 개발 PC 에 따로 보관한다.
2. 설치본에는 `.npz` 와 프로필 JSON, characters.json 만 넣는다.
3. 우선은 npz 를 넣고 공개한다.
4. "제외하면 동작에 이상이 생기는가" → `_samples`·라벨 파일은 **아니다**. `data/templates` 를 읽는 테스트는 위 한 건뿐이다(나머지는 합성 fixture). 정리 후 전체 스위트로 확인한다.

해상도·UI 설정별 동작은 친구 배포로 확인한다. 배포본에는 다음이 갖춰져야 한다:

## 7. 확인 필요 (추측으로 메우지 않은 것)

2. ~~**LGPL ffmpeg 빌드의 H.264 인코더**~~ → **이 PC 에서 실측함(2026-09-24).** 소스: 실제 스팀 클립(HEVC 2560x1440 60fps 25Mbps) 앞 20초 → 1080p 프록시. 인코딩 시간은 인코더 차이가 없이 약 7초(2.8배속) — 병목이 HEVC 1440p60 **디코딩**이라 인코더 속도가 드러나지 않았다. 화질은 SSIM/PSNR(원본을 1080p 로 줄인 것과 비교).

   | 인코더 | 결과 | 크기(20초) | SSIM / PSNR | 비고 |
   |---|---|---|---|---|
   | `libx264` crf23 veryfast (GPL 빌드) | 됨 | 14.2MB | 0.936 / 29.4 | 기준. **LGPL 빌드에는 없다** |

   | `h264_qsv` | 실패 | - | - | `Error creating a MFX session`(Intel 없음) |

   - 프록시 만드는 시간은 원본 길이 기준 약 1/3 배속이라, 90초 클립이 약 30초다(진행 표시가 뜬다). 이 PC 는 디코딩이 병목이라 `d3d11va` 디코딩을 프록시에도 쓰면 줄어들 수 있으나 안 해 봤다.

## 9. D1~D4 구현 중 발견한 함정 (2026-09-24)

- **이 PC 의 녹화 폴더 최신 세션이 다른 게임이었다**(`bg_5075020_…`, `session.mpd` 없음). 해상도를 읽을 때 최신 폴더만 보면 실패하므로 이터널 리턴(앱 ID 1049590) 세션을 우선하고 `session.mpd` 를 못 읽는 세션은 건너뛴다(`recording_info.py`).
- **스팀 녹화 코덱 태그는 `hev1`** (`hev1.2.4.L123.B0`)이다. 브라우저 `canPlayType` 은 `hvc1`·`hev1` 둘 다 물어 하나라도 통하면 쓴다.
- **개발 PC 의 ffmpeg 는 GPL 풀 빌드**(winget)다. 이 PC 에서 테스트가 통과한다고 LGPL 빌드에서 통과하는 것은 아니다 — libx264·libx265 가 없어 테스트 원본을 못 만든다. 프록시 테스트는 그 경우 skip 하고, LGPL 빌드로도 실행해 확인했다(`LUMIA_FFMPEG=<lgpl ffmpeg> pytest tests/test_proxy.py tests/test_api_proxy.py`).
- **pytest 는 모듈 이름 `setup` 과 변수 이름 `setup_module` 을 nose 식 훅으로 취급**한다(`api/setup.py`·`import ... as setup_module` 이 `__code__` 오류를 냈다). 그래서 첫 실행 API 는 `api/onboarding.py`.
- **첫 실행에서 녹화 폴더가 없으면 `run()` 이 `SystemExit` 로 끝나 감시 스레드가 죽었다.** 트레이 토글은 `running=True` 로 표시해 죽은 걸 모른다. 지금은 10초마다 재시도한다.
- **UI 를 여는 스레드가 둘**(첫 실행 자동 열기, 두 번째 실행 신호)이 되어 `make_on_open` 의 서버 지연 시작에 락이 필요했다.
- **자르기 뒤 프록시**는 파일 mtime 으로 무효 판정한다(자르기가 원본을 교체). 삭제 시점에 지우는 대신 완전 삭제·휴지통 비우기·자동 정리에서 고아 프록시를 쓸어 낸다.
- **프록시 위치**: `paths.proxies` 설정은 쓰지 않고 `<클립 폴더>/.proxy` 고정(정리 함수들이 클립 폴더만 받는다). 다시보기 클립도 같은 규칙이라 `<vod 폴더>/.proxy`.
- **개발자 도구 주의**: 이번 세션에서 셸 heredoc 로 파이썬 파일을 만들 때 백슬래시가 절반으로 줄어드는 일이 있었다(`"Local\{name}"` → `Local\{name}`). 백슬래시가 든 코드는 Edit/Write 도구로 쓰고 결과를 확인할 것.
- **D5 에서 할 일(넘김)**: ffmpeg LGPL 빌드 exe 를 `vendor/ffmpeg` 에 포함(문서에 빌드 출처·소스 링크), `paths.resource_dir()` 이 `sys._MEIPASS` 를 가리키는지 빌드본에서 실제 확인, `procs.kill_children_on_exit` 가 PyInstaller 부트로더 프로세스 구조에서도 자식(ffmpeg)을 정리하는지 확인(부트로더가 부모-자식 2개 프로세스일 수 있다), `--noconsole` 에서 `sys.stderr` 가 `None` 일 때 `logging.basicConfig` 처리, 샌드박스에서 `h264_mf` 프록시·`videoWidth===0` 폴백 실측.

      <HostFolder>repo\dist</HostFolder>
      <SandboxFolder>C:\Users\WDAGUtilityAccount\Desktop\setup</SandboxFolder>
      <ReadOnly>true</ReadOnly>
    </MappedFolder>
    <MappedFolder>
      <HostFolder>H:\steam video\video</HostFolder>
      <SandboxFolder>C:\Users\WDAGUtilityAccount\Desktop\recordings</SandboxFolder>

- **빌드본에서만 서버가 안 떴다.** `--noconsole` 이면 `sys.stdout` 이 `None` 인데 uvicorn 의 기본 로깅 설정이
  `ColourizedFormatter` → `sys.stdout.isatty()` 를 불러 `AttributeError` → `Unable to configure formatter 'default'`
  로 서버 스레드가 죽는다. 트레이는 멀쩡히 뜨고 UI 만 영영 안 열려서 원인을 찾기 어려운 종류다.
  `uvicorn.Config(log_config=None)` 로 고쳤다. **D5 에서 넣은 스레드 예외 훅이 이걸 로그 파일에 남겨 줘서 찾았다** —
  훅이 없었으면 조용히 실패했을 것이다.
- **`pythonw.exe` 로 띄우는 것만으로는 `--noconsole` 을 재현하지 못한다.** 셸에서 실행하면 콘솔 핸들을
  물려받아 `sys.stderr` 가 살아 있다. `creationflags=DETACHED_PROCESS` 를 줘야 `stdout/stderr/stdin` 이 전부 `None` 이
  된다(실측). 콘솔 없는 동작을 테스트하려면 이 조합을 써야 한다.
- **PyInstaller 가 `--add-data` 안의 `.dll` 을 바이너리로도 분류한다.** `vendor/ffmpeg` 를 datas 로 넣었더니
  DLL 이 `_internal` 루트에 한 벌 더 복사돼 149MB 가 통째로 중복됐다(607MB → 452MB). 빌드 뒤에 직접 복사한다.
- **번들 ffmpeg 가 개발 환경 테스트를 깬다.** `vendor/ffmpeg` 가 생기면 `discover_ffmpeg()` 가 LGPL 빌드를
  먼저 고르는데, 합성 녹화 픽스처는 `libx264` 가 필요해 24개가 실패했다. `tests/conftest.py` 가 테스트에서만
  PATH 의 전체 빌드를 `LUMIA_FFMPEG` 로 지정하게 했다(제품 코드 탐색 순서는 그대로).
- **BtbN ffmpeg 는 shared 빌드가 훨씬 작다** — 정적 267MB vs shared 149MB(DLL 포함). 실측해서 shared 를 골랐다.
- **rapidocr 는 모델 5개를 받아 두지만 실제로 여는 것은 4개다**(korean/ch 인식, 방향 분류, v6 검출).
  안 쓰는 `PP-OCRv6_rec_small.onnx`(21MB)와 `cv2/opencv_videoio_ffmpeg*.dll`(31MB)을 뺐다 → 400MB, zip 178MB.
  뺀 뒤에는 반드시 `--selftest` 로 OCR 엔진이 여전히 뜨는지 확인한다.
- **`dist` 폴더를 셸의 작업 디렉터리로 들어가면 지울 수 없다**("Device or resource busy"). 빌드를 다시 하기 전에
  셸이 그 안에 있지 않은지 확인할 것.
- **Inno Setup 은 winget 으로 넣으면 사용자 영역**(`%LOCALAPPDATA%\Programs\Inno Setup 6`)에 깔린다.
  `Program Files` 만 보면 못 찾는다(`tools/build_installer.py` 가 두 곳 다 본다).
- **무인 제거에서 `MsgBox` 는 그대로 뜬다.** 설정 삭제 여부를 묻는 대화상자가 `/VERYSILENT` 에서 멈춰 버리므로
  `UninstallSilent` 를 확인해 건너뛴다.
- **앱이 실행 중이면 빌드본을 테스트할 수 없다.** 중복 실행 방지 뮤텍스는 개발 앱과 빌드본이 공유한다
  (의도한 동작이다). 빌드본을 확인하려면 개발 앱을 먼저 닫아야 한다.
- **첫 실행 화면을 한 번 마치면 `consent.version` 이 올라가 UI 가 자동으로 안 열린다.**
  `ui.startMinimized=true` 면 트레이로만 뜨므로, 그 뒤 테스트에는 `--open-ui` 가 필요하다(버그가 아니다).
- **셸 heredoc 백슬래시 함정은 이번에도 재발했다**(§9 에 이미 적어 둔 것). `.iss`·`.wsb` 처럼 백슬래시가 많은
  문서를 만들 때는 Write 도구로 파일을 쓰고 결과를 확인할 것.
