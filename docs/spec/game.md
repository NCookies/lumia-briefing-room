# 게임·녹화 — 확정 사실

> 설계가 기대는 외부 사실(게임 규칙, 스팀 녹화 포맷, 로그, 화면 요소 위치). 실측 절차는 [research.md](../research.md). 이 결론을 뒤집으려면 실측으로 한다.

## 1. 게임 구조

- 3인 1팀 배틀로얄. 3명이 전부 죽어야 게임이 끝난다.
- 부활: **2일차 밤까지 무료**, **3일차 낮부터 크레딧**.

```
phaseIndex = (일차 - 1) × 2 + (낮 0 / 밤 1)
무료 부활 구간 = phaseIndex ≤ 3,  크레딧 구간 = phaseIndex ≥ 4
```

- 한 페이즈(낮 또는 밤)는 대략 2.5~3분. 20분 매치면 4~5일차.
- `K` 는 항상 내 값이다(팀원 것으로 바뀌지 않는다). 내가 죽고 팀원이 살아 있으면 **팀원 시점 관전 화면**이 되고 UI 가 본게임과 다르다.
- 사망은 시점이 아니라 **구간**(사망 → 부활)이다.

### 게임 모드 — 둘 다 추출 대상

| | 배틀로얄 | 코발트 프로토콜 |
|---|---|---|
| 부활 | 조건부 | 상시 |
| 상단 UI | `N일 차` + 해/달 | `Phase N`(0=대기, 실측 0~3, 4 이상도 견뎌야 함) + 팀 점수 |
| 팀 점수 | — | 양 팀 40 에서 시작, 킬·점령마다 1씩 감소, 먼저 0 이면 패배 |
| 종료 화면 | `N/M 실험 종료`·`최종 생존` | `PROTOCOL COMPLETE` → `VICTORY`/`DEFEAT` → (가끔) 상세 패널 |
| 킬피드 | — | 좌하단 한글 로그(쓰지 않음), 우측 킬로그(쓰지 않음) |
| TK/K/A·초상화 좌표 | 기준 | 스팀 녹화(2560x1440)에서는 **배틀로얄과 같은 자리**. 치지직 VOD(1920x1080)에서는 ~80px 왼쪽·3px 위 — 소스(재인코딩) 차이다 |

- 코발트 `Phase 0` 은 HUD 가 뜬 대기 상태(TK/K/A 0, 점수 40:40).
- 코발트 결과 상세 패널은 매 판 뜨지 않는다(배틀로얄의 "결과 화면 없는 판"과 같은 급).

## 2. 외부 데이터 — 쓰지 않는 것

- **BSER 공식 API 를 쓰지 않는다.** 매치 단위 집계뿐이고 지원이 열악하다. 배포·키 관리 부담도 있어 재검토(2026-09-21)에서도 유지. 화면 인식만으로 하고 못 읽으면 비운다.
- **Steam 타임라인 마커 없음.** `timelines\*.json` 엔 `screenshot` 뿐. 게임이 `ISteamTimeline` 미지원, 주입은 안티치트 문제로 제외.
- **클라이언트 킬 로그 없음.** `Player.log` 에 kill/death/damage/assist 이벤트가 없다.

## 3. `Player.log` — 매치 경계 (파이프라인 트리거)

`%USERPROFILE%\AppData\LocalLow\NimbleNeuron\Eternal Return\Player.log` (직전 실행은 `Player-prev.log`)

```
[LEVEL][HOSTNAME][YYYY-MM-DD HH:mm:ss,SSS][thread][Class:Method:Line] message
```

| 이벤트 | 라인 |
|---|---|
| 매치 로딩 시작 | `[LoadingView:Show:194] [PROFILE TIME][LOADING][GAME]` |
| 로비 복귀(매치 종료) | `[LoadingView:Show:135] [PROFILE TIME][LOADING][LOBBY]` |
| 게임 시작·페이즈 | `[ClientService:StartGame:…]`, `OnUpdateGamePlayPhase : Briefing\|StartCountdown\|PlayGame` |

- GAME ↔ LOBBY 가 1:1 교대, 누락 0(실측 19판). 실시간 flush.

**게임 경계는 캐릭터 선택부터다**(`playerlog.extract_matches`, 2026-09-30 실측). 한 게임은 로그에서 이렇게 이어진다.

| 순서 | 화면 | 로그 |
|---|---|---|
| 1 | 로비 "매칭 중" | `matchingNotification : StartMatching` |
| 2 | **캐릭터 선택**(로비 장면 안) | `MatchingComplete, matchPadding.userCount : N` |
| 3~4 | 루트 선택, "잠시 후 실험이 시작됩니다" | (없음) |
| 5 | 로딩 | `[LOADING][GAME]` (2번에서 약 80초 뒤) |
| 6 | 브리핑 룸 → 본게임 | `OnUpdateGamePlayPhase : Briefing → StartCountdown → PlayGame` |
| 7 | 결과 화면 → `나가기` | `[LOADING][LOBBY]` |

- 시작 = `[LOADING][GAME]` 직전의 **마지막** `MatchingComplete`. 사이에 `StartMatching` 이 다시 있으면 앞의 것은 닷지라 버린다. 없거나 5분 넘게 앞서면 `[LOADING][GAME]` 이 시작이다. 끝 = `[LOADING][LOBBY]`.
- `MatchBoundary.start_utc` 가 이 넓힌 시작, `loading_utc` 가 `[LOADING][GAME]` 시각이다. **처리 이력 키(`match_key`)는 `loading_utc`** 라서 경계를 넓히기 전 이력과 맞는다. 옛 클립의 `matchStartUtc` 는 `loading_utc` 와 같은 값이라 다시 분석(`find_match_end`)은 둘 다 본다.
- **연습 모드는 게임이 아니다**: 직전 `GlobalUserData:SetMatchingMode ... Invoked: Practice` 이거나 게임 구간 안에 `"matchingMode":"Practice"`(battleGameInfo) 가 찍힌 `[LOADING][GAME]`~`[LOADING][LOBBY]` 쌍은 버린다(실측 3분 24초). 사용자 설정 게임은 넣는다.
- **시각은 로컬 타임존**이다(녹화는 UTC).
- `GameResultTeamPlayerSlot` 은 프리메이드일 때만 찍힌다 — 종료 마커로 쓰지 않는다.
- 로그의 낮/밤(`SetDayNight input=Day|Night`)은 누락이 심해 **쓰지 않는다**. 로그에 게임 모드 문구도 없다.
- 로그는 최근 게임 실행 2번 분량만 남는다 → 그보다 오래된 경기는 화면으로 찾는다([pipeline.md §6](pipeline.md)).

## 4. 스팀 백그라운드 녹화 포맷

```
<BackgroundRecordPath>\video\bg_<appid>_<YYYYMMDD>_<HHMMSS>\   ← UTC
    session.mpd
    init-stream0.m4s / init-stream1.m4s        영상/음성 트랙 정의
    chunk-stream0-NNNNN.m4s  (~8.9MB, 3.000초)  영상
    chunk-stream1-NNNNN.m4s                     음성
    *.m4s.tmp                                   기록 중
```

- 녹화 경로: `Steam\userdata\<id>\config\localconfig.vdf` 의 `GameRecording.BackgroundRecordPath`. **계정이 여러 개일 수 있어 전부 훑는다.** 미설정이면 `userdata\<id>\gamerecordings`.
- 이터널 리턴 앱 ID `1049590`. 녹화 폴더에 다른 게임 세션도 섞이므로 이 앱 ID 만 본다(`session.mpd` 가 없는 세션은 건너뜀).
- 조각 번호는 세션마다 1부터, 세그먼트 = **정확히 3.000초 = 키프레임 1개**.
- **init + chunk 1개만으로 독립 디코딩된다.** init 없이 chunk 만으로는 실패(`could not find corresponding trex`).
- 녹화 중에도 완료된 조각은 읽을 수 있다(`.tmp` 제외).
- 번호에 **구멍이 있으면 이어붙여 디코딩하면 깨진다**(fMP4 오프셋) — 연속 구간별로 따로 디코딩한다.
- ffprobe 의 `Duration` 은 세션 전체 길이라 틀리다.
- **원본은 절대 수정하지 않는다.**

| 영상 규격(개발 PC) | 값 |
|---|---|
| 코덱 | HEVC Main, 태그 `hev1`, B프레임 없음 |
| 해상도 | 2560x1440 — **고정값 아님. `session.mpd` 의 width/height 로 읽는다** |
| fps / 비트레이트 | 60.02 / 약 15.7~25.5 Mbps (분당 약 190MB, 2026-09-29 클립 32개 실측) |

스팀 UI 로 export 하면 1080p 로 줄어든다. 원본 `.m4s` 를 직접 읽으므로 원본 해상도를 얻는다.

## 5. 시간 매핑

```
세그먼트 N 시작(UTC) = 세션시작(UTC) + (N - 1) × 3.000초
세션시작 = 폴더명 bg_<appid>_<YYYYMMDD>_<HHMMSS>   (1차, 항상 유효)
         = session.mpd availabilityStartTime       (녹화 중 세션만)
Player.log 는 로컬 시각 → UTC 로 바꿔 쓴다
```

`Player.log` 첫 줄과 `availabilityStartTime` 이 초 단위로 일치(게임 클라이언트가 뜰 때 녹화 시작). 종료된 세션은 `type="static"` 이 되고 `availabilityStartTime` 이 사라진다 → 폴더명이 1차.

## 6. 링버퍼

- 전역 설정 하나. 개발 PC 120분(`timeShiftBufferDepth="PT2H0M0.0S"` 와 일치). 새 녹화만큼 **앞에서부터 깎는다**(분석 도중에도, 실측 801→616 세그먼트).
- 버퍼 길이 인식 순서: `session.mpd` `timeShiftBufferDepth` → `localconfig.vdf` 의 `GameRecording.PerGameSettings.<appid>.minutes`(세션 폴더명에서 appid 추출) → 120분.
- **"세션 폴더가 있으니 조각도 있다"는 가정은 틀린다.** 번호로 접근하기 전에 항상 존재를 확인한다.

## 7. 화면 요소 (2560x1440 기준 좌표)

전체 ROI 는 `src/lumia_briefing_room/profiles/builtin/2560x1440.json` 이 원본이다. 아래는 설계에 영향을 주는 성질만.

### 좌하단 초상화 — 핵심 신호

| 요소 | ROI | 성질 |
|---|---|---|
| 배지 | `680..732, 1395..1440` | 평상시 레벨 숫자 원(파랑/노랑/**초록** — 매치·레벨마다 다름), **교전 중 주황 교차 칼**(애니메이션) |
| 얼굴 | `690..860, 1250..1400` | 사망 시 채도 절반·밝기 1/3, 중앙에 부활 카운트다운 |

- 배지 교전 판정: 선명 픽셀(`V≥90, S≥60`) 중 주황 ≥ 100(평상시 0~21, 교전 138~773). 주황/노랑은 **녹색 채널로 가른다**(`G < R×0.80`). 배지 존재는 주황+노랑+파랑+초록 ≥ 250.
- **배지는 전투 상태일 뿐 교전이 아니다** — 야생동물 사냥에도, 대기방에서도 똑같이 켜지고, 구도 잡기·거리 벌리기 중엔 꺼진다.
- 사망 국면: 초상화 **빨강**(0%→71.5%, 계단형) → 화면 암전 램프(3.5~5초, HUD 는 회색화 안 됨) → **캐릭터 UI 소멸(관전)**.

### 상단 HUD

| 요소 | 성질 |
|---|---|
| `TK` / `K` / `A` (`y 31..47`) | TK=팀 킬, K=내 킬, A=어시스트. 불투명 배경판이 없어 **해시·정확 매칭 불가 → 상관 매칭**. 자릿수가 늘면 **필드 중심 기준 좌우 확장**(다른 필드는 안 밀림). 새 숫자는 0.15초 알파 페이드인 — 높은 휘도 임계는 전환 직후를 놓친다 |
| 일차 `N일 차` 숫자(`1129..1144, 6..32`) | 흰/크림 글자. 후반(6~8일차) 빨강 배경 |
| 해/달 아이콘(`1145..1185, 30..58`) | 해=노랑, 달=보라. 바가 반투명이라 밝은 주황 배경에서 낮에도 보라가 잡힌다 → **큰 쪽 비교** |
| 시계 | 대기방에서는 `00 : 00` 에 멈춰 있다 |
| 버프/디버프 줄 | 화면 최상단 중앙, 날씨 박스(`x≈970`) 왼쪽으로 아이콘당 ~80px |

로비 화면에도 같은 영역에 흰 아이콘(지구본·메일·톱니)이 있으나 흰 픽셀 수로 쉽게 배제된다.

### 우측 — 팀 패널·미니맵

| 요소 | ROI | 성질 |
|---|---|---|
| 팀 슬롯 체력바 1·2 | `2112,1228,2170,1244` / `2112,1365,2170,1381` | 초록=생존, **주황=사망**(리스폰 대기) |
| 팀원 초상화 링 1·2 | `2100,1165,2180,1225` / `2100,1302,2180,1362` | 전투 중 **원 바깥으로 번지는 붉은 후광**. 얼굴 원화 빨강(빨간 머리 캐릭터, 데비&마를렌 등)과 섞인다 |

### 스킬바

- 전체 `880,1290,1300,1365`, 궁극기 `R` 칸 `1100,1298,1160,1358`.
- `R` 준비=원래 색, 쿨타임=파르스름한 반투명 오버레이 + 흰 숫자, **미투자(잠김)=빨간 X + 어두움**.
- 캐릭터마다 `R` 원화의 파란기 기준선이 다르다(절대 임계 불가).

### 결과 화면·팀 소개 화면

- 배틀로얄 결과 화면(나가기 전 항상 뜸): 좌측 패널 `result_panel [300,450,1000,1080]`, 모드 칩 `result_chip [335,625,600,675]`(파란 알약 = 랭크). 순위 `N/M`, 결과 문구, 닉네임, `TK K D A`. 랭크만 뒤에 `RANK POINT` 화면이 더 있다. 결과 화면 TK 와 순위표 TK 는 다를 수 있다(게임이 그렇게 보여준다).
- 스트리머는 탈락(`ELIMINATED`) 뒤 결과 화면을 안 보고 넘어가기도 한다 → "결과 화면 없는 판"이 정상 케이스.
- 로그의 로비 복귀 시각은 결과 화면 직후라, 결과 화면은 종료 세그먼트와 같거나 1칸 뒤, 순위표 탭은 5칸 뒤에 나온다.
- **캐릭터 선택·루트 선택 화면 판독**(`detect/select_screen.py`, ROI `select_timer` `1225,30,1335,95` + `select_title` `35,74,265,108`): 두 화면이 같은 머리띠를 쓴다 — 좌상단 `PAGEn 캐릭터/루트 선택`(어두운 바탕 위 회색 글자), 상단 가운데 시안색 남은 시간 숫자. 시안 픽셀 ≥ 5% 이고 제목 칸의 밝은 회색 픽셀 9~20%·평균 밝기 40~65 이면 선택 화면이다. 실측(스팀 녹화 `bg_1049590_20260929_151520`, 899프레임): 선택 화면 3덩어리(연습·본게임 2)에서만 켜지고 오탐 0, 본게임 덩어리 안에서도 몇 프레임(로딩 전환 등)은 놓친다 → 덩어리 잇기에 15초 틈을 허용한다. 캐릭터 선택 시작 직전 2프레임은 "매칭이 완료 되었습니다" 팝업이라 시작은 최대 3초 늦다. 캐릭터 선택 ~60초 → 루트 선택 → 로딩 순으로 이어지고, 인게임 첫 프레임은 선택 화면이 끝난 뒤 약 24초 뒤다. 연습 모드도 같은 머리띠를 쓰고 모드 글자만 `PRACTICE` 다: ROI `select_mode` `1430,38,1620,62` 의 하늘색 글자 마스크를 `PRACTICE` 기준 마스크와 IoU 로 비교한다(연습 0.985~1.0, `NORMAL GAME` 0.14~0.15 실측, `RANK GAME` 은 표본 없음). 선택 화면 덩어리의 과반이 연습이면 그 게임은 화면 경로에서도 제외한다(`GameSpan.practice`, 백필 창에서 뺌).
- **팀원 카드 막대**(1920x1080 만, ROI `select_card1~3` `962/1246/1530,952,+241,967`): 선택 화면 두 페이지 모두 아래쪽 팀원 카드 3장 밑에 6px 팀 색 막대(칸마다 파랑·초록·노랑 등)가 있고 바로 아래는 무채색이다. 세 칸 모두 막대(위 40%) 채도 픽셀 ≥ 80%·아래(47%~) ≤ 10% 면 선택 화면이다(`is_select_screen` = 머리띠 또는 막대). 방송에서 선택 화면 동안 왼쪽 위에 다른 게임 창을 띄워 머리띠가 가려지는 판이 많아서다. 실측(치지직 1080p 5시간, 키프레임 17606장): 13판 모두 게임 시작 79~82초 앞부터 잡히고 인게임 오탐 0. 연습 모드 판정은 여전히 머리띠의 모드 글자라 가려지면 못 거른다. 2560x1440 은 표본이 없어 머리띠만 본다.
- **루트 선택 화면**(우측 아래 팀원 카드 3장)이 캐릭터 초상화의 출처. `matchStartUtc` 보다 **최대 22초 앞**에 떠 있는 경기가 있다.
- 로딩 화면의 8스쿼드 카드는 내 자리가 경기마다 달라 쓰지 않는다.

## 8. HEVC 재생

- HEVC 는 특허 때문에 Windows·브라우저에 기본 내장되지 않는다. 개발 PC 는 OEM 무료판 `Microsoft.HEVCVideoExtension`(단수, 스토어에서 재설치 불가 — 지우지 말 것)이 있어 WebView2/Edge/Chrome 에서 재생된다.
- Playwright 번들 Chromium 은 HEVC 를 못 그린다(화면 검정, `videoWidth 0`). 확인은 설치된 Edge/Chrome 으로 한다.
- 실제 스팀 녹화는 **Main10**(`hev1.2.4.L123.B0`)이다(앞의 "Main" 은 프로파일 이름이 아니라 코덱 문자열 `hev1.<프로파일>.…` 의 `2` = Main10). 브라우저가 Main 은 되고 Main10 은 안 되는 경우가 있어, 앱은 시작 때 `canPlayType`(Main·Main10 따로)과 `MediaCapabilities.decodingInfo`(Main10 2560x1440 60fps → 지원·부드러움·저전력=하드웨어)를 재서 환경 정보(`hevcProbe`)에 싣는다.
- **오류 없이 검게 나오는 경우**(`loadedmetadata` 때 `videoWidth === 0`)가 있다. 풀영상 화면은 이 경우와 `error` 이벤트를 안내 문구로 보여 주고, `POST /api/client-events/playback-failure` 로 알려 오류 기록(`lumia_briefing_room.playback`)에 남긴다(같은 내용은 앱을 켠 동안 한 번만). 풀영상은 클립과 달리 프록시 폴백이 없다.
- 디코더는 재배포할 수 없다 → 재생 불가 PC 는 H.264 프록시로 폴백([ui.md](ui.md), [deploy.md](deploy.md)).
