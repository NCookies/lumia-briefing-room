# 열람 UI

> 코드: 백엔드 `src/lumia_briefing_room/api/`, 프론트 `frontend/src/`. **`frontend/src` 를 고치면 같은 작업에서 `npm run build` 로 `frontend/dist` 를 갱신한다**(`run.bat` 은 빌드된 정적 파일만 띄운다).

## 1. 스택과 실행 구조

- **React + TypeScript + Vite + Tailwind** → 정적 빌드 → FastAPI 가 서빙(`api/static.py`, 라우트를 먼저 등록하고 `Mount("/")` 를 나중에). 무거운 컴포넌트 라이브러리·상태 관리 라이브러리는 쓰지 않는다.
- 셸: 트레이 경로는 **기본 브라우저**(pystray 와 pywebview 가 메인 스레드를 다툰다). `cli.serve` 독립 실행만 pywebview(WebView2) 창을 시도하고 실패하면 브라우저. Electron 은 쓰지 않는다(RAM 150~300MB).
- 서버는 `127.0.0.1` 에만 바인드. 접속 주소 **`http://lumia-briefingroom.localhost`**(Chromium·Firefox 가 `*.localhost` 를 루프백으로 푼다, hosts 불필요). 포트 후보는 고정 순서 **80 → `ui.port`(8765) → +20** — 포트가 바뀌면 origin 이 바뀌어 localStorage(볼륨·탭·"다시 묻지 않기")가 초기화되기 때문이다. `ui.port=auto`(옛 값)는 8765 와 같다.
- 설정 API 는 매번 설정 파일을 다시 읽는다(감시가 학습한 닉네임을 메모리 사본이 덮어쓰지 않게).
- 앱 모드(`appmode.resolve_mode`, `app.mode`): 빌드본 = `release`, 소스 = `dev`. `release` 에서는 튜닝용 화면(클립 ID, 교전 점수 칩·슬라이더, 근거 상세)과 관리자 탭을 숨긴다. `GET /api/app-info` 로 모드·버전을 내려준다. 헤더 제목 옆에 버전(`v0.1.x`, dev 는 `(dev)`).
- 프론트 테스트: 순수 로직 모듈(`grouping.ts`·`timeline.ts`·`labeling.ts`·`cleanupPreview.ts`·`vodDates.ts` 등)만 Node 내장 러너로 TDD(`npm test`). 화면은 실제 브라우저로 확인한다.

## 2. 화면 구성

- 상단 탭 **`스팀 녹화` | `영상 파일` | `클립`**(개발 모드는 `관리자` 탭 추가). `클립` 탭(`ClipArchive`)은 보관한 클립을 카테고리별로 보는 화면이다 — 아래 "클립 탭". 선택 탭·열린 풀영상·카테고리는 주소(해시)가 정하고(아래 "화면 주소") 마지막 탭만 localStorage(`lumia.tab`)에 기억한다. **탭마다 필터·정렬·펼침·보기 모드가 독립**이다. 플레이어의 이전/다음은 현재 탭 목록 안에서만.
- **날짜 머리줄**(`gameDays.ts`·`GameDayHeader`): 게임 목록을 **자정 기준** 로컬 날짜로 나누고 `9월 30일 (수) · 오늘` + 게임·클립 수·용량을 적는다. 스크롤해도 위에 붙어 있다(sticky). 정렬 순서를 그대로 따르고, 시각을 모르는 게임은 맨 뒤 `날짜 모름`. 밤샘 세션도 자정에서 나눈다(사용자 결정 — 새벽 5시 기준안은 채택 안 함). **영상 파일 탭**도 같은 머리줄을 쓴다(`vodDates.groupVodsByDate`): 영상 날짜(`videoDate`)로 영상 묶음을 나누고 `영상 N개 · 게임 · 클립 · 용량` 을 적는다. 날짜 순서는 정렬 방향을 따르고(영상 목록은 원래 이름순이라 날짜로 다시 묶는다), 한 날짜 안은 이름순, 날짜 없는 영상은 맨 뒤 `날짜 모름`.
  - **접기**(`dayFold.ts`·`useDayFold.ts`, 두 탭 공통): 머리줄을 누르면 그 날짜 목록이 접히고(머리줄 한 줄은 남음, `▼/▶`) `날짜 모두 펼치기/접기` 버튼이 있다. 접힌 날짜는 탭마다 localStorage(`lumia.collapsedDays.<탭>`, 접근은 try/catch)에 저장하고 저장된 적 없는 새 날짜는 펼쳐진다. 날짜 바로가기 줄은 뺐다(머리줄 접기로 충분). 옛 영상 파일 탭의 날짜 칩 거르기(`filter.dates`)는 없앴다. 한 번에 한 날짜만 보이는 이동기는 채택하지 않았다.
- **게임 행**(`GameSection`, dak.gg 식 접이식): 순위(1위 초록 막대)·모드·시작 시각/경과·초상화 3장(`PortraitRow`, 코발트는 그리지 않음)·TK/K/A·클립 수·총 용량. 코발트는 `#N위` 대신 `승리`/`패배`, 그 아래 회색 `코발트`. ▾ 로 펼치면 첫 칸 결과표 썸네일(`ResultCard` → 확대 뷰어, ←/→ 로 이전/다음 게임 결과표) + 클립.
- 게임 묶음은 `sessionDir + matchStartUtc`(VOD 는 영상 → 게임). **정렬은 게임 순서에만** 적용(최신 순 기본 / 오래된 순 / 교전 가능성 = 게임의 최고 `pvpScore`), 게임 안 클립은 항상 오름차순. 정렬은 프론트에서 하며 API `sort` 는 쓰지 않는다.
- 클립이 다 지워진 게임은 게임 기록(`GET /api/games/records`)으로 "클립 삭제됨" 행이 된다(필터가 켜지면 숨김).
- **보기 모드** `카드 | 일자 타임라인`(라벨 `보기`). 타임라인은 `phaseIndex` 칸(1일차 낮·밤…)을 가로로 놓고 무료 부활/크레딧 경계를 표시, 교전 없는 페이즈도 칸을 그린다.
  - `phaseIndex` 가 없는 클립은 게임 경과 시간 ÷ `PHASE_LENGTH_SEC`(165초)로 칸을 추정해 **점선 테두리 + 툴팁**으로 구분. 그것도 못 하면 맨 끝 `시점 미상`. VOD 는 `combatStartOffsetSec − gameStartOffsetSec`.
  - 코발트 게임은 `cobaltPhase` 칸(`buildCobaltPhaseColumns`).
- **필터 바**: 태그(서버에서 **OR**), 게임 모드, 라벨 상태, 교전 가능성 하한(맨 왼쪽 `전체`), 고정만, 제목 검색(`q`, 대소문자·공백 무시 부분 일치, 0.3초 디바운스, 메모는 대상 아님), `삭제 예정만 보기`, VOD 날짜 칩, 영상 파일 탭 새로고침.
- **빈 화면**(`emptyState.ts`): 가운데 문구 + 스팀 탭 "과거 녹화 분석", 영상 파일 탭 "영상 경로 추가". 목록을 아직 못 받았으면 빈 문구를 띄우지 않는다. 비활성 버튼은 `title` 로 이유를 말한다.
- **활동 표시**: `GET /api/activity` 를 3초마다 읽어 헤더 아래 막대(감시의 게임 분석, 과거 녹화 분석, 다시 분석). 작업 중엔 5초마다, 끝나는 순간 한 번 목록을 깜빡임 없이 다시 읽는다. 다시 분석 중인 게임 행은 파란 테두리·불확정 막대. 감시 실패는 상단 빨간 배너 + "계속하기". 저장 공간 부족·풀영상 저장 실패는 그 아래 노란 배너(`NoticeBanner`, `GET /api/notices` 를 10초마다, "닫기" = dismiss).
- **첫 실행 화면 저장 공간 안내**: 설정 단계에서 "게임 하나에 2~5GB 가 저장됩니다. 50~100GB 여유 공간을 확보하고 사용하세요." 를 큰 글씨 경고 상자로 두고, 저장 폴더 드라이브의 현재 여유 공간(`disk`)을 보여 준다(50GB 미만이면 빨강). **"확인했습니다"를 켜야 `시작하기` 가 눌린다**(동의 항목만 다시 묻는 경우는 제외).
- **삭제 예정 표시**: 자동 정리가 켜져 있으면 대상 클립·게임 행(전부 대상일 때)·타임라인 블록에 빨간 테두리 + "N일 후 삭제 예정"/"한도 초과로 삭제 예정" 배지(툴팁 "현재 기준 예상"). 고정하면 사라진다. 스팀 탭만.

## 3. 플레이어 (`PlayerModal`)

- 좌우 큰 이전/다음 버튼(끝에서 비활성), 삭제(후 다음 클립으로), 저장(내보내기), 자르기. **닫기는 닫기 버튼·ESC 만** — 배경 클릭으로 닫으면 자르기 작업이 날아간다(결과표 뷰어도 같음).
- 방향키 ←/→ = **재생 위치 ∓5초**(클립 이동 아님). 저장 창이 떠 있는 동안 단축키 정지.
- 볼륨·음소거는 localStorage(영상마다 `<video>` 가 새로 만들어진다).
- 영상/썸네일 URL 에 `?v=길이` 를 붙여 자르기 뒤 캐시를 깬다.
- 창이 넘치면 잘리지 않고 스크롤(`playerLayout.ts` 가 라벨 컨트롤 높이를 반영).
- **재생 폴백**: 시작 시 `canPlayType`(`hvc1`·`hev1` 둘 다) + 첫 재생 `videoWidth === 0`/오류면 HEVC 불가로 보고 클립별 **H.264 프록시**로 자동 전환(`POST/GET /api/clips/{id}/proxy`, 진행률 표시). 프록시 모드면 현재 클립이 준비되면 다음 클립 1개를 미리 만든다(`?prefetch=1`, 서버 `PriorityGate` 는 직접 요청을 먼저, 실행 중 작업은 끊지 않음, `encode.proxy.prefetch`). 대기 화면에 선택적 코덱 설치 안내(유료 스토어 링크, 무료 제조사판은 검색 안내, 자동 설치 안 함). 프론트가 판별 결과를 `POST /api/client-capabilities` 로 알린다(환경 정보용).
- **라벨링**: `교전`/`그 외` 버튼, 키 `1`/`2`/`0`(해제). 라벨을 붙여도 **다음 클립으로 자동 이동하지 않는다**(메모를 쓰려면 머물러야 한다). 메모(`labelNote`, 500자, 텍스트만, 라벨 해제 시 함께 지움) — 라벨링을 켜면 라벨 전에도 보이되 비활성. `(?)` 도움말(무엇을 보내고 안 보내는지). **라벨링 UI 는 어떤 모드에서도 숨긴다**(`showLabelingUi` 가 늘 거짓 — 처음엔 개발 모드만 보이게 했다가 당장 쓸모가 없어 개발 모드도 껐다. 라벨 재설계 전까지, plan §3). 전송은 UI 와 무관하게 `telemetry.sendLabels` 가 정해 이미 붙인 라벨은 그대로 보낸다. 이 절의 `PlayerModal` 은 옛 카드 뷰만 쓴다 — 클립 탭은 `ClipViewer`.

### 자르기·분할 (`pipeline/trim.py`, `TrimPanel`)

- 구간 1개: `POST /api/clips/{id}/trim` — `ffmpeg -ss S -to E -i clip.mp4 -map 0 -c copy` 로 임시 파일 → `os.replace`(실패 시 원본 유지). MP4 편집 리스트로 시작 프레임이 정확하다. `durationSec`/`videoOffsetSec` 갱신, `trimmed`·`originalDurationSec`. 보이지 않는 프리롤(최대 3초)이 파일에 남는 게 무재인코딩의 대가.
- 구간 2개 이상: `POST /api/clips/{id}/split` — 구간마다 새 클립(`<원본>-pN`, `splitFrom`, 라벨은 비우고 자동 근거는 복사), 원본은 설정 삭제 방식으로. 구간은 겹칠 수 없고(서버도 400) 최소 1초. 하나라도 실패하면 만든 조각을 지우고 원본 유지.
- 자르기 시작 위치 = 현재 재생 위치.

### 내보내기

- 서버가 Windows 탐색기 선택 창을 띄운다(`POST /api/fs/pick-folder`, VOD 파일은 `pick-videos`, `native_dialog.py`, 전경 창 소유). 브라우저가 로컬 경로를 못 다루기 때문. 옛 `/api/fs/dirs`·`mkdir`·`videos` 는 남아 있지만 프론트는 안 쓴다.
- `POST /api/clips/{id}/export`: 같은 이름이면 `(2)`, 고른 폴더를 `paths.exportDefault` 로 기억.
- 디스코드 10MB 용 재인코딩은 실험 후 접었다(720p 이하로 뭉개져 닉네임이 안 읽힘). 다시 하려면 인코딩 말고 다른 방법부터. 외부 호스팅 자동 업로드는 "영상은 밖으로 보내지 않는다" 원칙과 충돌.

## 4. 게임 단위 동작

- 게임 단위 삭제(클립 삭제와 같은 확인 창), 게임 기록은 `retention.keepGameRecords` 대로 서버가 남긴다.
- **다시 분석**(`POST /api/games/reprocess`, 한 번에 하나 — 동시 요청은 지금 409).
- **수동 보정**: 순위 배지 옆 `✎` → 순위·결과 문구 입력 → 그 게임의 모든 클립에 `PATCH /api/clips/{id}`(`matchResult` 의 `placement`/`outcome` 만, `matchResultSource="manual"`). 잠금 해제는 `matchResultSource: null`(값은 유지). 캐릭터 보정은 후보 목록이 없어 만들지 않았다.
- 제목 수정: 카드·플레이어 `✎`/더블클릭. (이 수동 보정은 옛 카드 뷰 전용이다. 새 게임 목록·풀영상 화면은 게임 단위의 `게임 정보 수정하기`를 쓴다 - 아래 스팀 녹화 탭 절)

## 5. 삭제 확인 창 (`DeleteConfirmDialog`)

- "정말 삭제하시겠습니까?" + 체크박스 `다시 묻지 않기`(`ui.confirmDelete`) · `휴지통으로 보내지 않고 영구 삭제하기`(`ui.deleteMode`). 옵션 화면과 같은 값이다.
- 휴지통으로 보낼 때: "Windows 휴지통에서 되살릴 때는 클립의 파일(영상·정보·썸네일)을 모두 복원해야 이 앱에서 다시 볼 수 있다"고 안내(클립 = 여러 파일).
- 영구 삭제 + 다시 묻지 않기 조합은 저장 전에 한 번 더 경고.

## 6. 옵션 모달 (`SettingsModal`)

탭: 일반(닉네임, 자동 시작, 저장 폴더(`StorageSection` - 새 구조는 저장 폴더·폴더 구조 설명·고급 풀영상 위치·되돌리기, 이전 버전 사용자는 쓰던 폴더 목록과 "새 구조로 옮기기"), 클립 저장 방식, 재생 — 프록시 미리 만들기, 삭제 확인) / 클립 내보내기 / 스팀 녹화(스팀 녹화 폴더 - 입력 소스) / 영상 파일(영상 경로 - 입력 소스) / 자동 정리 / 정보·진단. 입력 소스 설정은 화면 위쪽 탭과 같은 이름의 옵션 탭에 하나씩 있다.

- **클립 보관 방식**(일반, `clip.saveMode`): 자동 보관(기본)/직접 보관 라디오. 고르는 즉시 `PUT /api/config` 로 저장하고 이미 보관한 클립에는 영향이 없다. 자동 옆에 "보관한 클립은 자동으로 지워지지 않아 게임마다 1.5~2GB 씩 쌓입니다" 안내.
- **자동 정리**: 켜기 + 기준별 체크박스(N일 지난 / N개 초과 / N GB 초과, 체크 해제 = `null`), 삭제 방식, 보호(고정·태그), 미리보기·즉시 실행. 끄면 기준들이 비활성. "게임 기록 유지"는 수동 삭제에도 적용돼 별도 구역. **켤 때마다 경고 창**(방식에 따라 "영구 삭제됩니다"/"휴지통으로 보내집니다"). `지우기 전에` 체크박스(`retention.preserveBeforeDelete`)는 자동 정리를 끄면 다른 기준처럼 회색. "저장 후 정리 대상 확인"·"지금 정리" 결과에 남길 클립 수·클립을 못 남겨 보류한 수가 붙는다.
- **영상 파일**: 경로 추가(파일/폴더), 하위 폴더, 원본 삭제(`매번 묻기`/`항상`/`안 함`, 방식, 항상+영구는 경고). 지원 확장자 `(?)` — `.mp4` `.mkv` `.ts` `.webm` `.mov`, 확인된 것은 `.mp4` 뿐이라고 적는다. 목록은 `video_formats.py` 한 곳 → `GET /api/app-info` `videoFormats` 로 내려준다.
- **정보·진단**: 버전·패치노트(`GET /api/changelog`)·업데이트, 선택 기능(동의 항목), 전송 상태·미리보기·삭제 요청, 진단 정보 보내기/zip, 표시용 ID, 개인정보 처리 안내([deploy.md](deploy.md)).

## 스팀 녹화 탭 = 게임 목록 → 풀영상 (F4·F4-b, 새 컴포넌트 `GameList`·`GameViewer`·`ViewerBar`·`ViewerCandidates`)

"스팀 녹화" 탭은 게임 목록이고 게임을 열면 풀영상 화면(← 게임 목록)이 뜬다. 별도 "게임(풀영상)" 탭은 없다. 옛 카드 뷰(`ClipBrowser` steam·`GameSection`·`ClipCard`)와 첫 구현 `GamePlayer` 는 F5 제거 전까지 코드로만 남아 있다 — `App.tsx` 의 전환 커밋 하나를 되돌리면 옛 화면이 돌아온다.

- **게임 목록**(`GET /api/games`): 날짜 머리줄(`GameDayHeader`, 게임 수·클립 수·풀영상 합계) 아래 게임 행 — **왼쪽**: 초상화 3장(카드 비율 그대로의 둥근 모서리 직사각형 - 원으로 그리면 좌우와 위 모서리가 잘려 이미 카드에서 잘린 얼굴이 더 잘린다. 내 캐릭터 칸은 저장된 그림 왼쪽 약 6% 에 선택 강조 테두리·바깥 배경이 들어 있어 화면에서 오른쪽 기준 8% 확대로 가린다), 순위(`#1`, `#7`; 코발트 프로토콜은 `승리`/`패배`만, 결과를 모르면 `결과 미확인`)와 `일반`/`랭크` 배지(`matchResult.matchType`, 판독하지 못했으면 배지 없음), 시작 시각, TK/K/A. **오른쪽 정렬**(게임마다 있을 수도 없을 수도 있는 배지 — 빨간 `N개 저장 대기`·고정·삭제 예정·풀영상 오류 — 는 이 묶음의 가장 왼쪽에 두어 나머지 열이 행마다 같은 자리에 오게 한다): `후보 N · 보관 M`(`clipCountsLabel` - 후보는 삭제한 것 제외, 보관은 클립이 있는 후보로 `자동 보관` 포함. "클립 N개"만 두면 직접 보관 모드에서 후보가 있어도 0개로 보여 헷갈렸다), 풀영상 크기(또는 "풀영상 삭제됨/없음"), 고정 배지, **자동 정리 삭제 예정 배지**(경기 키로 `GET /api/cleanup/preview` 와 맞춤), **저장 안 된 편집이 있으면 빨간 `편집 N개 저장 안 됨` 배지**(`unsavedEditCount` — 범위를 저장 당시/검출값과 다르게 고친 후보 수, 삭제한 후보 제외), 고정/해제 버튼. **행 어디를 눌러도 풀영상이 열린다**(열기 버튼 없음, 고정 버튼은 열지 않는다). 위쪽 "게임 N개" 줄에 **용량 막대**(`StorageUsageBar`, `storageUsage.ts`): "이 탭 6.2GB · 전체 10.8GB / 40GB" — 한도는 스팀 녹화·영상 파일 합산 하나라 두 탭 모두 전체 합계(`GET /api/games?source=all`)로 채우고, 75% 이상 노랑·90% 이상 빨강, 자동 정리가 꺼졌거나 한도가 없으면 숨기고 "풀영상 N" 글자만 둔다. **`삭제 예정만 보기`**(`DueOnlyToggle`, 두 탭 공통) 는 자동 정리 미리보기에 오른 게임만 남기며 대상이 없으면 켤 수 없다. **풀영상이 없고 원본이 남은 옛 스팀 게임 행에는 `풀영상 만들기` 버튼**(`useRebuildFullVideo`, 한 번에 한 게임, 진행률을 버튼에 표시)이 붙는다. 삭제 예정 배지에는 보존이 켜져 있으면 "지우기 전에 클립 N개를 남깁니다"가 붙는다.
 **게임 행 `⋯` 메뉴**(`GameMenu`·`useGameDelete`, 두 탭 공통, 풀영상 화면 머리줄에도 같은 메뉴 - 삭제하면 목록으로 돌아간다). 스팀 녹화 탭은 맨 위에 **`다시 분석`**(`useReanalyzeGame`·`reanalyze.ts`, `GET/POST /api/games/{key}/reanalyze`, [pipeline.md §11](pipeline.md)): 누르면 방식(`full`/`candidates`)을 물어 확인 창에 무엇이 새로 만들어지고 무엇이 유지·초기화되는지 적고, 진행 문구(`N%`)를 목록 아래에 보여 주며 끝나면 목록과 열려 있던 풀영상 화면을 새로 읽는다. 영상 파일 탭은 영상 묶음 머리에서 다시 분석한다. 삭제: `풀영상만 삭제`/`자동 보관 클립 삭제`/**`게임 전체 삭제`**(`POST /api/games/{key}/delete`, [pipeline.md §11](pipeline.md)). **사용자가 보관한 클립은 어느 삭제도 지우지 않는다**([pipeline.md §9](pipeline.md)) - `자동 보관 클립 삭제`는 `자동 보관` 카테고리의 클립만(`autoClipCount`)·`게임 전체 삭제`는 풀영상·게임 기록·`자동 보관` 클립만 지우고 보관한 클립(`savedClipCount`)은 클립 탭에 남는다. 앞의 둘은 지울 것이 없으면(`자동 보관` 클립이 없으면) 흐리게 꺼지고(`풀영상과 클립 전체 삭제`는 게임 전체 삭제에 포함되어 메뉴에서 뺐다 - API 의 `both` 는 남아 있다), 전체 삭제는 풀영상·게임 기록까지 지워 행이 사라지므로 늘 켜져 있다(연습 모드 게임 등 정리용). 확인 창은 `DeleteConfirmDialog` 에 풀영상 크기·`자동 보관` 클립 수를 적고 보관한 클립이 있으면 "보관한 클립 N개는 남습니다"(전체 삭제는 "클립 탭에 남습니다")를 덧붙이며, **고정한 게임은 "다시 묻지 않기"를 켰어도 묻는다**("고정한 게임입니다" 한 줄 추가). 행이 `overflow-hidden` 이라 메뉴는 `fixed` 로 띄운다.
- **목록 불러오기**(`listLoad.ts`, 2026-10-02 사용자 피드백): 목록이 느렸던 원인은 서버였다 - `GET /api/games` 가 보관한 클립마다 `find_clip`(클립 폴더 전체를 훑고 영상 약 320개의 태그를 읽는다)을 불러 게임 27개·클립 261개에서 8초(스팀 9게임 2.1초)였고 반복해도 같았다(캐시가 아니라 일 자체가 많았음). 그래서 `api.clips.find_clips` 가 요청당 한 번만 훑게 해 0.5초(0.2초)가 됐다 - **서버·프론트 캐시는 두지 않는다**(`GET /api/vods` 130~155ms, 나머지 3ms). 함정: 게임·클립 단위 루프에서 `find_clip` 을 다시 부르지 말 것. 영상 파일 탭은 영상 묶음 요청이 게임 요청보다 먼저 와서 한동안 "게임 0개"·"이 영상에서 찾은 게임이 없습니다"가 보였다 - 두 요청이 다 올 때까지(`listLoading`) 날짜·영상 묶음을 그리지 않고 "게임 불러오는 중…"+불러오는 막대만 둔다(오류가 나면 막대를 걷고 오류만 보인다). 두 탭 컴포넌트는 탭을 바꿔도 마운트된 채라 마지막 목록이 남은 채 뒤에서 갱신된다. 풀영상 화면의 모든 변경(보관·삭제·범위 수정 등)은 끝나면 `onChanged` 로 목록을 다시 읽고, 목록으로 돌아오는 순간(`returnedToList`)에도 한 번 더 조용히 읽어 행의 `보관 M` 이 새로고침 없이 맞는다.
- **게임 정보 수정하기**(`useGameEdit`·`GameInfoDialog`, `gameEdit.ts`, 두 탭 공통, [pipeline.md §11](pipeline.md)): 게임 행과 풀영상 화면 머리줄 `⋯` 메뉴의 `게임 정보 수정하기`가 대화상자를 연다 - **제목**(60자, 빈 값 = 제목 없음)과 순위(1~99)·종류(일반/랭크/미확인)·TK/K/A, 코발트는 순위·종류 대신 승리/패배 선택. 빈 칸은 값 비움, 잘못된 입력은 칸을 짚어 알리고 저장하지 않는다. **바뀐 것만 보낸다**(`buildSave`) - 제목만 고치면 결과는 보내지 않아 잠기지 않는다. 순위·TK/K/A 를 고쳐 저장하면 그 값으로 **잠기고**(다시 분석·결과 채우기가 덮어쓰지 않음) 그 게임의 클립 탭 결과도 같이 바뀐다. 잠금 해제 버튼은 없다(고친 값이 항상 이긴다). 제목은 행에서도 고친다: 초상화 옆 제목 자리의 `✎`(`GameTitle`, 호버 `제목 편집`, 제목이 없어도 항상 보임)를 눌러 그 자리에서 입력(Enter·포커스 이동 저장, Esc 취소). 풀영상 화면 머리줄은 `gameHeading`: 사용자 제목 > 영상 파일 게임의 `스트리머 · 게임 N` > 경기 키. 저장하면 풀영상 화면을 새로 읽는다(`key` 에 tick).

## 영상 파일 탭 = 날짜 > 영상 묶음 > 게임 행 → 풀영상 (F6, `VodGameList`)

스팀 녹화 탭과 같은 문법이다. 날짜 머리줄(영상 날짜 `videoDate` 기준, 접기) 아래 **영상 묶음**(`VodSection`), 그 안에 **게임 행**(`GameRow` - 스팀 녹화 탭과 같은 컴포넌트, 시간 칸만 `게임 N` + 원본 안 위치), 게임을 누르면 같은 `GameViewer`(← 영상 목록, 제목 `스트리머 · 게임 N`)가 열린다. 옛 카드 화면(`ClipBrowser` vod)은 F5 전까지 코드로만 남고 `App.tsx` 의 전환 커밋 하나를 되돌리면 돌아온다.

- 영상 묶음 머리 기능은 그대로: 분석 시작·취소·진행률(`풀영상 만들기` 단계 추가), 날짜·이름 고치기, 다시 분석, 전체 삭제(확인 문구가 게임 풀영상까지 지운다고 알린다), 목록에서 삭제.
- **필터 바는 없다** - 스팀 녹화 탭이 새 화면에서 필터 바를 없애고 도구 줄(게임 수·풀영상 용량·날짜 모두 펼치기/접기·검색창)만 둔 기준을 따른다. 도구 줄에 새로고침·영상 형식 도움말. 날짜는 최신순, 한 날짜 안은 영상 이름순, 영상 안은 게임 번호순.
- 옛 영상: 원본·캐시가 남았으면 영상 머리에 `풀영상 만들기 (N)`(확인 창에 최대 용량). 원본이 지워졌으면 게임 행이 `풀영상 없음(이전 버전)` 이고 열면 저장된 클립으로 본다(`LegacyGamePanel`, 클립은 후보 기록에서).

## 게임 목록 검색 (스팀 녹화·영상 파일 탭, `SearchBox`·`useSearch`·`search.ts`·`api/search.py`)

도구 줄의 검색창이 두 탭의 게임 목록을 거른다. 규칙은 옛 제목 검색(`q`, da921a7)과 같다 — **대소문자·모든 공백을 무시한 부분 일치, 입력이 멈춘 뒤 0.3초에 조회**(`SEARCH_DEBOUNCE_MS`·`useDebouncedValue`). 서버 규칙은 `api/search.py`(`normalize`·`matches`·`first_match`), 프론트 규칙은 `search.ts` 한 곳이고 세 탭이 같은 것을 쓴다. 빈 검색어는 검색이 아니다.

- **서버 `GET /api/games?q=`로 한다.** 게임 목록 응답(`_summary`)에는 후보 제목·클립 제목·메모가 없고, 메모는 클립 정보 파일에만 있다. 모든 행에 검색용 글자를 내려주면 평소 목록 응답이 후보 수만큼 커지므로 `q` 가 있을 때만 서버가 거른다. 목록 조회는 이미 클립 정보를 한 번에 읽어 오므로(`self_saved_categories`) 비용이 늘지 않는다.
- 대상과 우선순위(`game_routes.game_match`): 게임 제목 → 후보 제목(고친 제목 우선, 지운 후보 제외) → 클립 제목(후보 제목과 다를 때) → 클립 메모 → 영상 이름(`vodFile` 의 파일명). 스트리머 이름은 검색 대상이 아니다(화면에서 스트리머를 직접 내세우지 않는다). 맞은 게임에는 처음 맞은 칸 `match: {where, text}` 가 붙는다.
- 화면: 맞는 게임만 남기고 행 맨 아래에 `🔍 후보 '…'` 한 줄(`matchLabel`, 30자 넘으면 줄임). 접혀 있던 날짜(`visibleCollapsed`)와 영상 묶음은 검색 중 펼쳐 보이고(저장된 접힘은 그대로) `날짜 모두 펼치기/접기` 는 막는다. 영상 파일 탭은 맞는 게임이 없는 영상 묶음을 뺀다(`withGamesOnly`). 개수 줄은 `검색 결과 N개` 이고 풀영상 용량은 검색과 상관없이 그 탭 전체 값을 그대로 보인다(검색 직전 값을 기억). 도구 줄은 왼쪽에 날짜 펼치기/접기·삭제 예정만 보기·(스팀 녹화 탭은 과거 녹화 분석, 영상 파일 탭은 새로고침)을 먼저 두고 그 오른쪽 끝에 `게임 N개`·용량 막대를 둔다(글자 길이가 바뀌어도 버튼 자리가 안 움직이게), 검색창은 오른쪽 끝이다. 용량 막대는 마지막 값을 `localStorage`(`storageUsageTotals`)에 기억해 두었다가 먼저 보이고 서버 응답으로 갱신한다(탭 몫은 같은 응답의 소스별 합).
- 검색어는 탭 컴포넌트 상태라 풀영상 화면을 갔다 오거나 다른 탭으로 가도 유지되고(탭은 마운트가 남는다), 주소에는 넣지 않는다. 목록을 다시 읽을 때(분석 끝·삭제·새로고침)도 지금 검색어로 읽고, 늦게 온 이전 응답은 버린다.
- 한계: 영상 이름은 게임 기록(`vodFile`)에서 찾으므로 아직 분석하지 않아 게임이 없는 영상은 검색에 나오지 않는다.

## 클립 정리 API (F7, `api/library_routes.py`·`pipeline/library_fs.py`)

클립 폴더를 **실제 폴더 구조 그대로** 다룬다 - 앱은 분류하지 않고 폴더를 만들고 이름을 바꾸고 옮기고 지우는 것을 돕기만 한다(탐색기에서 직접 하는 것도 정상 사용).

- 경로는 전부 클립 폴더 기준 상대 경로(`/` 구분)다. `..`·절대 경로·드라이브(`:`)·역슬래시·`.` 으로 시작하는 이름(앱 작업·캐시 폴더)·클립 폴더 밖을 가리키는 심볼릭 링크는 400. 옛 경로 모드는 클립 폴더가 둘이라 가상 최상위(`스팀 녹화`·`영상 파일`) 아래로 보이고, 가상 최상위에는 폴더를 만들거나 옮기거나 지울 수 없다. 클립 폴더 자체도 지우거나 옮길 수 없다.
- `GET /api/library?path=`: 그 폴더의 하위 폴더(`clipCount` = 안쪽 영상 수)와 **그 폴더 바로 아래** 영상의 클립(`relPath`·`fileName` 덧붙임. 정보가 있는 클립 + 앱이 만들지 않은 영상), 경로 조각(`crumbs`). 탭을 열 때·새로고침할 때마다 다시 읽는다.
- `POST /folders {path,name}`(같은 이름 409), `PATCH /rename {path,name}`(영상은 확장자를 유지), `POST /move {items,dest}`(하나라도 같은 이름이 있으면 409 로 아무것도 안 옮김, 폴더를 자기 안으로는 불가, 다른 드라이브는 복사 뒤 원본 삭제), `POST /delete {items}`(설정한 삭제 방식. 클립은 기존 삭제와 같이 라벨 보관·게임 기록을 남기고 정보·썸네일·재생용 변환 영상까지 지운다. **복사본이 더 있는 클립은 영상만 지우고 정보는 남긴다**. 폴더는 안의 클립을 처리한 뒤 폴더째 지운다), `POST /reveal {path}`(Windows 탐색기), `POST /export {items,dir}`(선택한 항목의 영상을 복사, 고른 폴더를 `paths.exportDefault` 로 기억).
- 이름을 바꾸거나 옮겨도 정보(제목·태그·라벨·게임)는 영상 안 태그·지문으로 이어진다([pipeline.md §8](pipeline.md)).

## 클립 탭 (F7, 새 컴포넌트 `ClipArchive`, `clipArchive.ts`·`archive.ts`·`categoriesApi.ts`)

**보관한 클립만** 카테고리(= `clips\` 바로 아래 폴더, [pipeline.md §11](pipeline.md) `/api/categories`)별로 본다. 왼쪽 카테고리 목록(첫 클립 썸네일·개수, `+ 새 카테고리`, 사용자 카테고리는 ✎ 이름 바꾸기·✕ 삭제 - 안의 클립까지 지운다, `자동 보관` 은 맨 아래 흐리게), 오른쪽은 그 카테고리 폴더 바로 아래 클립 카드(`GET /api/library?path=<카테고리>`)와 검색창(아래 "클립 탭 검색"). 클립을 누르면 모달이 아니라 풀영상 화면 방식의 전체 화면(`ClipViewer`, 아래 "재생 화면")으로 바뀐다. 탭을 떠나면(`active` false) 재생 화면은 영상을 멈추고 단축키를 받지 않는다 — 탭은 숨기기만 하고 마운트가 남아 있어 멈추지 않으면 백그라운드에서 소리가 계속 난다.

- **카드는 게임 정보 중심**: 순위 · 일반/랭크(`cardHeadline`, 코발트는 `승리`/`패배`)·게임 시각·초상화 3장·제목·용량. 파일 이름은 쓰지 않는다. 앱이 만들지 않은 영상("앱 밖 영상" 배지)은 제목만. 게임 시각 최신순.
- **체크박스는 `선택` 모드에서만** 나온다. 선택하면 `카테고리 옮기기`(`ArchivePopup` 재사용 → `POST /api/categories/move`)·`내보내기…`·`삭제`(기존 확인 창), `모두 선택`. 카드를 누르면(선택 모드 밖) 재생 화면으로 간다.
- **사용 안내 가이드**(`guide.ts`·`GuideContent`·`GuideText`·`GuideDialog`, 2026-10-02 개편): 머리줄 `?` 버튼 모달(`max-w-3xl`, 높이 고정·본문만 스크롤)과 첫 실행 화면 `<details>` 가 같은 `GuideContent` 를 쓴다. 한 장 스크롤이 읽기 어렵다는 피드백으로 탭 `시작하기 | 풀영상 화면 | 클립 | 자동 정리 | 영상 파일 | 폴더 | 단축키` 로 나눴다 — 시작하기는 4단계 흐름 + "알아 두면 좋은 것" 3줄, 풀영상 화면은 후보 카드 버튼 설명, 클립은 자동 정리 대상이 아니라 용량에 신경 써야 한다는 안내, 자동 정리는 지워지는 것(풀영상만)·두 탭 합산 한도·오래된 순서·`삭제 예정만 보기` 가 흐린 이유·1시간 주기, 영상 파일은 추가·분석 3단계와 지원 형식, 폴더는 폴더 그림·SSD 권장 상자, 단축키는 `ShortcutTable` 그대로. 데이터는 탭마다 블록 배열(`steps`·`notes`·`paras`·`callout`·`tree`·`shortcuts`)이고, 문장 속 `` `용어` `` 는 실제 버튼 모양의 칩(`GUIDE_CHIPS` 에 등록된 이름만, 화면 버튼 이름과 같아야 한다), `{키}` 는 `<kbd>` 로 그린다(`parseGuideText`). 본문 15px·`leading-7`, 한 단락 두 문장 이내. 그림은 코드(텍스트 트리)로 그린다. `guide.test.ts` 가 탭 구성, 칩 등록·백틱 잔재 없음, 옛 용어(`클립으로 저장`·`무시`·옛 옵션 탭 이름 `다시보기`), 폴더 이름, 문장 길이를 고정한다. **`(?)` 도움말**(`helpTexts.ts` 문구 + `HelpTip` 재사용): 옵션 자동 정리 켜기·클립 보관 방식·풀영상 위치만 따로 두기(`summary` 안), 게임 행의 `스팀 녹화 오류로 …` 배지(SSD 권장 포함)·`풀영상 없음` 배지/글자. 옵션 → 영상 파일의 `분석 후 원본 영상 삭제` 옆 `(?)`(삭제 조건은 "게임 풀영상이 1개 이상 저장된 영상")도 같은 방식이다. 영상 파일 탭 도구 줄에는 `(?)` 를 두지 않는다 — 탭 설명과 지원 형식은 머리줄 `?` 사용 안내의 `영상 파일` 탭(`videoFormats` 블록, `videoFormatHelpText`)에 통합했다. `HelpTip` 은 글자 그대로 보여 주므로 문구에 백틱 등 마크업을 쓰지 않는다. 게임 행 `li` 의 `overflow-hidden` 은 툴팁을 잘라 없앴다(왼쪽 색 막대에 `rounded-l-lg`). 같은 디스크 경고(`recordingDiskWarning`)에도 SSD 권장 문장을 붙였다.
- **클립 메모**(`memo`, [pipeline.md §11](pipeline.md)): 재생 화면에 `ClipMemoInput`(한 칸)(포커스를 잃으면 저장, 최대 5,000자, "나만 보는 메모입니다. 서버로 보내지 않습니다"), 카드에는 `📝 메모 있음` 표시만, 메모도 클립 탭 검색 대상이다. 풀영상 화면의 보관한 후보 행에도 `메모`/`메모 ●` 버튼으로 같은 메모를 쓴다.
- **재생 화면**(`ClipViewer`, 2026-10-02): 주소 `#/clips/<카테고리>/clip/<클립 ID>`(`route.ts` 의 `clip`) — 열 때 push, 같은 카테고리 안에서 클립을 오가는 건 replace 라 `← <카테고리>`·뒤로 가기는 한 번에 목록으로 돌아간다. 없는 클립 주소는 `ClipArchive` 가 목록을 읽은 뒤 카테고리 목록으로 바꿔 친다. 머리줄(`← 카테고리`·제목 ✎·`내보내기`·`삭제`·`⋯` = 탐색기에서 열기·자르기·나누기), 왼쪽 영상(브라우저 기본 컨트롤 없음 - `ClipVideo` 의 `player` 모드) + 위치 슬라이더 + **풀영상 화면과 같은 컨트롤 줄**(`ViewerControlBar`·`ViewerControls.tsx` 를 `GameViewer` 와 공유) + 게임 정보(순위·일반/랭크·시각·초상화)·카테고리 칩(`ArchivePopup` 으로 옮기기, `Ctrl+S`)·메모 한 칸, 오른쪽 같은 카테고리의 클립 목록(이전/다음 클립은 이 순서, `clipViewer.ts`). 단축키는 `decideKey` 를 그대로 쓰되 재생·이동·볼륨·전체화면·삭제·카테고리·메모·`?` 만 받는다(`CLIP_VIEWER_ACTIONS`, 안내 표는 `shortcutGroupsFor` 로 같은 키만). 클립을 지우거나 다른 카테고리로 옮기면 다음 클립(없으면 이전, 없으면 목록)이 보인다. **범위는 풀영상에서 고친다**: `GET /api/games/by-clip/<클립>`(`getClipSource`)으로 클립을 만든 게임·후보를 찾아, 풀영상이 있으면 머리줄 `풀영상 보기·범위 고치기` 가 그 게임의 풀영상 화면을 그 후보가 선택된 채로 연다(주소 `#/steam/game/<키>/cand/<후보>`·`#/vod/game/<키>/cand/<후보>`, `route.ts` 의 `cand` → `GameNav.openCand` → `GameViewer.initialSelected` 가 선택하고 범위 시작으로 이동). 그 풀영상 화면의 돌아가기 버튼은 `← 클립`(주소가 `cand` 일 때)이고 직전 항목이 클립 주소면 `history.back()`. 게임이 이어지지 않았거나(앱 밖 영상·게임 기록이 지워짐) 풀영상이 지워진 클립만 `⋯` 메뉴에 `✂ 자르기·나누기`(`TrimPanel`)가 나온다(`rangeFixTarget`). **개발 모드에서만** 클립 ID·교전 점수 칩·신호 태그·근거가 점선 상자로 보인다(`useTuningUi`). 라벨 버튼·라벨 메모는 없다. 오른쪽 클립 목록 항목에는 썸네일·순위·초상화 3장(`PortraitRow size="sm"`)·제목·시각이 보인다. 앱 밖 영상은 게임 정보 없이 제목·메모·카테고리만. 옛 `PlayerModal` 은 옛 카드 뷰(`ClipBrowser`·`ClipLibrary`)가 쓰므로 지우지 않는다(F5 보류).
- **클립 탭 검색**(`ClipArchive`, `GET /api/library/search?q=`, 2026-10-02): 규칙은 게임 목록 검색과 같다(`search.ts`·`api/search.py`, 0.3초 디바운스, 위 "게임 목록 검색"). **모든 카테고리**를 훑어 클립 제목·메모·게임 제목(클립을 만든 게임의 고친 제목, `savedClipId` 로 이음)을 찾고, 앱 밖 영상은 파일 이름(= 제목)만 본다(맞은 것만 길이·썸네일 조사). 서버가 카테고리 순서(`보관함` → 사용자 카테고리 → `자동 보관`) 그대로 묶어 `{categories:[{name, clips:[… match]}]}` 로 주고 맞는 클립이 없는 카테고리는 뺀다. 화면은 검색 중 오른쪽을 카테고리별 묶음(`카테고리 이름 N개` 소제목)으로 바꾸고 머리 제목은 `검색 결과 N개 · 카테고리 M곳`, 카드에 `🔍 메모 '…'` 한 줄이 붙는다. 검색어를 지우면(입력 즉시) 원래 카테고리 화면, 왼쪽 카테고리를 누르면 검색어를 지우고 그 카테고리로 간다. 선택·`카테고리 옮기기`·내보내기·삭제는 결과 전체를 대상으로 한다(`shown`). 결과의 클립을 누르면 그 클립의 카테고리 주소(`#/clips/<카테고리>/clip/<ID>`)로 재생 화면이 열리고 오른쪽 목록은 그 카테고리 클립이다. `← 카테고리`·뒤로 가기로 돌아오면 검색어와 결과가 남아 있다(탭 컴포넌트 상태). 이름 바꾸기·삭제·옮기기 뒤에는 결과도 다시 읽는다. 옛 카테고리 안 검색(`filterClips`, 제목·파일 이름·메모)은 이것으로 바꿨다. 옛 경로 모드(카테고리 없음)는 `enabled:false` 와 빈 결과.
- **탐색기에서 열기**(그 카테고리 폴더), 새로고침. 카테고리 밑 하위 폴더의 클립은 이 화면에 보이지 않는다(탐색기에서 정리한 경우) — 카테고리는 한 단계만 쓴다.
- 옛 경로 모드는 카테고리가 없어(`enabled:false`) 안내 문구만 나온다.
- 옛 탐색기식 화면(`ClipLibrary`·`LibraryFolderPicker`)은 F5 전까지 코드로만 남고 `App.tsx` 의 전환 커밋 하나를 되돌리면 돌아온다. 위 "클립 정리 API" 는 이 화면의 이름 바꾸기(`PATCH /rename`)·삭제·내보내기·탐색기 열기가 그대로 쓴다.
