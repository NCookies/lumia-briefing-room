# 검출 — 교전 구간·태그·PvP 점수·결과 화면

> 코드: `src/lumia_briefing_room/detect/`, 해상도 프로필 `profiles/`, 본보기 `data/templates/`. 화면 요소의 성질은 [game.md §7](game.md).

## 1. 원칙

### 재현율 우선 — 생성에서 버리지 않는다

- 목표는 내가 참여한 **사람과의 교전 전부**다. 이기든 지든, 킬이 있든 없든.
- **잘못 버리면 영구 손실**(링버퍼가 원본을 지운다), 잘못 남기면 디스크만 쓴다. 그래서 생성은 느슨하게, 엄격한 판단은 열람 단계(점수 정렬·필터)에서 한다.
- **구간 경계를 정하는 규칙도 필터다.** 교전을 "아님"으로 판정하는 새 규칙은 **라벨된 교전을 몇 개 버리는지부터 재고, 1개라도 버리면 채택하지 않는다.** 대신 점수를 깎거나 신호로 기록한다.
- 예외는 교전이 물리적으로 불가능한 구간뿐이다(대기방 — `브리핑 룸` 지역명, 대기방 시계 `00:00`). 이때도 오독으로 진짜 교전이 잘리지 않는지 실측한다.
  - 실패 사례: "팀원 링만 켜지고 내 배지는 안 켜진 구간을 버린다" → 막으려던 오탐 1개, 같이 버린 진짜 교전 4개. 되돌렸다.
- > "교전이 아닌 장면 몇 개를 빼겠다고 핵심인 교전 장면을 빠뜨리면 안 된다" — 사용자, 2026-09-21

### 판독 불가(`None`)는 "아님"(`False`)과 다르다

- 어두운 프레임·로딩·관전 화면은 `None`. `None` 은 교전 종료로 치지 않고 직전 상태를 유지한다.
- 조건문은 `if x is not False:` 처럼 세 값을 구분해 쓴다. `if spectating:` 은 `None` 을 "관전 아님"으로 흘려 로딩 화면을 사망으로 오판했다(2026-09-23 실사고).
- 본보기가 없거나 점수 차가 작으면 **답을 내지 않는다**(`None`). 틀린 값을 조용히 내는 것보다 낫다.

### 외부 의존 없음, LLM 없음

검출은 로그·영상·스팀 설정 파일만 읽는다. 고정 UI 영역 픽셀 판독이라 OpenCV 로 충분하다(LLM 은 20분 매치당 수백만 토큰).

## 2. 프레임 공급과 샘플링

- **키프레임만 디코딩한다**(`-skip_frame nokey`). 스팀은 세그먼트(3초)당 1장. 20분 매치 22초(소프트웨어)/12초(`d3d11va`). 전체 디코딩 대비 16배.
- 검출 정밀도(3초) = `-c copy` 컷 정밀도(3초 격자)라 잃는 것이 거의 없다. 3초 미만 교전은 최소 길이 필터가 어차피 버린다. 실측으로 교전 경계·사망 판정 모두 충분함을 확인해 **2패스(경계 부근 전체 디코딩)는 만들지 않았다.**
- 하드웨어 디코딩은 있으면 쓰고 실패하면 소프트웨어로 떨어진다.
- `FrameSource` 가 `(t초, 프레임)` 을 내준다: `SteamSegmentSource`(세그먼트 연속 구간별 디코딩, 파이프 스트리밍), `VodFileSource`(단일 영상 파일). 검출(`analyze_frame` → `finalize_match`)은 프레임·시각만 받으므로 소스와 무관하다. 스팀 소스는 `expected_frame_count()` 로 진행률을 알린다.
- 프레임 추출은 **파이프 스트리밍**이다(임시 파일 병합 + 전체 메모리 적재는 40분에 9GB 였다).

## 3. 해상도 프로필

- 좌표를 하드코딩하지 않는다. 녹화/영상의 실제 해상도로 프로필을 고른다.
- 측정 프로필: `2560x1440`(기준), `1920x1080`(기준×0.75, `normalizedTo: [2560,1440]`). 그 외 해상도는 기준을 비례 축척하고 `measured=False`·경고. 16:9 가 아닌 비율은 HUD 가 모서리 기준이라 틀릴 가능성이 높다(미검증).
- **정규화 방식**: `ResolutionProfile.crop()` 이 ROI 조각만 기준 ROI 크기로 확대(큐빅)해 기존 본보기·픽셀 임계를 그대로 쓴다. 기준 프로필은 배율 1 이라 동작 불변.
  - ⚠ 크기가 다른 칸(예: `tk_value`)에 템플릿을 맞출 때는 `profile.rois` 가 아니라 **`crop()` 이 실제로 내놓는 크기**에 맞춘다(안 맞으면 조용히 `None`).
  - ⚠ 해상도 네이티브 전용 ROI(`_RESOLUTION_NATIVE_ONLY_ROIS`: `phase_digit`, `cobalt_*` 8종)는 기준 크기로 확대하지 않는다. 이름만 같다고 확대하면 다른 해상도의 크롭이 깨진다.
- **카운터 칸 자동 보정**(`calibrate_counter_position`): 영상 처음 8프레임에서 `k_value` 기본 자리로 3번 미만 읽히면 주변(±160px, ±24px)을 `locate_digit` 로 뒤져 `k/a/tk_value` 를 통째로 옮긴 프로필을 쓴다. 기본 자리가 맞으면 돌지 않는다. 새 방송·새 해상도마다 좌표를 손으로 재던 것을 대체한다.
- 본보기를 못 찾으면 **반드시 경고 로그**를 남긴다(K/A 본보기가 조용히 꺼진 채 몇 주 돈 사고가 있었다).
- 스트리머 VOD 는 **다운로드 소스(플랫폼 재인코딩)마다** HUD 위치가 다를 수 있다. 자기 스팀 녹화는 네이티브라 문제가 적다.

## 4. 프레임 판독기 (`analyze_frame`)

`spectating` 이 `False` 로 확정됐을 때만 배지·얼굴·지역·미니맵·궁극기처럼 "내 시점"이어야 하는 신호를 읽는다(관전 화면은 팀원 시점, 로딩·로비는 모름).

| 신호 | 모듈 | 방식 · 요점 |
|---|---|---|
| 교전 배지 | `badge.py` | 색 픽셀 세기. 주황 ≥ 100, 배지 존재 ≥ 250(초록 포함 — 1080p VOD 평상시 배지가 초록이라 `None` 74%→0%) |
| 관전 | `spectator.py` | 미니맵 헤더 아이콘 보임 ∧ 하단 넓은 띠(`860,1300,1300,1440`)에 내 체력바 없음. 미니맵도 없으면 `None` |
| 사망(얼굴) | `death.py` | 매치 중앙값 대비 상대 하락(밝기 0.6·채도 0.7 배). 절대 임계는 밤·실내에서 오탐 |
| K / A / TK | `counter.py`·`glyph.py` | **글자 점수 맵**(밝기×무채도, 이진화 안 함) × **숫자 본보기**(여러 배경 샘플의 하위 10퍼센타일) **평균 제거 상관**. 1·2등 점수차 `MIN_MARGIN 0.05` 미만이면 `None`. 두 자리(10~99)는 한 자리 본보기를 ±6px 밀어 겹친 조합 본보기. TK 는 K 본보기를 `tk_value` 칸 크기로 리사이즈해 재사용. ROI 폭 == 본보기 폭(테스트로 고정) |
| 일차 | `day.py` | 숫자 한 글자만. **`min` 채널 점수**(모든 채널이 밝아야 글자 — 빨강 배경을 글자로 착각하지 않게). 1~8, 9 이상·두 자리는 못 읽음 |
| 낮/밤 | `daynight.py` | 노랑 vs 보라 **큰 쪽** |
| 지역명 | `region.py` | **밝기(`max` 채널)만** 본다(글자색이 바뀜). ROI 폭 전체 비교(접두어 오인 방지). 21개 이름, 모르는 이름은 대부분 `None` |
| 대기방 시계 | `clock.py` | 시계 네 칸이 모두 같은 모양 = `00:00`(본보기 불필요). 1920x1080 프로필에만 `timer` ROI |
| 코발트 페이즈 | `phase.py` | `Phase N` 숫자 본보기, `v_lo 120`(옅은 주황). 가운데 정렬이라 ROI 를 넉넉히(32px) |
| 팀원 사망 | `teammate.py` | 체력바 주황 ≥ 2% ∧ 초록 < 0.5% |
| 팀원 전투 | `teammate.py` | 링 ROI 의 **원 바깥 띠**만 셈(빨강 ≥ 3%). 얼굴 원화 빨강 오염 제거 |
| 미니맵 링 | `minimap.py` | `HoughCircles` 로 링을 찾고 테두리 색으로 적(빨강)/아군 구분. 단순 색 카운팅은 배경에 묻혀 실패 |
| 궁극기 | `ultimate.py` | `R` 칸 파란기 비율 + 잠김(빨간 X 2~15% ∧ `v_median < 55`) 판정 |

본보기를 만드는 법(라벨셋 → npz)은 [DEVELOPMENT.md 개발 도구](../DEVELOPMENT.md). **라벨셋 원본 이미지(`_samples`, `*_labels.jsonl`)는 공개 저장소에 없고 개발 PC 에만 있다.**

## 5. 구간 산출 (`finalize_match`)

게임(매치) 하나 단위로 돈다 — VOD 처럼 여러 판이 한 영상에 있으면 게임마다 초기화해야 K/A 단조 규칙·최종값·포화 판정·사망 구간이 맞는다.

### 배틀로얄

1. **교전 신호 = 내 배지 OR 팀원 전투**(관전 중엔 무조건 꺼짐). 팀원 신호로 구도 잡기·원거리 교전을 잇는다(놓친 교전 8→5, 새 구간 12개 발견).
2. 짧은 끊김(≤ 2샘플) 메우고, 짧은 구간(< 2샘플) 버림(`intervals.py`).
3. **팀원 전투 포화 보호**: 20샘플 이상에서 60% 초과로 켜져 있으면 그 매치는 팀원 신호를 버리고 배지만 쓴다. 이때 구간에 `team_combat_unreliable` 을 표시하고 컷은 넓은 프리롤(`fixedPrerollSec`)을 쓴다.
4. **관전**: 2샘플 이상 연속이어야 관전 구간. 교전 종료 후 8초 안에 관전이 시작되면 `died`. 살아 있는 화면이 한 번도 나오기 전의 관전(팀 소개 화면)은 사망으로 보지 않는다.
5. **구간 밖 증거로 구간 만들기**: 배지 구간 밖의 K/A 증가 → 이벤트 12초 전~이벤트 구간. 어떤 구간에도 안 걸린 내 사망(관전 시작) → 직전 12초 구간(살아 있는 프레임이 없으면 안 만듦). 팀원 사망 단독은 스플릿·금지구역 가능성이 커서 만들지 않는다.
6. **TK 는 새 구간을 만들지 않는다**(코발트는 팀 킬이 초당 수준이라 가짜 클립이 쏟아진다). 대신 기존 구간 끝 12초 안에 K/A/TK 델타가 있으면 그 구간의 **끝만** 그 시점까지 늘린다(배지가 꺼진 뒤 팀원이 막타).
7. **대기방 제외**: 지역명 `브리핑 룸` 프레임, 대기방 시계 `00:00` 5초 이상 연속 구간은 교전이 아니다(방송 오버레이가 지역명을 가려도 시계로 잡힌다).
8. K/A: 같은 값이 2샘플 연속이어야 확정, 매치 안에서 단조(감소는 오판), 구멍을 사이에 둔 변화는 태그로 만들지 않는다(`K: 2 → [구멍] → 6` 은 "모름"). 멀티킬이 `+2` 한 번인지 `+1` 두 번인지는 미확인 — 관측대로 기록하고 `delta > 1` 이면 경고.
9. 구간 경계는 샘플 시각 그대로(3초 격자).

### 코발트 프로토콜 (사용자 결정 2026-09-28)

야생동물도 이동도 거의 없이 교전의 연속이라 **부활 직후 ~ 사망 직후를 통째로 구간 하나**로 삼는다.

- 사망(얼굴 하락) + 첫 생존 이후 관전 구간을 "죽은 시간"으로 보고 그 여집합이 구간. 사망 샘플이 옆 구간에 섞이지 않게 경계를 한 칸 안쪽으로 당긴다. `died` = 바로 다음(≤ 2스텝)이 사망.
- 실측 구간 84~123초/목숨. 더 짧게 보고 싶으면 사용자가 자르기로 나눈다.
- 클립 범위를 만들 때도 코발트는 프리롤·포스트롤을 붙이지 않는다(붙이면 사망 간격 15~21초가 병합 간격 10초 밑으로 줄어 게임 전체가 클립 하나로 뭉친다 — 2026-09-28 실사고).

### 모드 판별

`infer_game_mode(states)`: `cobalt_phase` 와 `game_day` 판독 성공 횟수를 비교해 많은 쪽(둘 다 0 이면 배틀로얄). 호출자가 `game_mode` 를 명시하면 그 값이 우선(CLI `--game-mode`).

## 6. 태그

| 태그 | 판정 |
|---|---|
| `kill` / `assist` | 구간 안에서 확정 K / A 증가 |
| `death` | 구간 중 내 사망(관전 전환) |
| `teammate_death` | 구간 앞뒤 8초 안에 팀원 사망(살아 있다가 죽은 순간만) |
| `team_wipe` | 붙지 않는다 — 전멸 배너를 아직 읽지 않아 메타데이터 `teamWipe` 는 항상 `null`([plan.md §3](../plan.md)) |
| `no_result` | 위가 다 없음 — 사냥과 "아무도 안 죽고 끝난 교전"이 섞인 자리. 판별은 태그가 아니라 `pvpScore` 로 |

태그는 배타적이지 않다(킬 내고 죽기).

## 7. PvP 점수 (`detect/pvp.py`)

배지는 PvP/PvE 를 못 가른다. 여러 약한 증거 중 **가장 센 것이 점수**(0~1)가 되고, 걸린 근거는 전부 `pvpSignals` 에 남긴다(점수만 있으면 복기 불가).

| 증거 | 신호 이름 | 기본 가중치 | 근거(라벨 276개, 2026-09-24) |
|---|---|---|---|
| 킬/어시 증가 | `kill_delta`/`assist_delta` | **1.0 고정** | 정밀도 100%(교전 107/사냥 0) |
| 내 사망 | `death` | 0.9 | 95% — 야생동물·금지구역에도 죽는다 |
| 팀원 사망 | `teammate_death` | 0.8 | 69%(3일차+ 4:0) |
| 팀원 사망 1~2일차 | `teammateDeathSplit` | 0.5 | 무료 부활 구간은 흩어져 사냥하다 혼자 죽는다 |
| 궁극기 사용 | `ultimate_used` | 0.75 (델타 ≥ 0.25) | 델타 ≥ 0.25 정밀도 80%, 0.15~0.25 는 25%(노이즈) |
| 미니맵 적 링 평균 | `enemyRingMean` | **0**(값만 기록) | AUC 0.53 — 못 가른다 |

- 점수 전체: 임계 0.75 에서 정밀도 0.965 / 재현율 0.922. 못 찾는 "조용한 교전"(근거 전무)은 교전의 8%.
- 가중치는 설정 `filter.pvpWeights` 이고 **임시값**이다. 고치면 `tools/rescore_clips.py` 로 저장된 근거에서 재계산(검출 재실행 없음).
- **궁극기 델타**: 구간 앞 5초~뒤 8초(=클립 프리롤/포스트롤 폭)의 파란기 시계열에서 **잠김 프레임을 빼고** `max_rise`(이전 저점 대비 이후 상승의 최댓값)를 쓴다. 전역 절대 임계는 캐릭터 원화 색에 오염되고, `max-min` 은 직전 교전의 쿨타임이 줄어드는 것(캐리오버)을 오탐하고, 잠김↔해금 전환(스킬 레벨업)도 오탐한다 — 셋 다 실사고로 고쳤다. `is_locked` 임계는 캐릭터 2명 실측.
- `filter.minPvpScore` 기본 0(전부 생성). 라벨로 검증되면 올린다.

## 8. 결과 화면 판독

### 배틀로얄 (`detect/result.py`, `pipeline/result_scan.py`)

- **RapidOCR**(ONNX, PP-OCRv5 한국어/중국어). 샘플이 적어 글자 본보기 방식은 접었다. `rapidocr` 는 `opencv-python` 을 끌어와 headless 와 충돌하므로 `--no-deps` 로 설치.
- **읽는 범위**(`pipeline/result_tail.py`): 결과 화면이 2~3초만 떠도 잡히도록 **게임 끝 30초를 초당 2장으로 디코딩**한다 — 풀영상(`full.mp4`)이 있으면 그 끝, 없으면 끝 12개 세그먼트를 이어 붙인 임시 파일(`extract_tail_frames`). 인게임 프레임(일차 판독 성공)은 OCR 없이 건너뛴다. 못 찾거나 실패하면 예전 **키프레임 훑기**(거슬러 올라가며 최대 40프레임, 종료 뒤 8칸(24초)까지)로 넘어간다. 세그먼트를 이어 붙인 조각 파일은 타임스탬프가 세션 기준 절대값이라 `-sseof` 가 빗나가므로(0장) 전부 읽는다.
- **여러 장 다수결**(`detect.result.merge_results`, `_Votes`): 첫 장에서 멈추지 않고 결과 화면이 이어지는 동안 최대 3장(`MAX_VOTES`)을 읽어 순위·칩·결과 문구·닉네임·스탯을 **항목별로** 정한다(못 읽은 값 제외, 동률은 먼저 나온 쪽). 연속 3장(`VOTE_PATIENCE`) 못 읽으면 결과 화면이 끝난 것으로 본다. 결과표 이미지는 가장 많은 항목이 읽힌 장. OCR 이 장마다 다른 곳을 틀리기 때문이다.
- **순위를 못 읽어도 나머지를 저장**: 닉네임 줄 + 스탯 3개 이상이 함께 읽히면 결과 화면으로 받고 `placement`/`total` 만 `null` 로 둔다(UI 는 `순위 미확인`). 조건 없이 받으면 오탐이 는다.
- **`N/M` 하나만으로는 결과 화면이 아니다**: 순위가 읽혀도 결과 문구·닉네임 줄·스탯 3개 중 하나는 함께 읽혀야 받는다. 방송 화면에 띄운 다른 게임의 `4/9` 같은 글자가 결과(9/10 등)로 저장됐다(2026-10-01 치지직).
- **순위 숫자**(`detect/rank.py`, ROI `result_rank`, 본보기 `data/templates/rank/`): OCR 이 이 글꼴의 `3` 을 `L` 로 읽는다. K/A 처럼 밝기 점수맵을 본보기와 정규화 상관으로 대조한다(임계 0.95 — 진짜 표본 0.98~1.0, 다른 숫자 합성 글리프 0.45~0.78). 우선순위: 본보기 → OCR `N/M` → 결과 문구 `최종 생존` 이면 1위. 본보기는 `tools/build_rank_templates.py` 로 만든다(지금 **1·3 만** — 총원 `/7` 은 작은 회색 글자라 순위 숫자 본보기로 못 쓴다). 본보기 없는 숫자는 None 이라 다른 숫자로 오독하지 않는다.
- **숫자만 따로 잘라 OCR**(`read_placement_digits`, ROI `result_rank`·`result_total`): 본보기·패널 OCR 로 순위나 총원이 비면 큰 순위 숫자와 작은 `/총원` 을 각각 3배 확대해 읽는다. 패널 통째 OCR 은 1080p 에서 `3/8`→`8/E`, `6/7`→`L/9` 로 깨졌지만 따로 자르면 12판 모두 맞았다(2026-10-01 치지직). 그래도 순위 > 총원이면 순위를 버린다.
- **위치가 아니라 순서로 파싱**: `N/M` → 신뢰도 0.8+·한글 2자+ 줄 = 결과 문구 → `|` 로 시작하는 줄 = 닉네임(모드 칩 글자가 문구로 읽히던 버그 방지). 스탯은 `TK K D A` 라벨 아래 **같은 열**(열 거리 우선, 행 간격 다음).
- 모드 칩: **그냥 3배 확대가 먼저**, 못 읽으면 밝기 200 이하를 지우는 이진화(파란 랭크 칩용)를 다시 시도한다. 이진화만 쓰면 `일반` 칩이 14장 중 4장만 읽혔다(3배 확대는 14장 모두). 한글이 없는 글자(`{0` 등 OCR 쓰레기)는 못 읽은 것으로 본다 - 아니면 랭크 칩이 `normal` 로 저장된다. 둘 다 못 읽으면 `matchType=unknown`(일반으로 단정 안 함), 문구는 원문 저장.
- 닉네임: 줄만 3배 확대해 두 모델 중 점수 높은 쪽. 한글·영문 정확, 일본어·한자 미실측.
- 훑기는 **끊김 없이 이어진 세그먼트만, 다음 경기 시작 전까지만**(`contiguous_segments`). 원본이 지워진 경기를 다시 돌렸다가 뒤쪽 다른 경기 결과가 붙은 사고가 있었다.
- 화면 기반 경계(과거 녹화 분석)는 끝이 마지막 인게임 프레임이라 `find_result_after`(끝 뒤에서 앞으로)를 쓴다. 영상 파일(VOD)은 [vod.md](vod.md) 3.
- 소급: 결과 없는·`unknown`·순위 빈 게임은 `tools/backfill_game_result.py`(`pipeline/game_backfill.py`)가 풀영상 끝 30초로 다시 읽어 `game.json` 과 그 게임의 클립 메타를 채운다. 사용자가 고친 게임(`matchResultSource="manual"`)은 `--force` 여도 건드리지 않고, 새 값이 비면 예전 값을 남긴다.
- 결과 프레임은 경기당 1장 1280px JPEG 로 저장(`matchResult.imagePath`).
- **캐릭터 이름 OCR(세로 영문 이름·순위표 탭)은 폐기**(2026-09-28, 실사용 실패율 높음). `detect/character.py`·`scoreboard.py`·`characters.json` 삭제. 결과 OCR 은 모드·순위·문구·스탯·닉네임만.
- 탈출·일반 게임 결과 화면은 샘플이 없어 미실측.

### 코발트 (`detect/cobalt_result.py`)

- `승리`/`패배` 글자는 OCR 이 자신 있게 틀려서(`패배`→`HAHⅡ`) **본보기 대조**로 읽는다(마진 큼).
- 본인 TK/K/D/A 는 정확, 팀원 카드의 작은 숫자는 가끔 오독(`9`→`6`). 닉네임은 첫 판독을 그대로 쓴다(재판독이 오히려 나빴다). 팀원 닉네임 줄은 `TK/K/D/A` 라벨 줄보다 위 후보 중 가장 아래(추천 배지 `5/6` 오인 방지).
- `to_result_screen()` 이 `placement=1(승리)/2(패배)`, `total=2` 자리표시자로 기존 `ResultScreen` 모양에 맞춘다 — 뒤 파이프라인은 그대로.
- 본보기: `phase/{1920x1080,2560x1440}.npz`, `cobalt_outcome/1920x1080.npz`(승·패), `cobalt_outcome/2560x1440.npz`(**승리만** — 패배 표본 없음).

### 수동 보정

자동 판독이 틀리면 사용자가 순위·결과 문구를 고친다([ui.md](ui.md)). 저장 시 그 게임의 모든 클립에 `matchResultSource="manual"` 로 잠가 자동 판독(백필·다시 분석)이 덮어쓰지 않는다. 판독 정확도를 끝없이 올리기보다 고칠 수단을 주는 편이 싸다.

## 9. 캐릭터 초상화 (`detect/portrait.py`, `pipeline/portrait_scan.py`)

캐릭터 이름을 식별하지 않고 **루트 선택 화면의 팀원 카드 3장을 크롭해 그대로 보여 준다.**

- 탐색: `matchStartUtc` 직전 45초를 가까운 쪽부터 거슬러 먼저 찾고, 없으면 뒤 120초. OCR 없이 픽셀 판정뿐이라 싸다.
- 판정: **선택 화면 머리띠(`select_timer`·`select_title`, §선택 화면)가 보이는 프레임에서만** 본다. 판정용 칸 세 개와 저장용 칸 세 개가 **모두** 채워진 칸(`_looks_filled`)이면 채택. 채워진 칸 = 초상화다운 색(밝고 채도 높은 픽셀 비율 10% 이상) **또는 그림의 결**(밝기 표준편차 40 이상 - 흰 머리 캐릭터처럼 채도가 낮은 카드용, 2560x1440 실측 채워진 카드 65~100 / 회색 `EMPTY` 자리표시 19~24. 색으로는 흰 머리 카드 5.5% 와 자리표시 4.4~6.1% 를 가를 수 없었다. 2026-10-01, 20260928_163711 - 선택 화면이 66초(22 세그먼트)나 있는데도 못 찾던 문제). 결 기준은 선택 화면 경로에서만 쓴다(관전 판정 경로는 글자·아이콘 오탐 위험으로 색 기준만). 선택 화면에서만 보므로 이전 경기의 로비·인게임을 잘못 잡을 일이 없어 포기 규칙이 없다.
  - 관전 판정으로 로비·선택 단계를 가리던 옛 방식은 **방송 오버레이에 깨진다**: 치지직 1080p 다시보기에서 방송 캐릭터가 미니맵 아이콘 자리를 덮어 로딩·선택 화면이 전부 "관전"으로 읽혔고, 게임 시작에서 거꾸로 훑다 로딩 화면 두 장에서 포기했다. 옛 방식은 선택 화면 칸이 없는 프로필에만 남는다(`None` 이 아닌 판정 연속 2번이면 포기).
  - 저장용 칸까지 보는 이유: 캐릭터 선택 화면에서는 팀원 칸이 회색 `EMPTY` 자리표시인데 넓은 판정용 칸이 주변 색으로 통과했다. 저장용 칸까지 보면 세 장이 다 채워진 루트 선택 화면만 남는다.
  - 1920x1080 프로필의 선택 화면 칸은 2560x1440 × 0.75 다(치지직 1080p 다시보기 실측: 선택 화면 140~196초 전부 판독, 앞 로비·뒤 로딩은 아님, `RANK GAME` 을 연습으로 오판 안 함). 이 칸이 생기면서 1080p 에서도 게임 시작을 선택 화면까지 넓히고 닷지·연습 모드를 거른다.
- **판정용 ROI 와 저장용 ROI 가 다르다**: 판정은 좁은 `portrait`/`teammate1`/`teammate2`, 저장은 카드 안쪽을 딱 맞춘 `*_display`(약 2.04:1). 판정 ROI 를 넓히면 배경이 섞여 검출률이 떨어진다.
- 코발트는 선택 화면 UI 가 달라 찾지 않는다.
- 옛 클립·게임 기록만 남은 행은 초상화가 없다.

## 10. 자체 검증과 평가

- **`K` 카운터가 자기 정답지다**: 매치 마지막 인게임 프레임의 `K` = 그 매치 총 킬. 검출이 센 증가와 대조한다(구멍이 있으면 불일치를 검출 실패로 세지 않는다).
- 결과 화면 K/A 와 게임별 검출 최종값이 VOD 14판·코발트 6판에서 전부 일치.
- 라벨: 사용자가 UI 에서 `교전`/`그 외`(저장값 `pvp`/`pve`)를 찍는다. 기준은 "이 클립에 사람과의 교전이 **포함**되어 있는가" — 교전 뒤 야생동물을 잡아도 교전, 보스전에 다른 팀이 끼면 교전, 보이기만 하고 안 싸우면 그 외, 애매하면 안 찍는다(일관성이 정확성보다 중요).
- `tools/eval_pvp.py`(임계별 정밀도·재현율, "확정 증거인데 사냥" 목록), `--source steam|vod|all`(기본 steam — VOD 표본은 해상도·화질이 달라 따로 평가).
- 지표: 구간 단위 재현율(목표 90%+), 카운터 **오답률을 미지율보다 우선**(포기는 그 프레임만 버리지만 오답은 없는 킬 태그를 만든다).

## 11. 함정 모음

- `FrameState`/`CombatInterval` 에 필드를 더하면 **`vod_analyze.ANALYSIS_VERSION` 을 반드시 올린다.** 안 올리면 옛 판독 캐시가 새 필드 없이 재사용된다(코발트 영상이 "분석 완료, 게임 0개"로 사라진 사고).
- 군집 라벨을 정답으로 믿지 말 것 — 모양 비슷한 낱말(소방서/경찰서, 3/8/6)이 섞인다. 높은 임계로 재군집하고 대표를 눈으로 확인한다. 자기일관성 정확도(99.9%)는 새 매치에서 다시 잰다.
- 텍스트마다 점수 함수를 다르게: 지역명 `max`(글자색이 바뀜), 일차 `min`(배경이 빨강), K/A 밝기×무채도.
- 스크린샷은 창 테두리 때문에 절대 좌표가 어긋난다. ROI 는 실제 녹화 프레임에서 잰다.
- 표본 편중: 지역 `숲`·`창고` 등은 몇 장뿐, `is_locked` 는 캐릭터 2명, 관전 화면은 영상 표본 없음(스크린샷 1장 + 사망 직후 4프레임).
