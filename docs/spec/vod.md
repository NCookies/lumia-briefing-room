# 영상 파일(다시보기, VOD)

> 스트리머 방송 다시보기(치지직 등)·OBS 녹화 같은 **사용자가 가진 영상 파일**에서 교전 클립을 뽑아 스팀 녹화와 분리된 탭에서 본다. 코드: `pipeline/vod_*.py`, `api/vods.py`, `cli/analyze_vod.py`.
> 화면 이름은 `영상 파일` 탭이지만 코드 식별자·API·설정 키·저장된 탭 id 는 `vod` 그대로다.

## 1. 목적

1. 잘하는 사람의 교전을 모아 본다.
2. 라벨 표본을 늘린다(방송 한 편에 여러 판).
3. 원본이 사용자 파일로 남아 시간 압박이 없다 — 검출을 다시 돌려도 된다.

개인 분석용이다. 다운로드·재배포·저작권 문제는 앱 범위 밖이다.

## 2. 설계 결정

- **앱은 다운로드하지 않는다.** 설정(`vod.sources`)에 지정한 파일·폴더를 읽기만 한다. 분석·컷은 파일 원래 해상도에서.
- 원본은 수정·이동하지 않는다. **삭제는 사용자가 `vod.deleteSourceAfter` 로 고른 경우에만**, 분석이 성공하고 클립이 1개 이상 나온 그 파일 하나만(폴더의 다른 파일은 안 건드림). 기본 방식 Windows 휴지통. 결정은 영상 색인(`deleteSourceOnSuccess`)에 저장돼 이어하기 뒤에도 적용된다. 지워지면 `exists=false` 로 다시 분석 버튼이 막힌다.
- **저장소 완전 분리**: 클립은 `paths.vodClips`(썸네일·색인·캐시 `.thumbs`·`.vods` 가 그 아래). `scan_clips` 가 폴더 `*.json` 을 통째로 읽으므로 섞으면 스팀 목록·자동 정리·평가에 남의 방송이 끼기 때문. `find_clip` 은 두 폴더를 모두 찾는다(클립 라우트 재사용).
- **트리거는 수동**(분석 버튼). `Player.log` 도 벽시계 시각도 없다. `vod.autoAnalyze` 는 선언만 있고 동작하지 않는다.
- 한 번에 한 영상만 분석(`409`). 스팀 감시와 동시 실행 시 스팀이 우선이어야 하지만(링버퍼), 지금은 앱 전체 낮은 우선순위 외 별도 양보 장치는 없다.
- **닉네임 자동 학습 금지**: 결과 화면 닉네임은 스트리머 것이라 `player.nickname` 에 넣지 않고 그 VOD 의 `streamerNickname` 으로만.
- **자동 정리 적용 안 함**(v1) — 원본이 남아 다시 뽑을 수 있다.
- 클립 구간·필터(`clip.*`, `filter.*`)는 스팀과 설정을 공유한다.
- 라벨은 같은 `userLabel`, 평가 도구 기본은 스팀 표본만(`--source`).

## 3. 데이터 모델

```
영상(VOD) ─ 게임(화면으로 나눈 1판) ─ 교전 클립
```

- `vodId` = 파일 크기 + 앞·뒤 1MiB 해시 앞 12자. **내용으로 식별**해 파일을 옮겨도 이어진다.
- 색인 `<vodClips>/.vods/<vodId>.json`: 경로·크기·길이·해상도·fps·상태·게임 목록(시작·끝, 결과)·스트리머·`analysisVersion`.
- 판독 캐시 `<vodClips>/.vods/<vodId>.states.jsonl.gz`(8시간 영상도 수백 KB). 필터·클립 설정을 바꿔도 재디코딩 없이 다시 계산한다.
- 클립 메타데이터는 스팀 스키마에서 세션 필드 대신:

```json
{"source": "vod", "vodId": "3fa91c02b7de", "vodFile": "D:\\vod\\방송.mp4", "streamer": "○○○",
 "vodGameIndex": 3, "vodOffsetSec": 15234.0, "gameStartOffsetSec": 14820.0, "gameEndOffsetSec": 16391.0,
 "combatStartOffsetSec": 15242.0, "combatEndOffsetSec": 15268.5, "gameMode": "battle_royale", "…": "…"}
```

`sessionDir`·`segmentStart`·`matchStartUtc` 는 없다.

## 4. 분석 (`pipeline/vod_analyze.py::analyze_vod`)

1. **프레임 판독 → 캐시**(`VodFileSource`, 키프레임만). 일정 간격 체크포인트라 취소·앱 종료·오류 뒤 이어서 한다.
2. **게임 분할**(`vod_games.split_games`): 인게임 = 일차·낮밤이 읽히거나, 관전 아닌 채 K 가 읽히거나, **`cobalt_phase` 가 읽히는** 프레임. 인게임이 `vod.gameGapSec`(30초) 이내로 이어지면 한 게임, 일차가 2 이상에서 1 로 5프레임 연속 돌아가면 새 게임, `vod.minGameSec`(60초) 미만은 게임 아님. 못 나누면 버리지 않고 확신도만 낮춘다. 관전 화면은 게임 안으로 본다.
3. **게임별 결과 화면**(`vod_result.scan_game_end`): 게임 끝 근처 키프레임만 OCR(전 프레임 OCR 은 너무 비싸다). 결과 화면이 잡히면 그 앞 3초~뒤 12초를, 못 잡으면 게임 끝 직후 30초를 초당 2장으로 전부 디코딩(`VodFileSource(fps=2)`)해 다수결로 정한다([detection.md §8](detection.md)). 스트리머가 결과 화면을 안 보면 비운다.
4. **게임별 검출**(`vod_detect.detect_games`): 게임마다 `finalize_match`.
5. **클립 컷**: `ffmpeg -ss/-to -i <vod> -c copy`, 썸네일, 메타데이터. 새 클립은 스테이징 폴더에 만들고 성공해야 기존을 지운다(0개면 기존 보존).

- **다시 분석** 메뉴: "캐시 재사용(빠름)"(`rebuild` — 클립만 다시) / "처음부터 다시(느림)"(`force`). 옛 `ANALYSIS_VERSION` 캐시는 자동으로 처음부터 판독한다. 라벨은 3초 이상 겹치는 새 클립으로 이관(스팀과 같은 규칙).
- 삭제는 세 단위다. 원본 영상 파일은 어느 경우에도 건드리지 않는다(V7 선택 삭제 제외).
  - **전체 삭제**(`DELETE /api/vods/{vid}/clips`): 클립을 지우고 색인을 `games=[]·clips=[]·status="new"` 로 되돌린다(판독 캐시는 남겨 재분석이 빠름). 클립 0개짜리 게임 행이 남아 "다시 만들 수 없다"던 문제의 해결.
  - **게임 삭제**(`DELETE /api/vods/{vid}/games/{index}`): 클립 0개 게임도 지운다.
  - **목록에서 완전 삭제**(`DELETE /api/vods/{vid}`): 클립·캐시·색인 전부. 원본이 아직 있으면 다음 조회 때 "분석 안 함"으로 다시 나타나고, 원본도 없으면 사라진다.
- 목록은 클립 0개 영상도 숨기지 않는다(자동 숨김 조건이 "못 찾은 영상"까지 숨겨 다시 시도할 길을 막았다). 대신 새로고침 버튼을 둔다.
- 진행률: 디코드 15%(키프레임 디코드는 ~50배속으로 제일 빠름) · 게임 10% · 컷 75%(클립마다 증가). 디코드에 70% 를 주던 옛 비율은 "금방 70% 가고 멈춘다"는 불만을 샀다 — **진행 막대 비중은 실제 소요 시간에 맞춘다.**
- 영상 길이 조회(`ffprobe`, 11GB 파일 1분+)는 백그라운드 스레드. `GET /api/vods` 는 바로 돌려주고 항목마다 `probing`.
- 날짜: `ffprobe format_tags.creation_time` → 없으면 파일 수정 시각 → 사용자가 섹션 머리에서 고친 값(`vod.videoDates`, `PATCH /api/vods/{id}` `date`). 파일 이름에서 날짜를 추정하지 않는다. 한 영상 = 한 날짜(자정을 넘긴 방송은 시작한 날).

## 5. 1080p 방송의 성질 (치지직, 실측 2편 + 코발트 1편)

- mp4, H.264 1920x1080 60fps ~8Mbps, **키프레임 정확히 1초** → 키프레임 샘플링 그대로. 타임스탬프 점프 없음.
- 3시간 18분 방송 = 8판·클립 110개·약 12분.
- HUD 는 기본 UI 스케일(2560x1440 × 0.75 위치)이었다. 채팅·아바타 오버레이는 TK/K/A·일차·초상화를 안 가렸지만 **지역명은 아바타가 가려** 못 읽는다(대기방은 시계로 대신 잡는다).
- 다른 스트리머·다른 방송 종류는 아직 확인하지 않았다. 코발트 VOD 는 방송 위젯이 미니맵 헤더를 덮어 관전 판정이 `None` 이 되는 사례가 있었다.

## 6. 하지 않는 것 (v1)

다운로드·URL 입력·플랫폼 API, 스트리머 자동 식별·"잘하는 사람" 자동 판정, 채팅·오버레이 기반 하이라이트, 여러 영상 동시 분석, VOD 전용 클립·필터 설정.
