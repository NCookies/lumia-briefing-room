`docs/todo.md` 를 읽고 미처리 항목(`- [ ]`)을 문서에 반영해라.

## 범위

- **문서만 수정한다. 코드(`api/`, `cli/`, `frontend/` 등)는 절대 건드리지 않는다.** 항목이 코드 변경을 요구하더라도 구현하지 말고, 무엇을 구현해야 하는지를 문서에 적기만 한다.
- 수정 대상은 `docs/plan.md`(남은 작업), 진행 중 작업 문서 `docs/plan-<주제>.md`, 그리고 이미 구현된 동작을 바로잡는 경우에만 `docs/SPEC.md`·`docs/spec/*.md`·`README.md`·`docs/DEVELOPMENT.md`.
- **spec 에는 계획을 쓰지 않는다**(CLAUDE.md). 아직 안 만든 것은 전부 plan 으로 간다.

## 반영 방식

- **당장 구현** 항목: `docs/plan.md` 의 해당 영역 절(또는 진행 중 작업 문서)에 할 일로 추가하고, 우선순위가 바뀌면 `plan.md §1` 표도 고친다.
- **추후 구현** 항목: `docs/plan.md` 의 "보류" 또는 "확인 필요" 절에 적는다.
- 어느 문서에 들어가야 할지 불분명하거나 기존 문서 내용과 충돌하면 임의로 판단하지 말고 사용자에게 물어본다.
- 기존 문서의 어조와 형식(한국어, 표/절 구조)을 따른다. 불필요한 주석·장황한 설명은 넣지 않는다.

## 마무리

- 반영을 끝낸 항목은 `docs/todo.md` 의 "처리됨"으로 옮기고 `- [x] 내용 → 반영한 문서 §절` 형태로 적는다.
- 문서 갱신은 항목(또는 관련 문서) 단위로 잦게 커밋한다. 메시지는 한국어로 무엇을 왜 반영했는지 적는다.
- 끝에 반영 결과 요약(항목 → 문서/절)과, 사용자에게 되물은 것/보류한 것을 알려준다.
